## 中文版

这是 SeiunEngine v0.2.2，联机预发布阶段（Pre-Online.1 → Pre-Online.3）的成果第一次进入正式版。联机不再是要单独开宏才编进去的实验分支，而是默认随游戏发布的正式功能；谱面读取、图形内存、打歌开销、存档写盘与崩溃排查也都在这三个月里重做了一遍。下面按「玩家拿到手能感觉到什么」整理成为最终形态，预发布期里被后续提交推翻的做法不再单独记录。先给一段不列数字的概述，再按章节展开。

### 概述

这一版刻意不逐项引用预发布期的实测数字——那些数字是在特定机器、特定谱面上量出来的，写进公告就变成了承诺。这里只按方向说：

- **读谱**：从「整份 JSON DOM 常驻内存」变成按小节流式处理，排序、扫描与折叠换成了更合适的数据结构；重复音符密集的谱面还能打包成体积小几个数量级的 `.chartpack`。
- **图形**：图集裁边、去重与调色板把显存明显压下来，GL 提交次数大约减半，画面逐像素不变。
- **打歌**：HUD 文本与弹窗的重绘开销大幅下降，「帧数随歌曲进行持续下滑」不再出现。
- **稳定性**：崩溃报告能直接看懂，存档写盘有快照与回滚，联机第一次进入正式版。

每一条的取舍与理由见下面各章。

### 联机

> **来源署名 / Credit**：联机部分的菜单 UI、房间与协议模型、服务端房间语义**移植 / 参照**自 **Funkin-Psych-Online** 及其配套的 **Funkin-Online-Server**（作者 **Snirozu**，Apache License 2.0）。本引擎内的联机实现是自研 Haxe 代码，**不包含**上述仓库的 TypeScript / Node 源码。完整署名见仓库根目录的 `NOTICE`，游戏内「鸣谢名单」的 *Online UI / Protocol Reference* 一节也已列出。

#### 怎么玩：三条开局路径

- **公共服务器**：在服务器列表里填地址即可。会落到明文 `ws://` 的形态（裸 IP、裸主机名、`http://x`、`ws://x` 等）会自动补上默认端口 2567，且只补一次；`wss://` / `https://` 保持 443 语义，走反向代理的公网服务器不受影响。探测结果分 **可达 / 超时 / 协议不符** 三类，最后一类表示那个地址不是本引擎的服务端或版本不一致，不再笼统显示「连不上」。
- **局域网搜索**：不知道房主 IP 就直接搜——服务器列表里的 **搜索本网络中的服务器** 会监听 UDP 2569 广播 4 秒，把听到的服务器列成 **Found on This Network** 清单（不会自动加入）。勾选想要的条目再点 **Add Selected Servers** 才写进服务器列表，已在列表里的会标注出来且不可勾选，**Clear These Results** 直接丢弃本次结果。广播分别发往每块网卡的 `x.y.z.255`，装了 VPN / WSL / Hyper-V 虚拟网卡也不会走错接口。
- **游戏内开服**：联机菜单里的 `LAN HOST` 把服务端跑在自己的游戏进程里，房间码带上主机的局域网 IP，朋友把这一行粘进 JOIN 就能进来（详见下文「局域网：在游戏里开服」）。

#### 房间、暂停与开始闸门

- **双方各自一套评分弹窗**：联机时你和对方各有一套评分图标与连击数字，互不覆盖、互不干扰；远端弹窗锚定在**该玩家自己的角色**一侧（并夹在 5%~95% 屏宽内），找不到绑定的角色时落到对方所在的那一半屏，同侧玩家（coop / 2v2）之间会再横向拉开。本地弹窗的位置与单机一致。
- **连击数字仍是引擎原有口径**：连击小于 10 不显示数字，10~99 显示三位（例如 `010`）。
- **房间设置新增「暂停策略」**（房主循环切换，三档）：
  1. **仅房主可暂停**：房主一按暂停，其他玩家被强制一起暂停；客人按 ESC 只会收到本地提示。
  2. **任一玩家暂停则全体暂停**（**默认**）：谁按 ESC 都会让所有人一起停、一起恢复。
  3. **保留原有逻辑**：暂停只影响自己，暂停消息双向都不上线，与旧版本行为完全一致。
- **服务端是唯一仲裁**：暂停会回显给房间里所有人（含发起者）并带上发起者标识——收到自己的标识表示自己持有暂停，收到别人的表示自己只是被强制暂停、**无权单独恢复**；两人同一时刻按 ESC 时先到服务端的一方持有暂停，另一方从回显里得知并交出所有权。恢复只对暂停持有者生效（仅房主档里房主也可以），被拒绝的一方会收到一条提示。持有者离开 / 掉线 / 被踢、结束歌曲、新一轮重置时，服务端都会自动广播恢复；迟到进房的玩家也不会继承一个旧暂停。
- **开始闸门**：房主点播放（或按 ACCEPT）后全员进入谱面，屏幕正中提示 **按 ACCEPT 开始**——ACCEPT / 手柄 A / 直接点那行提示文字都算「我准备好了」，提示随即变成 **等待其他玩家...**，等房主那句 start 到达才进倒计时。安卓 / 开了触屏支持的桌面端会同时出现一个 **A** 虚拟键（右下角），房主开始后自动收起。
- **房间级暂停走消息通知**：其他人会比暂停者晚**一个单程延迟**才停下，恢复时各自从自己的冻结位置继续，两边保留这点偏移（局域网通常是个位数毫秒，与进歌时各自的音频启动偏差同一量级）。

#### 局域网：在游戏里开服

- **`LAN HOST` 面板**：开 / 停、端口（默认 2567，被占用时向上顺延并真实显示占用情况）、最大人数（1-64）、*允许本机玩家加入*、*公开房间*（关闭时只能凭房间码进入）、实时状态行（局域网地址、房间码点击复制、当前人数）、防火墙提示、*打开本机网页控制台*。
- **真·内嵌服务端**：游戏二进制里就是同一套服务端代码。开服时在游戏进程内绑定 2567（HTTP）+ 2568（WebSocket），房主客户端自动建房并通过本机地址加入。停止会关闭两个监听口并释放端口，同一局游戏里可以反复「开 → 停 → 开」。
- **开服期间游戏房与社交 / 网络房都走本机服务端**：只在运行期改地址，玩家保存的服务器列表与账号选择完全不受影响。
- **免账号**：客人用房间码加入即可，不需要 token；账号、分数与排行榜只写在游戏自己的存档目录里，不会上传。
- **Android** 上同样提供该面板并会尝试开服（尽力而为），无法探测到局域网地址时会给出手动填写提示。
- **内嵌网页控制台：本机免登录、只读**。内嵌开服没有管理员账号，因此只有来自本机（`127.0.0.0/8`、`::1`、`::ffff:127.0.0.1`）的 GET 免登录，服务端返回一个合成的只读账号，页面据此跳过登录墙并显示「本机只读」横幅；写操作（POST / PUT / DELETE）与局域网里其它机器的请求仍走原来的四步校验（401）。独立服务端默认关闭该模式，需要时用 `--console-local-readonly` 打开。
- 内嵌开服会写自己的 `config.toml`（不带 `[smtp]` 段），邮件黑名单在内嵌模式下不生效——未配置邮件时无影响。

#### 账号与服务端

- **存储层换成 SQLite**：WAL 模式、单连接 + 唯一的数据库互斥锁、按 `user_version` 版本化的只增式建表，共 13 张表（账号、会话、成绩、评论、举报、俱乐部、Mod、警告、管理日志、首页消息、每日玩家、公共状态等）。标量字段走类型化列（可索引、可排序），列表型字段（权限 / 好友 / 成员 / 下载项等）仍以 JSON 文本列保存。
- **旧数据一次性导入**：首次启动且库为空时，自动导入旧的 accounts / leaderboard / clubs / mods / admin / public 这些 JSON，随后把原文件改名为 `*.imported-<时间戳>`（**绝不删除**），并在库里记录导入标记与计数；也可以用 `--import-legacy-json` 显式重跑。
- **凭据与会话**：token **只存 HMAC-SHA256 哈希**（外加 8 字符查找前缀），比较走常量时间，支持过期与撤销；登录时明文 token 只返回一次，从库里读出来的账号对象不再携带 token；邮件验证码同样只存哈希。
- **随机数**：优先 `/dev/urandom`；没有该设备的平台（例如 Windows）走 HMAC-SHA256 DRBG。README 与启动日志都如实写明：**这不是硬件 CSPRNG**，是自建单进程局域网服务的工程折中。
- **可观测性**：结构化 JSON Lines 日志（按天切分），只读 `GET /api/health`（状态 / 运行时长 / 房间数 / 版本 / 库版本 / 各表行数），`--log-dir` / `--log-level` 参数。
- **独立服务端可执行文件**：可以编出原生的 `SeiunServer.exe`（零运行时依赖）；neko 目标与既有用法完全不变。
- **接口行为不变**：账号 / 排行榜 / 俱乐部 / Mod 仓库 / 管理控制台在换成 SQLite 实现后，对外签名、错误字符串、排序、分页与 id 格式逐字保持。
- **双端口**：HTTP 2567 + WebSocket 2568，握手带协议标识与版本校验。
- **管理控制台网页**编译进服务端程序本身，没有 `server/web/` 目录也能打开；部署目录里存在该目录时仍以磁盘为准，所以改页面依然是刷新即生效、不用重编译。
- **配置写入修好**：公告原先按 UTF-8 **字节**截断，长中文 / emoji 会被切在字符中间，写坏 `config.toml` 并让控制台接口一直报 500。现在按 **字符** 计数（500 字符，另加 2048 字节上限），磁盘上已损坏的值在加载配置时自动修复，写入失败会返回错误而不是假的 200。同一类问题在全接口做了排查：简介、俱乐部名、network 聊天、房间聊天、`sez`、Mod 标题、搜索、封禁 / 警告理由等 12 处用户可见的字数上限现在都按字符计数，上限数值、错误文案与成功响应的结构都不变。
- **公告**：持久化的公告随 `GET /api/front` 一并返回，后登录的玩家也能看到；客户端在联机菜单左上角以固定区域渲染（最多 100 字符，没有公告就不画），实时推送改为带标题的提示（`NOTIFICATION` + 内容）；折行按字符计算，中日韩文本不再按大约三分之一的宽度被折行。

### 谱面：一次读谱改造

这一版把「读一张谱面」这件事整体换掉了：解析、排序、扫描、折叠、缓存、容器六件事是一次性重做的，所以这里按最终形态讲，而不是按我们分几次做完。

- **不再整份解析**：大于 64 MB 的谱面走字节流式加载——只把当前小节解析出来、用完立刻丢弃，整份 DOM 不常驻内存。**≤64 MB 的谱面行为完全不变。**
- **字节级解析**：逐条按字节产出数据，不再为每一节建一次 JSON DOM——那一节的 `sectionNotes` 不再被整段建进对象树，也不再复制成字符串，峰值内存因此大幅下降。没有 `events` 字段的老谱面同样能流式加载（改用字节级特征判断），不再退回整份 DOM 解析——那次回退正是这类谱面在选歌界面卡死的原因。
- **排序换计数分桶**：上千万条 Note 改走计数分桶排序——一趟线性计数直接落位，不再逐条比较。进歌前最重的几段之一是排序，换成计数之后它不再是瓶颈。
- **扫描换缓冲区内紧循环**：定位小节边界的扫描不再逐字符过字符串，而是缓冲区里的紧循环，进歌前那一段固定开销随之明显缩短。
- **列式存储**：每个数值字段单独成列，全谱恒定的字段（`stepCrochet`、命中 / 失误扣血、偏移与各种字符串列通常整个文件只有一个值）直接提升为标量、根本不建列，因此单个 Note 的内存占用降到几十字节量级（原来要数百字节）；列按倍增扩容并可在解析时直接写入，不再把 hxcpp 的块池按整张谱面的规模撑满。
- **计数换 Int64**：谱面与命中计数改用 64 位，二十亿级 Note 的谱面（`amphotercity` 那张就有 20.6 亿条）不再溢出。分数、连击、各判定桶、Miss 数、总可玩数一并换掉，存档与回放按十进制字符串写、读取兼容旧档的 Int / Float / String。
- **低流速折叠按屏幕像素间距**：引擎只有一条渲染路径——真实 Note 精灵，所以「性能不够」永远等价于「同时存活的精灵太多了」。低流速下这个问题最严重：屏幕像素带固定，换算成的可视频段是 `1400 / (0.45 × 流速)` 毫秒，流速 1.0 时约 3.1 秒、0.5 时约 6.2 秒。现在按**屏幕像素间距**（而不是时间间距）折叠：同轨道、同侧、同 `multSpeed`、间距不足 4 像素的 tap 合并成一条代表 Note，折叠数量记入 `noteDensity`，判定与计分口径与原来完全一致；判据与流速自洽，流速越低合并越多，物化量因此恒定。效果是同屏存活的 Note 数不再随谱面密度与低流速一起爆炸——低流速下反而回到接近高流速的量级，而打出来的判定与分数与原来一致。
- **物化地平线对齐真实像素带**：生成窗口不再固定按 2000 ms 铺开，而是按屏幕几何推导（上限仍是原版 `spawnTime`），初值降到 250 ms，避免倒计时前一次性物化成千上万条 Note。
- **运行时像素级归属闸门**：与加载期折叠同一判据，但用**当前**流速计算；即使运行中 `songSpeed` 被事件或缓动改写，物化量依然有界。被挡下的音符就地走数据层结算，不会卡住结算游标，也不会把 combo 拆成好几段（`fastSkipPastNotes` 与新物化路径共用同一个结算函数与帧内累加器）。
- **谱面缓存：第二次加载不再重算**。缓存落在可执行文件旁的 `chart_cache/`，每张谱面两个文件（`.skel` / `.notes`）；缓存的是 Note 循环的**输出**（完整数据对象，而不是可变数组的下标），所以命中缓存也不可能指到错的那一条 Note。失效判据是「每个分段文件的**大小 + 修改时间** + 调用方配置串（流速、mania、折叠阈值、Turbo 开关…）都不变」，任何一项变了就重写。命中时骨架扫描、逐小节解析、折叠与排序全部跳过，直接回放 Note 列表。记录按列压缩，同一张列表从 GB 级压到几 MB；读写时内存里最多只持有 1 MB 块。
- **缓存设置**（性能页 → Note 优化）：`超大谱面缓存`（默认开）、`压缩谱面缓存`（默认开，代价是每次读写多花一点时间）、`清除谱面缓存` 按钮（会报告释放了多少 MB）。原地改过谱面后建议清一次。
- **选歌不再为「预览」解析整张谱面**：流式尺寸的谱面会先被识别出来并直接跳过预览解析（预览只需要歌名与 `needsVoices`）。
- **分段谱面识别放宽到任意起始编号**：目录里所有 `<song>-<n>.json` 按编号升序合并，起始编号任意（从 0、1、5 或 100 开始都一样）；中间缺文件只记录、不再作废（会输出缺了哪些编号）；编号文件少于 2 个仍按单文件处理。同目录存在 `<song>.json` 时不做分段（那要留给「普通歌 + 数字难度」），`.parts.json` 清单仍是显式覆盖手段。
- **新增 `.chartpack` 谱面容器（SEIUNPK1）**：谱面存成「骨架 + 组流」——骨架除每个 `sectionNotes` 数组的内容外逐字节保留（节对象、未知字段、events、格式都不动），数组位置留一个 NUL；组流按 section 内不同的 `(time, lane, sustain, type)` 各写一条记录加重复次数（varint + zlib）。读 pack 时把一组展开成带 `repeat` 的原始 note，直接喂给折叠器，不再为每个重复音符分配对象；时间落在 BPM 网格上走 tick，否则退回 float64，判定容差 `1e-6 ms`。重复越密集收益越大：几十 GiB 的谱面目录能压到几十 KB，几十 GiB 的巨型单曲能压到 MB 级，加载从「读几十 GB」变成「读几 MB」。打包工具带界面（`chartpack-ui.exe`，中英双语、拖拽、实时压缩比），也有命令行版本；引擎只读 pack，不会自动把 JSON 转 pack。
- **巨型谱面加载走多线程**（Turbo 或 note 数 > 12,000,000 时启用）：第一阶段按 part 并行扫描，产出合并骨架、每 section 的 `sectionNotes` 字节区间与精确 note 数；第二阶段按区间读取，worker 解码归一化、单消费线程按谱面顺序折叠，直接产出打包列，worker 上不创建 Haxe 对象。任何异常返回失败并**自动回退 Haxe 路径**，只影响速度。
- **单个谱面文件超过 2 GB 也能正确读取**：改用 64 位 `seek` / `tell`（`_hx_std_file_seek64`），以前会读错位置、表现为音符错乱；`sectionNotes` 里的垃圾字节不再抛错，改为跳到下一个数组并记录跳过量。
- **联机只承诺单文件谱面**：分段谱面在联机下**明确拒绝并提示**（本地弹窗 + 房间内状态），不再因为哈希阶段抛异常而静默卡在「等待对手谱面」。联机下的键数取自每条 Note 自己的 mania 快照，含 Change Mania 事件的谱面评计算更准。

### 渲染与画面

- **图形页新增「渲染器」一行**：可以在 OpenGL 和 Vulkan 之间切换。选择需要确认，确认后写入存档，下次启动生效。
- **启动失败会自动回退**：驱动、窗口或管线出错时，本局回到 OpenGL，存档里的选择也改回 OpenGL，并弹窗说明原因。启动阶段直接崩溃的情况会在下次启动时被识别，留在 OpenGL，不会形成崩溃循环。
- **命令行参数仍然可用**：`--vulkan` / `--no-vulkan` / `SEIUN_VULKAN` 的优先级高于存档选择；`--vulkan-stats` 打印帧时与批处理统计；`logs/renderer.txt` 记录每次启动的决定。构建时加 `-DSEIUN_NO_VULKAN` 可以不编入后端。
- **仍然是实验性功能**：菜单只在 Windows 提供。Android 编入了后端但暂不开放——模组与 OpenFL 着色器还需要在运行时从 GLSL 翻译到 SPIR-V，这条链还没做；Linux / macOS / iOS 不提供。glow、投影、位移贴图、triangle 路径和离屏渲染纹理还没有实现，用到这些效果的画面会缺东西。
- **图形内存后端重写**：删除 `GfxPolicy` / `GfxLru` / `GfxRepack`（持有强引用、销毁仍被引用的图、强制 GC、运行时重打包，并走出设备相关的 C++ 崩溃路径）。新的 `GfxMemory` 只在上传 GPU 后释放大图（≥512×512）的 CPU 像素副本，读像素时由 OpenFL 自动重解码；不销毁图片、不驱逐缓存、不碰 GC。旧的「强制回收、销毁仍在使用的图片」的做法已删除。
- **图集裁边**：把整张图裁到所有帧实际用到的区域，并按同样距离平移帧坐标，`offset` / `sourceSize` / 帧名 / 顺序不变；换图前后逐帧校验，任一不符整体回滚；省不到 0.5% 就放弃。
- **图集逐帧裁边 + 去重 + 紧排**：每帧裁到自身不透明边界、相同的图块只留一份、紧密重排进新画布并改写帧坐标，`offset` 按 trim 补偿，精灵位置与大小不变；失败整体回滚，省不到 5% 跳过，旋转 / 翻转帧整张回滚。
- **调色板纹理**：一张图不同颜色 ≤ 256 种时改成「8 位索引 + 256 色调色板」，条目就是源位图的 premultiplied BGRA 原始字节，索引采样强制 `NEAREST`，批次数不变；超过 256 色、无 CPU 像素、已上传过纹理、无 8 位索引格式、shader 编译失败、采样校验不一致——逐图退回 RGBA。
- **省的是显存**：图集裁边、去重与调色板叠加之后，启动时的解码内存与 GPU 占用都明显下降——调色板对大图的收益最大，单张图能省掉大半；图集重排的收益小一些，代价是加载慢了一点。工作集基本不变，画面逐像素不变。
- **GL 提交开销**：openfl 侧缓存 viewport / 纹理绑定 / 属性数组位掩码，删掉冗余 `glEnable`，同一画面的 GL 调用次数大致减半；动态顶点缓冲改原地 `bufferSubData`（装不下才退回 `bufferData`）。
- **图形选项精简**：删「纹理复用缓存（LRU）」与「运行时纹理重打包」；「大纹理内存释放」改名「纹理内存释放」、阈值 2048px → 512px；「清除图片缓存」说明补上「仍在使用的图不会被动」。
- **批处理与画面**：同一批图形只在真的需要不同颜色或透明度时才逐个顶点展开；相机滤镜和舞台覆盖层都接上了；鼠标指针改用系统光标。顺带修掉竖屏设备上横屏画面被再转 90 度、非 16:9 屏幕右侧被裁的问题。
- **窗口模式统一**：新的 `backend.WindowMode` 用一条代码路径处理窗口化 / 全屏（真正的 SDL 显示模式切换）/ 无边框（去装饰 + 铺满 + 置顶），启动流程与选项页共用。
- **平板 / 高 DPI**：画布偏移按真实的舞台单位与设备像素映射计算（新增 `backend/RenderScale.hx`），Retina 切换时即时重排。
- **异步图片加载移除**：`AsyncGfxLoader` 与其设置项删除，位图解码回到主线程按帧小批量处理。追查 GC 线程崩溃时最终指到跨线程位图发布路径是堆损坏来源之一，那点异步收益不值得这个风险。

### 打歌

- **带描边文字的重绘路径简化**：`FlxText.regenGraphic()` 的描边从「每个偏移把 TextField 整画一遍」（1 + 8 × `int(borderSize × borderQuality)`，HUD 是 17 遍）改为「描边色栅格化一次 + 位图 blit 盖章」，17 遍变 2 遍且逐像素相同；新增增量重绘，只重画新旧字符串差异对应的设备像素箱；新增输入签名比对，输入未变的重建直接跳过；签名稳定 750 ms 的静态文本合页到共享大图，菜单里稳定的静态文本因此只占一次绘制，整页批次数随之下降。
- **效果**：重绘开销明显下降、画面逐像素不变——这一条改的是「怎么画」，不是「画多少」。
- **HUD 文本行为回到 0.6.3 原版**：命中表现按帧排队、各类文本节流、1x 栅格化全部撤销（脚本会读 `scoreTxt`，`onUpdateScore` 要求命中当帧就是新值；1x 会让高倍率窗口文字变软）。省下来的性能全部来自库侧补丁，不是「少画」。高分辨率窗口与高 DPI 设备上 HUD 文字保持全分辨率。
- **视觉页新增两个开关**：命中毫秒读数（`showHitMs`）和左下角的歌曲 / 版本行（`showVersionText`），默认开启，也受 Hide HUD 控制。旧的 `Stock HUD Text Rewrite` 开关已删除。
- **静止箭头不再单独占一次绘制**：8 个空闲 strum 不再各带一个恒等 `ColorSwap`（flixel 按着色器实例分批，八个箭头就是八次 draw，也无法与从不挂着色器的下落音符合批），改为轨道色非中性时才挂、回中性即摘，因此可与下落音符合批。
- **溅射合批**：中性 `ColorSwap` 不再挂 shader，同屏多个溅射可合批。
- **连击 / 评分弹窗修复与提速**：修复开启「连击堆叠」后新生成的连击图标会被旧图标压住的问题；修掉弹窗对象池从不释放容器槽位、导致每帧绘制循环越走越长的问题（这正是高密度谱面下「帧数随歌曲进行持续下降」的根因）。连击数不再被截断；rating / 数字 / COMBO 贴图改为缓存复用、弹窗取用改为 O(1)，图片键只建一次、连击数字写进复用缓冲、淡出不再依赖 FlxTween 全局管理器，稳态零分配。
- **各项预算按时间计**：弹窗 / 溅射 / 物化 / 排空这几个预算原先按 60 fps 设计速率、每渲染帧重置，所以每秒速率会随帧率上限放大（360 fps 下是设计值的 6 倍）；现在按「经过时间 × 60」累积、按整单位消费并逐帧封顶，60 fps 及以下逐位不变。
- **`purgeUnusedGraphics()` 重做**：不再为每个待清理的键重扫一遍缓存，死候选一次收集、分批删除，长会话里周期性的多秒主线程冻结消失；被清理图形注册的 Sparrow 图集帧缓存随之一并驱逐，不再留下「僵尸图集」（动态生成精灵的模组以前会渲染不出东西并掉进 Lua 报错循环）。
- **Turbo / Botplay HUD**：Turbo 下标签读作 `TURBO BOTPLAY`（普通自动打谱仍是 `BOTPLAY`，练习模式仍是 `Practice Mode`）；自动打谱时分数行读作 `Notes: <对手命中> + <自己命中> = <总数> | NPS: … | HP: <血量>%`，NPS 用 1 秒滑动窗口且**快升慢降**（一帧内的爆发在一秒多的时间里平滑衰减到 0，而不是下一帧直接归零），过长数字切紧凑写法（如 `1.03B`）以保持单行，精确值仍在左侧统计栏。
- **侧边 HUD 固定字段宽度**：Botplay / Turbo 下计数器每帧都在变，值变化跳过永远不生效，而比例字体每次 autoSize 都要重新排版并把新位图 + GPU 纹理塞进位图缓存；侧边计数改用固定字段宽度（单行、一张位图永久复用）。
- **模组皮肤的长条几何**：修掉模组自带 `arrowSkin` 图集（trimmed Sparrow 帧）下长条断裂、尾帽错位、「BPM 越高偏移越大」的问题：长条高度归一化改用图集的可见区域高度（新增 `Note.sustainContentHeight()` 把四套公式统一成一个随皮肤自适应的系数），下落模式的长条锚点补偿符号修正，裁剪上边缘改用新的 `Note.contentTopInFrame()`。默认与内置皮肤逐位不变。
- **Note 材质统一入口**：修复池化复用跳过 `reloadNote` 时「一部分 Note 不上色」；Hurt Note 的白底图集改走 RGB 色板染色（`0xFF101010` / `0xFFFF0000` / `0xFF990022`），不再无条件找不存在的 `HURTNOTE_assets` 把帧清空，Hurt 溅射也不再沿用轨道色。池化复用时的材质比对从「为每条 Note 拼一个字符串」改为逐字段比较，reload 路径不再产生字符串垃圾。
- **结算界面**：评级图标不再回落 `FALSE`（统计总数漏了 perfect-plus 桶，Turbo + 自动打谱下每次都记成 perfect-plus、其它桶为 0，总数得 0 直接落到 `FALSE`）；图标统一按 240×90 框适配（150×150 仍渲染 90×90，视觉不变）；统计图例不再换行、也不再画出黑色色块；残余 HUD（侧边统计、BOTPLAY / REPLAY / ms / 判定文字）随结算界面一起隐藏。
- **评级顺序修正**：开了 Marvelous 的玩家不再按错误的档位复算联机分数。

### 存档与备份

旧存档直接走 OpenFL 的 `SharedObject.flush()`，写入前先截断文件，中途失败就会留下坏档，下次启动静默变成空存档。这一版补上了写档这一侧的保护，并把设置里的备份 / 恢复整套重写。

- **写档前先留快照**：每次 flush 前把内容写进 `flxsave_backups/`，轮转保留若干份（份数与上限可配，可以关闭）。快照先写临时文件再改名，不会留下写了一半的版本。
- **坏档自动恢复**：`bind()` 读不出存档时，把文件另存为 `*.corrupt`，再用最新的有效快照顶上，并把 `recovered` 置 true。
- **写完回读校验**（`verifyWrites`，可以关闭）。序列化失败、空对象覆盖已有存档、超过大小上限的写入会在截断文件之前被拒绝；快照写不出来时默认也不覆盖（`abortWhenBackupFails`）。
- `MinFileSize` 现在真的传给 `flush()`，flush 失败会给出原因（`status` / `lastError`）。只调 `bind()` / `flush()` 的代码不用改。
- **新的容器与载荷**（`BackupFormat` / `BackupData`）：`SEB2` 容器带版本与校验和，文件损坏会给出具体原因；存档字段用 `haxe.Serializer` 原样保存，Map、Int64 和模组字段不再丢失；成绩文件按字节保存，路径经过校验。
- **全有或全无**：恢复前先全部解码校验，当前数据先存一份安全备份，写入失败会回滚；恢复完成后重新加载设置、键位、成绩、成就和语言。
- **旧的 `SEB1` 备份仍可读取**，读取时升级并合并进当前存档。
- **导出改为流式写盘**，不再把整份备份在内存里复制多遍；导入按块解码，并用文件实际大小挡掉头部声明的异常长度。
- **备份界面重做**：备份 / 恢复两张卡片，支持键盘、鼠标和触屏；确认框先显示文件日期、引擎版本、字段与成绩数量；失败时说明原因。

### 崩溃排查与诊断

- **四条崩溃路径统一成一份报告**：原生崩溃、脚本异常、底层库初始化失败、网页版；报告首行带 `Kind:`，不靠文件名猜来源。
- 报告里有系统、显卡与驱动、系统错误码、加载的模块和这次构建的身份信息（主模块尺寸与 PE `TimeDateStamp`、`Linemap` 是否存在）；报告 UTF-8 + BOM，Windows 对话框用 UTF-16。
- **堆栈自带源码位置**（形如 `[src/File.cpp:123]`），不再是一串 `<sprintf>+0x...` 的假地址；报告头还会写明它是哪一次构建、符号是否可信（`SymType=0` 时内联帧名一律不可信）。
- 报告只写事实，不再自动生成「猜测的原因」；保留 150 行游戏日志（原约 30 行），原生缓冲扩到 32 KB，报告上下文带当次生效的图形设置。
- **每次构建自动生成符号文件**，工具能判断符号是否属于这个版本；发布包只发一个按平台分目录的符号压缩包，附 `manifest.json`，**不会混进玩家下载的游戏包**。符号包带上 ELF / Mach-O 符号表，`crash.py sym` 可以把偏移解析成函数名（代价是 macOS 发布件不再 strip）。
- **九个旧工具合并成一个 `crash.py`**（子命令覆盖 status / report / bundle / ui / symbols / prune / triage / resolve / verify-map / symbolize / linemap），中英双语。拆开本身就是 bug 来源：报告可能对着另一个构建的 map 解析，每一帧都「解析成功」却全错。
- **构建工具链记录下来**：每次构建写入 `toolchain.json` / `toolchain.txt` / `toolchain-key.txt` 并进入 `build.json`；工具链标识参与 hxcpp 对象缓存 key。Windows 构建钉在固定镜像上，另有每周一次的 canary 检查镜像变动。
- **F8 诊断**：卡顿时按一次 F8，会把最近 600 帧的分段耗时（整帧 / 批量结算 / Note 更新 / 排序 / 弹窗 / 分数文字）写到 `crash/hitprobe.txt`。只读诊断，不影响判定与上报。
- **安全模式默认开启**：Haxe 层报错自带源文件与行号（行号表生成 / 刷新链路修正，提供 `tools/refresh_linemap.ps1`）；CI 与发布构建同样保持安全模式。
- 顺带修掉几个确证的崩溃源：SDL3 迁移后 `SDL_GetBasePath()` 被错误释放（退出时 double free）；窗口关闭后渲染循环仍在调用 native 接口造成的空指针解引用；strum 组重建期间越界取成员；组容器解引用已被回收的成员。
- 顺带澄清：多线程渲染早已移除（`RenderThread` 是空壳），渲染一直在单线程主循环里——它**不是**崩溃的原因。

### 脚本（Lua / HScript）

- **完整对齐 1.0.4 API**：1.0.4 放宽的 62 个签名这里同样放宽（`doTween*` / `noteTween*` 的 `ease`、`mouseClicked/Pressed/Released` 的 `button`、`getMouseX/Y`、`makeLuaText`、`startVideo` 的四个新参数、`precacheImage` 的 `allowGPU`、`setProperty` 系列的 `allowInstances`、`getPropertyFromGroup` / `setPropertyFromGroup` 的 `allowMaps` 等）；回调参数对齐（`eventEarlyTrigger` 拿到 `(event, value1, value2, strumTime)`，`onTweenCompleted(tag, vars)`）；补上 1.0.4 的 `getFileTranslation` / `getTranslationPhrase`，背后是 1.0.4 纯文本 `data/<language>.lang` 的读取器（与本引擎的 JSON 语言表合并，含 `{1}` / `{2}` 替换）；移植 `Paths.getAtlas` / `Paths.getAsepriteAtlas`，`'auto'` 真正能自动识别图集格式；HScript 补上 `getModSetting` 与可选参数的 `keyJustPressed` / `keyPressed` / `keyReleased`。类型放宽（`addAnimation` 接受数组或 `'0,1,2'` 字符串、动画帧率用 `Float`、`setGraphicSize` 收 `Float`），`removeFromGroup` 两种方言都答，版本相关默认值（`setHealth`、`setObjectCamera`、`loadFrames` 等）统一走 `CompatEngine`——0.6.3 / 0.7.3 模式逐位不变。
- **模组 JSON 按 1.0.4 的方式解析**：1.0.4 用 tjson 读模组数据（容忍尾逗号与 `//` / `/* */` 注释），本引擎在同样的位置用严格解析，所以 `pack.json` 结尾多一个逗号就会让整个模组失效。`pack.json`、`stages/*.json`、`data/settings.json`、`images/gfDanceTitle.json` 改为「先 tjson、失败再严格」；歌曲 / 角色 / 对话解析仍保持严格，与 1.0.4 一致。
- **`close()` 不再关错脚本**：linc_luajit 的回调表是静态共享的，最后创建的实例会赢，于是 `close()` 可能作用在别的脚本上（可见症状是模组的自定义菜单永远不出现）。现在回调派发时记录正在执行的实例，`close()` 作用于它，日志记 `CLOSE() <script>`。
- **`callMethodFromObject` 不再用没解析出来的参数去调用**：`instanceArg(...)` 先在模组图表精灵 / 文本里解析，再退回变量表，解析不出来就跳过这次调用并记日志——修掉模组把 null 传进 `mouse.overlaps` 造成的 `0xC0000005` 原生崩溃。
- **`getDataFromSave` 会返回调用方的默认值**：0.7.3 / 1.0.4 语义下存檔里没有的字段返回调用方给的默认值（0.6.3 保留原始查表）；`logs/script_log.txt` 记录 `[save]` 诊断。
- **脚本更难弄死进程**：`makeLuaSprite` 一类在 tag 缺失时安全跳过；`safeColor()` 取代手写十六进制转换（垃圾颜色得到不透明白而不是原生崩溃；严格校验只在 1.0.4 模式生效）；引擎自绘光标在进游戏前强制关闭、由暂停菜单在退出时恢复；引擎附加的 HUD 组件（按键 / KPS 面板与侧边统计）随 `scoreTxt.visible` 一起隐藏。
- **1.0.4 判定名映射**：新增「1.0.4 Judgement Names for Mods」选项（默认开，仅 1.0.4 兼容模式）：脚本读判定名时把引擎私有的 `marvelous` 改写成 `sick`（同一击在 1.0.4 里的叫法），按名字判定对错 / 连击的模组不再算错；引擎自己的判定、计分、结算、联机与回放仍用真实评级，想要 perfect-plus 档的脚本可以读 `notes.members[i].ratingRaw`。
- **脚本报错不再废掉整个脚本，且默认不静默**：错误上限默认 0——有多少报多少；设了正数时重复错误只触发静默（一条汇总行，之后限速），脚本其它回调继续跑；一次性回调里的错误只打印。旧行为是「每帧回调错 50 次就关掉整个脚本」，连 `onEndSong` 都收不到。
- **`logs/script_log.txt`**（每次启动重建，上限 20,000 行）：记录每个加载的 Lua 脚本及其路径、每个扫过的脚本目录（不存在标 `MISSING`）、每个脚本错误（脚本 + 回调 + 原始错误文本）、以及哪些脚本收到了生命周期回调；`[scan]` 行写明 `currentMod` 与 `globalMods`——这正是决定模组 `data/<song>/` 会不会被搜到的两个值。
- **HScript 引擎 1.4 与 1.5**：1.4 带来正则字面量、对象展开、结构化匹配、`enum abstract`、带脚本调用栈与「你可能拼错了」提示的错误；1.5 见「底层库」。
- **新增脚本能力**：`addWiggleEffect` / `removeWiggleEffect`（H-Slice 签名：speed / frequency / amplitude / type，每帧推进）；`setProperty` 在目标字段不存在时改为存成脚本变量并记日志（以前抛 `Invalid field` 直接废掉整个回调）；`cameraFade` 补上第五个参数 `?fadeOut`（四参数形式行为不变，五参数形式不再被静默丢弃）。

### 视频与录制

- **过场视频**：引擎改用 **hxvlc 2.3.1**（libVLC 3.0.23），树内的影子副本删除。开场 / 曲中过场照旧播放，`startVideo` 接受 1.0.4 的完整参数集（`canSkip` / `forMidSong` / `shouldLoop` / `playOnLoad`）；hxcodec 风格的 `FlxVideo` / `FlxVideoSprite` / `VideoSprite` 包装层与视频预加载器保留，模组照旧调用。
- **游戏内录制（桌面端）**：歌曲中按 **F9**（或开启「歌曲开始时渲染」）把游戏画面与 Inst / Voices 混音送进 ffmpeg，写到游戏旁的 `render_video/`。
  - 编码器：H.264（x264 / NVENC / AMF / QSV）、HEVC（x265 / NVENC）、VP9 / VP8（写 `.webm`，其余写 `.mp4`）；码率控制支持 CRF/CQP（恒定质量）、VBR（目标码率）与 CBR（固定码率）。
  - **1 帧 = 1/fps 的歌曲时间**：帧号由 Conductor 时钟推出来，暂停 / 跳转 / 变速自动对齐；渲染时游戏钉在设定帧率上用固定步长，跑不动的机器也不会改变视频长度（环形缓冲会等编码器而不是丢帧）。
  - **预览渲染**：整条流水线都跑（固定步长 + 逐帧抓取）但不写文件，先确认时序。
  - 渲染时角标显示状态，每次渲染都在输出旁写一个 `.log`（设置、帧数、速度、ffmpeg 自己的 stderr）。
  - 新增「渲染」设置页（三语）：歌曲开始时渲染、预览、帧率（15-480）、音频混合、编码器、码率控制、质量、码率、缓冲帧数（缓冲即内存上限）。
- 录制依赖系统里可用的 **ffmpeg**（GPU 编码器还需要支持的显卡与对应编码器构建）。

### 手机与启动

- **启动画面重做，引擎第一次有了自己的标记**：六边形核心、两条反向旋转的弧、一圈分段进度环，中间一颗四角星——全部由几何图形实时绘制，不用任何图片资源（引擎目前还没有正式图标，所以也不再拿 HaxeFlixel 的 logo 顶替）。

- **iPad / 平板**：画布偏移按真实的舞台单位与设备像素映射计算，Retina 切换时即时重排。
- **安卓**：崩溃报告列出加载的模块；联机聊天可以收起软键盘；聊天时按返回键不再退出结算页；输入框有内容时也能双击 B 取消；放行明文 `ws://` / `http://`（否则较新的系统会直接拒绝局域网连接）；编译改用 compileSdk 33。

### 关于大物量谱面的免责声明

> **游玩大物量谱面遇到卡顿，这是正常现象，不是 bug。** Note 数量没有上限，而任何设备的算力与显存都有——任何引擎的 Note 优化都只能在这些资源里争取余量，不能凭空造出性能。本引擎的全部优化（Turbo、折叠、缓存、流式加载、各项预算……）都**不构成「任何谱面都能流畅运行」的承诺**。
>
> **大物量谱面请使用为这类内容设计的专用引擎。** 向本引擎反馈大物量谱面的卡顿之前，请先确认你已接受这一条。

## English Version

This is SeiunEngine v0.2.2: the online pre-release stage (Pre-Online.1 → Pre-Online.3) reaches a regular release for the first time. Online play is no longer an experimental branch behind a build flag — it ships with the game by default. Chart loading, graphics memory, in-song cost, save writes and crash investigation were all reworked inside those three months as well. What follows is the final state, put in terms of what a player actually notices; approaches that later commits overturned are not recorded separately. A short overview follows, deliberately without figures, and then each chapter in turn.

### At a glance

This version deliberately does not quote the pre-release benchmark figures: they were measured on particular machines with particular charts, and publishing them turns them into promises. In terms of direction:

- **Chart loading**: from "the whole JSON DOM stays resident" to per-section streaming, with sorting, scanning and folding moved to structures that fit the job; charts dense with repeated notes can also be packed into a `.chartpack` that is orders of magnitude smaller.
- **Graphics**: atlas cropping, deduplication and palette textures bring VRAM down noticeably and roughly halve the GL submission count, with the picture pixel-identical.
- **Gameplay**: redrawing HUD text and popups costs far less, and the old "frame rate decays as the song goes on" no longer happens.
- **Stability**: crash reports are readable again, saves take a snapshot and can roll back, and online play reaches a regular release for the first time.

The trade-offs and reasoning behind each item are in the chapters below.

### Online

> **Credit**: the online slice's menu UI, room/protocol model and server-side room semantics are **ported from / modelled after** **Funkin-Psych-Online** and its companion **Funkin-Online-Server** by **Snirozu** (Apache License 2.0). The online code bundled in this engine is this project's own Haxe implementation and **contains no TypeScript or Node source** from those repositories. Full attribution: the `NOTICE` file in the repository root and the *Online UI / Protocol Reference* section of the in-game credits screen.

#### Three ways to start

- **Public servers**: fill in the address. Anything that falls back to plaintext `ws://` (bare IP, bare hostname, `http://x`, `ws://x`) gets the default port 2567 appended exactly once; `wss://` / `https://` keep 443 semantics, so public servers behind a reverse proxy are unaffected. Reachability reports **reachable / timed out / protocol mismatch**, the last meaning that address is not this engine's server or the versions differ.
- **LAN search**: don't know the host's IP? **Search for Servers on This Network** listens for UDP 2569 broadcasts for 4 seconds and lists what it heard as **Found on This Network** (nothing is joined automatically). Tick entries and press **Add Selected Servers** to write them into your server list; entries already listed are marked and cannot be ticked, and **Clear These Results** discards the batch. Broadcasts go to `x.y.z.255` of every interface, so VPN / WSL / Hyper-V adapters never steal them.
- **Hosting inside the game**: `LAN HOST` in the online menu runs the server inside your own game process; the room code carries the host's LAN IP, and friends paste that one line into JOIN.

#### Rooms, pausing and the start gate

- **Each player gets their own rating popup**: online, you and your opponent each have a set of rating icons and combo numbers, with no overwriting and no interference; the remote popup anchors to **that player's own character** (clamped to 5%–95% of screen width), falls back to the opponent's half when no bound character is found, and same-side players (coop / 2v2) are spread further apart. The local popup stays where it is in single player.
- **Combo numbers keep the engine's rule**: no number below 10 combo, three digits from 10 to 99 (for example `010`).
- **Room settings gain a "pause policy"** (host cycles, three modes): **host only** (the host pauses everyone; a guest pressing ESC only gets a local hint); **any player pauses everyone** (**default**); **keep the old logic** (pausing affects only yourself and no pause message is sent, exactly matching older versions).
- **The server is the sole arbiter**: a pause is echoed to everyone (including the initiator) with the initiator's identifier — your own identifier means you hold the pause, someone else's means you were merely force-paused and **cannot resume on your own**. If two players press ESC at the same moment, whoever reaches the server first holds it. When the holder leaves / disconnects / is kicked, when the song ends, or when state resets, the server broadcasts a resume automatically; late joiners do not inherit an old pause.
- **Start gate**: when the host presses play (or ACCEPT), everyone enters the chart and sees **Press ACCEPT to start** — ACCEPT / gamepad A / clicking the hint all count as "I'm ready", the hint becomes **Waiting for other players...**, and the countdown starts only when the host's start arrives. Android / touch-enabled desktop also shows an **A** virtual button that retracts once the host starts.
- **Room-level pause works by notification**, so others stop **one one-way delay** later and each side resumes from its own frozen position, preserving that offset (single-digit milliseconds on a LAN).

#### LAN: hosting from inside the game

- **`LAN HOST` panel**: start / stop, port (2567 by default, incremented upward when taken with the real occupancy shown), max players (1-64), *allow local player to join*, *public room*, a live status row (LAN address, click-to-copy room code, player count), firewall hints and *open local web console*.
- **A genuinely embedded server**: the same server code lives inside the game binary. Hosting binds 2567 (HTTP) + 2568 (WebSocket) inside the game process and the host client joins through the local address. Stopping releases both ports, and "start → stop → start" can be repeated within one session.
- **While hosting, both the game room and the social / network room talk to the local server**: only the address changes at runtime; the saved server list and account choice are untouched.
- **No account needed**: guests join with the room code; accounts, scores and leaderboards stay in the game's own save directory and are never uploaded.
- **Android** offers the panel and attempts hosting (best effort), with a manual-entry hint when no LAN address can be detected.
- **Embedded web console: local, login-free, read-only.** Only GETs from this machine (`127.0.0.0/8`, `::1`, `::ffff:127.0.0.1`) skip login; writes and other machines still go through the original four-step check (401). The standalone server disables the mode by default (`--console-local-readonly`).
- Embedded hosting writes its own `config.toml` (no `[smtp]` section) and the email blacklist does not apply in embedded mode — no impact when email is unconfigured.

#### Accounts and the server

- **Storage moved to SQLite**: WAL mode, one connection plus a single database mutex, append-only schema versioned by `user_version`, 13 tables. Scalar fields use typed columns; list-shaped fields stay in JSON text columns.
- **One-time legacy import**: on first start with an empty database the old accounts / leaderboard / clubs / mods / admin / public JSON is imported, then renamed to `*.imported-<timestamp>` (**never deleted**); `--import-legacy-json` re-runs it.
- **Credentials and sessions**: tokens are stored **only as HMAC-SHA256 hashes** (plus an 8-character lookup prefix), compared in constant time, with expiry and revocation; the plaintext token is returned once at login. Email codes are hashed too.
- **Random numbers**: `/dev/urandom` when available, otherwise an HMAC-SHA256 DRBG — and both the README and the startup log say plainly that **this is not a hardware CSPRNG**.
- **Observability**: structured JSON Lines logs rotated per day, read-only `GET /api/health`, `--log-dir` / `--log-level`.
- **Standalone server executable**: a native `SeiunServer.exe` with zero runtime dependencies; the neko target and all existing usage are unchanged.
- **API behaviour unchanged**: signatures, error strings, ordering, pagination and id formats are kept verbatim after the SQLite move. Two ports (HTTP 2567 + WebSocket 2568) with a protocol identifier and version check in the handshake.
- **The admin console page** is compiled into the server; when `server/web/` exists on disk it still wins, so editing pages stays refresh-only.
- **Config writing fixed**: announcements were truncated by UTF-8 **bytes**, cutting Chinese / emoji mid-character, corrupting `config.toml` and leaving console endpoints returning 500. Counting is by **characters** now (500, plus a 2048-byte cap), corrupted values on disk are repaired on load, and a failed write returns an error instead of a fake 200. The same sweep covered 12 user-visible length limits across the API.
- **Announcements**: persisted announcements ship with `GET /api/front`, render in a fixed area at the top-left of the online menu (up to 100 characters), and arrive as a titled notification (`NOTIFICATION` + content) on live push; wrapping counts characters, so CJK no longer wraps at about a third of its width.

#### In-game downloader

- GameBanana / PE search, download progress, install confirmation after the download finishes, downloaded files kept when installation is declined, redirects followed up to 3 hops.
- Fixed the thumbnail-fetch crash and the downloader crash on offline / online transitions.

#### Localization and setting values

- Engine menus and the entire online UI ship in Simplified Chinese, Traditional Chinese and English, sharing one key set.
- String setting values (language, display mode, time bar, note style, engine compatibility, the `Custom` judgement preset, touch-button position, ...) now follow the UI language; custom or untranslated values still show as-is.

#### Other online fixes

- A crash when opening the player leaderboard (server page size 20 vs the client's 15 rows).
- A reconnect crash in the network room (`NetworkClient.client` was never assigned).
- Remote players not animating after a character swap, and two players sharing one rating popup.
- **All runtime optimizations are force-disabled online** (`perfMode`, `bulkSkip`, `fastSort`, `scriptArgReuse`, `limitNotes` and Turbo's forced autoplay) — in memory for the current song only, restored from the entry snapshot on exit. Load-time optimizations (streaming parse, bucketed sort, huge-chart cache, section detection) stay on.

### Charts: one rewrite of chart loading

Parsing, sorting, scanning, folding, caching and the container were redone as one piece of work, so this is the final shape rather than the order we finished it in.

- **No more whole-file parse**: charts above 64 MB load as a byte stream — only the section being consumed is parsed and dropped immediately. **Charts at or under 64 MB behave exactly as before.**
- **Byte-level parsing**: notes are produced straight from the bytes — that section's `sectionNotes` is no longer materialised into an object tree, nor copied as a string, so the peak memory for a section drops sharply. Charts without an `events` field stream too (byte-level detection), no longer falling back to whole-DOM parsing — that fallback was why they froze on song select.
- **Sorting moved to counting buckets**: tens of millions of notes are placed by one linear counting pass instead of by comparison. Sorting was one of the heaviest stretches before a song started; with counting, it is no longer a bottleneck.
- **Scanning moved to a tight loop over a buffer**: section boundaries are found by a tight loop instead of walking the string character by character, which shortens that fixed cost before a song starts.
- **Column store**: every numeric field gets its own column and fields constant across the chart are hoisted to a scalar (no column at all), shrinking a note from hundreds of bytes to the order of a few tens; columns grow by doubling and can be written while parsing.
- **Counters are Int64**: a chart with two billion notes no longer overflows. Save and replay files write them as decimal strings and still read the old Int / Float / String forms.
- **Low-scroll-speed folding by screen pixel gap**: this engine has one render path — real note sprites — so "not enough performance" always means "too many live sprites". The visible band is `1400 / (0.45 × speed)` ms, about 3.1 s at speed 1.0 and 6.2 s at 0.5. Taps in the same lane, on the same side, at the same `multSpeed` and less than 4 pixels apart are merged into one representative note, and the fold count goes into `noteDensity`, so judgement and scoring are unchanged. The number of live notes stops exploding with chart density and low speed — at low speeds it falls back to roughly the high-speed range — while judgement and scoring stay exactly what they were.
- **The materialisation horizon follows the real pixel band**: the window is derived from screen geometry (still capped by the stock `spawnTime`), starting at 250 ms so a countdown no longer materialises thousands of notes at once.
- **A runtime pixel gate uses the *current* speed**, so even a `songSpeed` changed by an event or a tween keeps materialisation bounded; blocked notes settle in the data layer without stalling the cursor. `fastSkipPastNotes` and the new path share one settle function and frame accumulator, so a pixel band is not split into several combo runs.
- **Chart cache: the second load no longer recomputes.** The cache lives in `chart_cache/` next to the executable, two files per chart (`.skel` / `.notes`); what is cached is the **output** of the note loop, so a hit cannot point at the wrong note. Invalidation requires the **size + modification time** of every section file and the caller's configuration string to be unchanged. On a hit, skeleton scanning, per-section parsing, folding and sorting are skipped. Records are column-compressed, taking one list from gigabytes down to a few megabytes, and at most a 1 MB chunk is held in memory.
- **Cache settings** (Performance → Note Optimization): `超大谱面缓存` / `压缩谱面缓存` (both on by default; compression costs a little time on every read and write) and a `清除谱面缓存` button that reports how many MB were freed. Clear it once after editing a chart in place.
- **Song select no longer parses a whole chart for the preview**: streamed-size charts are recognised and skip preview parsing (the preview only needs the song name and `needsVoices`).
- **Sectioned charts accept any starting index**: all `<song>-<n>.json` files merge in ascending order from any start; a gap is recorded, not fatal; fewer than 2 files is still a single file; `<song>.json` in the same directory suppresses sectioning, and `.parts.json` remains the explicit override.
- **New `.chartpack` container (SEIUNPK1)**: the chart is a byte-preserved skeleton plus a group stream — repeated notes are written once with a repeat count (varint + zlib). The denser the repetition, the bigger the win: a chart directory of tens of gigabytes packs down to tens of kilobytes, and a gigantic single song packs down to megabytes, turning "read tens of gigabytes" into "read a few megabytes". The packer has a window (`chartpack-ui.exe`, bilingual, drag-and-drop, live ratio) and a command line; the engine only reads packs and never converts JSON automatically.
- **Very large charts load on multiple threads** (Turbo or more than 12,000,000 notes): parallel per-part scanning, then a decode-normalise pass feeding a single consumer that folds in chart order without creating Haxe objects on the workers. Any error **falls back to the Haxe path**.
- **A single chart file over 2 GB reads correctly** through 64-bit `seek` / `tell`; junk bytes inside `sectionNotes` are skipped and counted instead of throwing.
- **Online guarantees single-file charts only**: sectioned charts are **explicitly refused with a hint** instead of silently hanging on "waiting for the opponent's chart". Key counts come from each note's own mania snapshot, so charts with Change Mania score more accurately.

### Rendering

- **A Renderer row on the Graphics page** switches between OpenGL and Vulkan; the choice is confirmed, saved and applied on the next launch.
- **A failed start falls back by itself**: if the driver, the window or a pipeline fails, the session returns to OpenGL, the saved choice is put back, and a dialog says why. A launch that dies before it can report anything is recognised on the next boot, so a bad driver does not become a crash loop.
- **The command line still works**: `--vulkan` / `--no-vulkan` / `SEIUN_VULKAN` outrank the saved choice; `--vulkan-stats` prints frame and batch statistics; `logs/renderer.txt` records each launch's decision; `-DSEIUN_NO_VULKAN` leaves the backend out.
- **Still experimental**: offered on Windows only. Android compiles it in but does not offer it (mods and OpenFL shaders would need runtime GLSL → SPIR-V translation, and that chain does not exist); Linux / macOS / iOS do not offer it. Glow, drop shadow, displacement maps, the triangle path and offscreen render textures are not implemented.
- **The graphics memory backend was rewritten**: `GfxPolicy` / `GfxLru` / `GfxRepack` are gone (strong references, destroying images still in use, forced collections, runtime repacking). The new `GfxMemory` only drops the CPU copy of large images (≥512×512) after the GPU upload and lets OpenFL re-decode on demand; it never destroys images, never evicts caches, never touches the GC.
- **Atlas cropping**: the whole sheet is cropped to the region the frames actually use, with frame coordinates shifted by the same distance; verified frame by frame and rolled back wholesale on any mismatch; abandoned below 0.5% savings.
- **Atlas repacking**: per-frame trimming, identical tiles kept once, tight repacking with `offset` compensated; rolled back on failure, skipped below 5%, rotated / flipped frames roll back the whole sheet.
- **Palette textures**: an image with ≤256 distinct colours becomes an 8-bit index plus a 256-entry palette of premultiplied BGRA bytes, sampled with forced `NEAREST`; anything that fails verification falls back to RGBA per image.
- **What is saved is VRAM**: with cropping, deduplication and palette textures stacked, both boot-time decode memory and GPU memory drop noticeably — the palette gives the biggest win on large images, and repacking gives a smaller one at the cost of slightly slower loading. The working set stays about the same and the picture is pixel-identical.
- **GL submission cost**: viewport / texture binding / attribute-array bitmask are cached on the openfl side and redundant `glEnable` calls are gone — a representative frame's GL call count is roughly halved; dynamic vertex buffers refresh in place with `bufferSubData`.
- **Graphics options trimmed**: "texture reuse cache (LRU)" and "runtime texture repacking" removed; "large texture memory release" renamed and its threshold moved from 2048px to 512px.
- **Batching and picture**: per-vertex values are materialised only when a batch really has to mix colours or alpha; camera filters and the stage overlay are wired in; the mouse uses the system cursor. A landscape game on a portrait panel is no longer rotated another 90 degrees, and the right edge is no longer clipped on non-16:9 screens.
- **Window modes unified** in `backend.WindowMode` (windowed / fullscreen as a real SDL mode switch / borderless), shared by the boot flow and the options page.
- **Tablets and high DPI**: the canvas offset comes from the real stage-unit-to-device-pixel mapping (`backend/RenderScale.hx`) and re-lays out immediately when Retina changes.
- **Async image loading removed**: `AsyncGfxLoader` and its option are gone; decoding happens on the main thread in small per-frame batches. The GC-thread crash investigation pointed at the cross-thread bitmap publication path, and the async win was not worth that risk.

### Gameplay

- **The outlined-text redraw path is simpler**: the stroke went from "draw the whole TextField once per offset" (17 passes for the HUD) to "rasterise the outline once and blit it", 17 → 2 passes with identical pixels; incremental redraw touches only the device-pixel boxes that differ; an input signature skips rebuilds entirely; static text stable for 750 ms is paged into one shared sheet, so the menu's stable static text occupies a single draw and the page's batch count drops with it.
- **The result**: redraw cost drops noticeably with the picture unchanged — this changes *how* it is drawn, not *how much*.
- **HUD text behaves like stock 0.6.3 again**: per-frame hit queues, text throttling and 1x rasterisation are all reverted (scripts read `scoreTxt`, and `onUpdateScore` must see the new value on the hit frame). Every millisecond saved comes from the library patches, not from drawing less. HUD text stays at full resolution on high-resolution and high-DPI displays.
- **Two new switches on the Visuals page**: the hit timing readout (`showHitMs`) and the bottom-left song / version line (`showVersionText`), on by default and gated by Hide HUD. The old `Stock HUD Text Rewrite` option is gone.
- **Idle arrows no longer cost a separate draw**: the eight idle strums stopped carrying an identity `ColorSwap` (flixel batches per shader instance, so eight arrows were eight draws and could never batch with the notes), so they now batch with the falling notes.
- **Splash batching**: a neutral `ColorSwap` is no longer attached, letting several splashes batch together.
- **Combo / rating popups fixed and made cheaper**: a newly spawned combo icon now always draws on top; the pool no longer leaks container slots (the root cause of frame rate decaying over a dense chart). The combo count is no longer truncated; rating / digit / COMBO graphics are cached, acquisition is O(1), image keys are built once, combo digits go into a reused buffer, and fades no longer depend on FlxTween's global manager — allocation-free in steady state.
- **Budgets are charged by time**: popup / splash / materialisation / drain budgets were 60 fps design rates reset per rendered frame, so the per-second rate scaled with the fps cap (6x at 360 fps); they now accumulate as elapsed × 60, are spent in whole units and capped per frame, with 60 fps and below bit-identical.
- **`purgeUnusedGraphics()` reworked**: dead candidates are collected in one pass and removed in batches, ending the periodic multi-second main-thread freezes on long sessions; Sparrow atlas frame caches registered by a purged graphic are evicted with it, so no "zombie atlas" is left behind.
- **Turbo / Botplay HUD**: under Turbo the label reads `TURBO BOTPLAY` (normal autoplay still reads `BOTPLAY`, practice mode still reads `Practice Mode`); while autoplay the score line reads `Notes: <opponent> + <own> = <total> | NPS: … | HP: <health>%`, where NPS uses a 1-second sliding window with a **fast rise, slow fall** trajectory (a burst decays smoothly to zero over about a second and a half) and long numbers switch to a compact form such as `1.03B`.
- **Side HUD uses a fixed field width**: under Botplay / Turbo the counters change every frame, so the value-change skip never fires and proportional autoSize re-laid out a new bitmap per change; the side counters now use a fixed field width with one bitmap reused forever.
- **Mod skin sustain geometry**: broken sustains, misaligned tail caps and "the higher the BPM the bigger the offset" are fixed for trimmed Sparrow `arrowSkin` atlases — sustain height uses the atlas's visible region (`Note.sustainContentHeight()`), the falling-mode anchor sign is corrected, and the clip top uses `Note.contentTopInFrame()`. Default and built-in skins are bit-identical.
- **One entry point for note materials**: fixes pooled reloads leaving some notes uncoloured; Hurt note atlases are tinted through an RGB palette instead of looking for a missing `HURTNOTE_assets`; the pooled material comparison is field-by-field instead of building a string per note.
- **Results screen**: the rating icon no longer falls back to `FALSE` (the total omitted the perfect-plus bucket, so Turbo + autoplay produced a total of 0); icons fit a 240×90 frame with 150×150 still rendering 90×90; the stats legend no longer wraps or paints black blocks; leftover HUD elements hide together with the panel.
- **Judgement order fixed**: players with Marvelous enabled no longer get online scores weighted against the wrong tier.

### Saves and backups

A save used to go through OpenFL's `SharedObject.flush()`, which truncates before writing: a failure in the middle left a broken file and the next launch silently came back empty. The write path has protection now, and Backup / Restore was rewritten.

- **Snapshot before the risky write**: every flush writes the payload into `flxsave_backups/` first, keeping a configurable number of rotating snapshots (capped, can be disabled). Snapshots go to a temporary file and are renamed.
- **Damaged files come back**: when `bind()` cannot deserialize the save it archives the file as `*.corrupt`, puts the newest valid snapshot in place and sets `recovered`.
- **Writes are read back** (`verifyWrites`, can be turned off). An unserializable payload, an empty object over an existing file or a write above the size cap is refused before anything is truncated; a snapshot that cannot be created refuses to overwrite by default (`abortWhenBackupFails`).
- `MinFileSize` is really forwarded to `flush()`, and a failed flush reports why. Code that only calls `bind()` / `flush()` needs no changes.
- **A new container and payload** (`BackupFormat` / `BackupData`): the `SEB2` container carries a version and a checksum and names the reason a file is damaged; save fields are stored as `haxe.Serializer` output, so Maps, Int64 values and mod-added fields survive; score files are stored as raw bytes with validated paths.
- **All or nothing**: everything is decoded and verified before the restore starts, the current data is captured to a safety backup first, a failed write rolls back, and settings, key binds, scores, achievements and language are reloaded afterwards.
- **Old `SEB1` backups are still readable**, upgraded on read and merged into the current save.
- **The export streams to disk**; the import decodes in chunks and rejects a header that claims more than the file holds.
- **The backup screen was rebuilt**: Backup / Restore cards with keyboard, mouse and touch support; the confirmation shows the file date, engine version, field and score counts first; failures name the reason.

### Crashes

- **Four crash paths, one report format**: native crashes, script exceptions, low-level library init failures and the web build; the first line carries `Kind:` instead of guessing from the file name.
- Reports carry the system, GPU and driver, the system error code, the loaded modules and the build's identity (main module size and PE `TimeDateStamp`, whether a `Linemap` exists). Reports are UTF-8 with a BOM; Windows dialogs use UTF-16.
- **Backtraces carry source locations** (`[src/File.cpp:123]`) instead of `<sprintf>+0x...`; the header states which build produced the report and whether its symbols can be trusted (`SymType=0` means inline frame names are all fictitious).
- Reports carry facts only — the auto-generated "guessed cause" table is gone. They keep 150 lines of game log (about 30 before), the native buffer grew to 32 KB, and the context names the graphics settings in effect.
- **Every build publishes symbols**, and the tool can tell whether they belong to that build; a release ships one symbols archive per platform with a `manifest.json`, **never inside the game archive**. The bundle carries the ELF / Mach-O symbol tables, so `crash.py sym` turns an offset into a function name (the price is that macOS release builds no longer strip).
- **Nine old tools became one `crash.py`** (status / report / bundle / ui / symbols / prune / triage / resolve / verify-map / symbolize / linemap), bilingual. Splitting them was itself a bug source: a report could be resolved against another build's map with every frame "resolving" and every frame wrong.
- **The build toolchain is recorded**: every build writes `toolchain.json` / `toolchain.txt` / `toolchain-key.txt` and feeds `build.json`; the toolchain token takes part in the hxcpp object-cache key. Windows legs are pinned to a fixed image with a weekly canary.
- **F8 diagnostics**: press F8 while a chart stutters and the last 600 frames' section timings (whole frame / bulk settlement / note update / sort / popups / score text) are written to `crash/hitprobe.txt`. Read-only.
- **Safe mode is on by default**: Haxe-level errors carry source file and line numbers out of the box, and CI and release builds keep safe mode too.
- Fixed crashes with confirmed causes: `SDL_GetBasePath()` being freed after the SDL3 migration (a double free at exit); a null dereference from the render loop calling native window APIs after close; an out-of-bounds `members[idx]` read while the strum group was rebuilt; container members dereferenced after they had been collected.
- To be clear: multi-threaded rendering was removed long ago (`RenderThread` is a stub) and rendering has always run in the single-threaded main loop — it is **not** the cause of those crashes.

### Scripts (Lua / HScript)

- **Full 1.0.4 API alignment**: all 62 signatures 1.0.4 relaxed are relaxed here too, callback arguments match (`eventEarlyTrigger` gets `(event, value1, value2, strumTime)`, `onTweenCompleted(tag, vars)`), the two missing 1.0.4 functions `getFileTranslation` / `getTranslationPhrase` are added with a reader for 1.0.4's plain-text `data/<language>.lang` format, `Paths.getAtlas` / `Paths.getAsepriteAtlas` are ported so `'auto'` really auto-detects, and HScript gains `getModSetting` plus optional-argument `keyJustPressed` / `keyPressed` / `keyReleased`. Types are widened, `removeFromGroup` answers both dialects, and version-dependent defaults go through `CompatEngine` — 0.6.3 / 0.7.3 modes stay bit-identical.
- **Mod JSON is parsed the way 1.0.4 parses it**: `pack.json`, `stages/*.json`, `data/settings.json` and `images/gfDanceTitle.json` use a tolerant-first parser (tjson, then strict), so a trailing comma no longer disables a mod; song / character / dialogue parsing stays strict, matching 1.0.4.
- **`close()` no longer closes the wrong script**: the executing instance is recorded during callback dispatch and `close()` acts on it, with `CLOSE() <script>` in the log.
- **`callMethodFromObject` no longer calls with unresolved arguments**: `instanceArg(...)` resolves modchart sprites / texts first and skips the call with a logged warning otherwise — fixing a `0xC0000005` crash from a mod passing null into `mouse.overlaps`.
- **`getDataFromSave` honours its default value** in 0.7.3 / 1.0.4 semantics; `logs/script_log.txt` records `[save]` diagnostics.
- **Scripts are less able to kill the process**: missing tags skip safely; `safeColor()` replaces hand-rolled hex conversions; the software cursor is force-disabled before gameplay; the engine's extra HUD widgets hide together with `scoreTxt.visible`.
- **1.0.4 judgement-name mapping**: a new option (on by default, 1.0.4 mode only) rewrites the engine-private `marvelous` to `sick` for scripts reading rating names; the engine's own judgement, scoring, results, online and replays keep the real rating, and `notes.members[i].ratingRaw` exposes the perfect-plus tier.
- **Script errors no longer disable the whole script, and silencing is off by default**: the error limit defaults to 0; a positive limit only triggers silencing (one summary line, then rate-limited) while other callbacks keep running.
- **`logs/script_log.txt`** (recreated each launch, capped at 20,000 lines) records every loaded Lua script with its path, every scanned folder (`MISSING` when absent), every script error with script + callback + raw text, which scripts received the lifecycle callbacks, and `[scan]` lines naming `currentMod` / `globalMods` — exactly what decides whether a mod's `data/<song>/` folder is searched.
- **New scripting capabilities**: `addWiggleEffect` / `removeWiggleEffect` (H-Slice signature); `setProperty` on a missing field stores a script variable instead of killing the callback; `cameraFade` gains `?fadeOut` with the four-argument form unchanged.

### Video and recording

- **Cutscene playback** moved to **hxvlc 2.3.1** (libVLC 3.0.23) and the in-tree shadow copy is gone; `startVideo` accepts 1.0.4's full parameter set, and the hxcodec-style wrappers stay, so mods keep calling them the old way.
- **In-game recording (desktop)**: press **F9** during a song (or enable "render on song start") to pipe frames plus the Inst / Voices mix into ffmpeg under `render_video/`.
  - Encoders: H.264 (x264 / NVENC / AMF / QSV), HEVC (x265 / NVENC), VP9 / VP8 (`.webm` for VP8 / VP9, `.mp4` otherwise); rate control supports CRF/CQP, VBR and CBR.
  - **1 frame = 1/fps of song time**: frame numbers come from the Conductor clock, so pause / seek / speed changes line up; the game is pinned to the configured rate with a fixed timestep, and a machine that cannot keep up does not change the video length.
  - **Preview render** runs the whole pipeline without writing a file; a corner badge shows state, and every render writes a `.log` next to the output.
  - A new Render settings page (trilingual): render on song start, preview, framerate (15-480), audio mix, codec, rate control, quality, bitrate and buffer frames.
- Recording needs an **ffmpeg** available on the system (GPU encoders additionally need a supported GPU and encoder build).

### Phones and launching

- **The boot screen was rebuilt, and the engine finally has a mark of its own**: a hexagonal core, two counter-rotating arcs and a segmented progress ring around a four-point star — all drawn from geometry at runtime, with no image assets (the engine has no official icon yet, so it no longer borrows HaxeFlixel's logo either).
- **The intro follows the music**: four light streaks leave the corners on the jingle's first four notes and arrive together on the fifth, ringing out on impact. The mark then rises out of the way while the title arrives letter by letter, followed by the hairline, the tagline, the version and the corner labels. Any key or click skips the intro; the loading itself is not skipped.
- **Loading no longer freezes the animation**: the old splash decoded one atlas per frame while it animated, so a single decode landed right on top of the choreography and read as a hang. The intro now decodes nothing, and the progress bar starts working once the intro is over — the animation stays smooth even when loading is slow.
- **Progress is real**: the bar, the segmented ring and the `atlas / logoBumpin` line underneath all report finished work, and the task line follows the phase (loading graphics / caching sounds / ready).
- **More information**: the renderer actually drawing this frame bottom-left (with the OpenGL / Vulkan marks already in the repository), platform and word size top-right, and the engine version plus build under the title — including a live switch if Vulkan takes the window over mid-boot.
- **The exit** holds for a "ready" pulse and then fades, instead of cutting to black.
- **iPhone / iPad**: the picture fills the screen, fonts load properly, and video and rendering run on SDL3. This is the first playable iOS build.
- **iOS has not been verified on a device**: the fixes are verified at the code and CI level, and the `.ipa` CI produces is ad-hoc signed with no provisioning profile. Treat the platform as experimental.
- **iPad / tablets**: the canvas offset comes from the real stage-unit-to-device-pixel mapping, re-laying out immediately on Retina changes.
- **Android**: crash reports list the loaded modules; the online chat box can close the keyboard; BACK while chatting no longer leaves the results screen; a prompt with content can be cancelled with a double B; plaintext `ws://` / `http://` is allowed (newer systems refuse LAN connections otherwise); builds use compileSdk 33.
- **Launching from a shortcut or a command line** no longer loses assets, mods and crash reports.
- Android permission dialogs (all-files access, overlay) use the engine's own multilingual dialog after the language loads, backed by the new `Android.json`.

### Editors and interface

- **Controls rebuilt**: panels, buttons, check boxes, sliders, numeric steppers, radio groups, input fields and tabs share one event model; panels drag and collapse on a double click and page switches fade in. The old "collapsed panel still eats clicks" and "page destroyed mid-fade leaves an invisible control" faults are gone.
- **Two chart editor layouts**: a top-right button switches between "modern" and "classic (0.6.3)", both moving the same control objects. The old `PsychUIDropDownMenuOld` is deleted.
- **Screens switch with a transition**: shutter (default), fade or instant; existing call sites keep working.
- **Menu effects removed**: aurora, particles, beat pulses, selection glow, entry animations and the freeplay preview glow, plus their options.
- **The credits screen** now lists GitHub contributors.
- **File dialogs**: opening one while the previous is still pending no longer throws into the main loop; the state resets, the attempt is logged and `onError` runs.

### For mod authors

**Gone outright:**

- **The menu effect API and its options** (aurora, particles, beat pulses, selection glow, entry animations, the freeplay preview glow). The API existed since 0.2.1 and is removed wholesale in this release — mods that call it will fail to load.
- **`PsychUIDropDownMenuOld`** (present since 0.2.1) is deleted; use the unified control set.
- `Stock HUD Text Rewrite` is replaced by `showHitMs` / `showVersionText`.
- The "async image loading" option and `AsyncGfxLoader` are removed.
- "Texture reuse cache (LRU)" and "runtime texture repacking" are removed.

**Still runs, different result:**

- Atlas cropping hides blank areas from mods that read whole atlases by coordinates, and indexed palettes filter slightly differently when scaling or rotating with smoothing on (identical at 1:1).
- Side HUD counters use a fixed field width now, so mods that OCR the pixels will see different glyph spacing.
- The 1.0.4-only judgement-name mapping rewrites `marvelous` to `sick` for scripts.

**Saves**: after the `FlxSave` rewrite, code that only calls `bind()` / `flush()` stays compatible; the new fields are optional.

### Upgrading from 0.2.1

- **Old saves, replays and charts all load directly**: with Int64 counters, saves and replays write decimal strings and still read the old Int / Float / String forms.
- **Old `SEB1` backups still import**, upgraded on read and merged into the current save; a restore takes a safety backup of the current data first.
- **Clear the chart cache once**: the hit test is "section file size + modification time + configuration string", so a tool that edited a chart in place while preserving timestamps keeps the old cache alive. Performance → Note Optimization → `清除谱面缓存`.
- **Two graphics options are gone and one is new**: "texture reuse cache (LRU)" and "runtime texture repacking" are removed, and a Renderer row is added (Vulkan selectable on Windows, OpenGL by default).
- **The menu effect switches are gone**: the keys in your save are ignored, and the interface no longer has aurora / particles / beat pulses / selection glow / entry animations / the freeplay preview glow.
- **HUD**: `Stock HUD Text Rewrite` is replaced by two independent switches, the hit timing readout and the song / version line.
- **Online appears in a regular release for the first time**: 0.2.1 and earlier had no online play; if you ran a pre-release, your server list and account still carry over.

### Known issues

- The atlas and palette differences above: reading through frames is unaffected and 1:1 is identical.
- Turbo and very large charts can lose Alt Animation on the accelerated loading path.
- tvOS only has the compile switch — no build, no verification.
- iOS is not verified on a device and the `.ipa` has to be re-signed.
- Installing under a read-only location such as `Program Files` cannot write saves or crash reports.
- Vulkan is offered on Windows only, some filters and offscreen rendering are not implemented, and it stays experimental.
- Stutter on enormous charts is expected.
- Online rooms guarantee single-file charts only; sectioned charts combined with the huge-chart cache are not guaranteed.
- The server only arbitrates and relays — **there is no server-side simulation and no anti-cheat boundary**: scores are reported by the client.
- LAN hosting needs firewall allowance for **2567 and 2568**, and LAN search depends on UDP **2569**; only host on networks you trust, since the embedded server binds every interface and its REST and `/console` endpoints are visible on the LAN (read-only).
- **This release is still in development**: the list above will keep changing.

### A disclaimer about huge charts

> **Stuttering while playing a huge chart is normal and expected — it is not a bug.** Note counts have no ceiling while every device's compute and VRAM do; any engine's note optimizations can only buy headroom inside those resources, never conjure performance out of nothing. None of this engine's optimizations (Turbo, folding, caching, streaming, the various budgets, ...) is a promise that "every chart runs smoothly".
>
> **For huge charts, please use an engine built specifically for them.** Before reporting a huge chart's stutter against this engine, please make sure you accept this statement.

### Underlying libraries

<details>
<summary>For developers and anyone debugging</summary>

- **Script engine 1.5.0 (hscript-seiun)**: a compiled execution backend — `hscript.Compiler` lowers the AST to closures instead of walking it; call frames link the captured environment rather than copying it per call (the environment captured at function creation lives in `frameParent`, and `Interp.locals` now means the current call frame only); two runtime guards turn stack overflows and infinite loops into catchable script errors (`maxCallDepth`, a loop-iteration budget); anonymous-object field access gets a fast path, local writes carry scope tags, and script-class instantiation is faster. A differential compiled-vs-interpreted test suite and Measure / Cmp / Diff bench harnesses ship with it: 649 assertions across compiled, interpreter-only and linked-frame builds.
- **The C++ runtime (hxcpp)**: finalisers are registered only for values with a non-trivial destructor; buffer pointers use `Pointer()` / `data()` instead of `&a[0]`; `hxcpp.n` was rebuilt from the updated build-tool sources; CI workflows moved to Node 24 actions. The earlier rebase (single-line bilingual build progress, the `0x07` conservative-GC alignment mask) already shipped in the previous version.
- **The renderer backend (the lime fork)**: the Vulkan renderer is compiled into `Lime.ndll` (Windows / Linux / Android, `-Dlime-vulkan-off` leaves it out) and covers note batches, colour transforms, palette textures, camera filters, per-sprite shaders, the overlay and video frames, plus a texture memory budget, image suballocation, a pipeline cache and frame statistics; this version adds upload channels split per frame slot, pre-rotation handed to the compositor, `SUBOPTIMAL` no longer rebuilding the swapchain, and ANativeWindow takeover. Desktop file dialogs moved to the SDL3 dialog API, and every HxString → native `char*` path goes through one UTF-8 conversion helper.
- **The openfl fork**: the bitmap buffer keeps headroom so cairo/pixman cannot write past it; GL state is not re-sent and dynamic vertex buffers refresh in place; a `FileReference` failure no longer terminates the process; a colour-only text change no longer invalidates the layout.
- **The flixel fork**: outlined text is rasterised once; unchanged text skips the rebuild and static text batches into one page; the palette hooks into the atlas and the quad batch; `FlxSave` rewritten; "separate update and draw" is a real mode (`FlxG.separateUpdateDraw`, `separateDrawSkipIdleFrames`, `FlxGame.invalidateDrawCache()`).
- **flixel-ui**: a sort-by-ID branch that swallowed every value is fixed.
- **Video library**: hxvlc 2.3.1 (libVLC 3.0.23) ships real libvlc dylibs and the macOS packaging failure is fixed.
- **Lua**: a state's callback table is dropped before the state closes; reading a function out of Lua no longer changes the stack; linc_luajit pushes a copy first so the stack stays balanced, and `forget_state` collects the leftover callback entries; the prebuilt Lua binaries were rebuilt by CI with an architecture check.
- **extension-androidtools**: a legacy nested layout is repaired before extraction, and the extraction version marker forces old assets to be overwritten after an update.
- **Toolchain**: Haxe 4.3.7; every build records its toolchain, Windows legs are pinned to a fixed image with a weekly canary, and Android builds with compileSdk 33.

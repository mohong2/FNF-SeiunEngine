# SeiunEngine v0.2.2 Pre-Online.1 · 更新公告 / Release Notes

---

## 中文版

这是 SeiunEngine 的 v0.2.2 Pre-Online.1。本次把引擎带进「联机时代」，重做了谱面加载与低流速 Note 的性能模型，修好了连击 / 评分弹窗的显示与开销问题，把设置里的文字取值接入多语言，并让崩溃报告重新变得可读。

同一张一千多万 Note 的谱面，过去光是把 JSON 解析成 DOM 就要约 4.8 GB，2 GB 级的谱面根本载不入；现在只解析当前消费的小节、用完即丢，不再逐节建 DOM，排序与扫描也换成了更快的数据结构。

### 联机

- **联机对战**：房间列表、大厅、共享血条、逐玩家评分、聊天与私聊、房间设置、断线重连。
- **账号与服务端**：注册 / 登录 / 改邮箱 / 删号（真实邮件验证码）、排行榜、俱乐部、Mod 仓库、通知与好友；服务端为 Haxe 重写，不依赖 Node / colyseus。
- **游戏内下载器**：GameBanana / PE 搜索、下载进度、下载完成后再确认安装；取消安装时保留已下载的文件；重定向最多跟随 3 跳。
- **多语言**：引擎菜单与整个联机界面的文案支持简体中文 / 繁体中文 / 英文。

### 谱面加载

- **不再整份解析**：大于 64 MB 的谱面走字节流式加载 —— 只把当前小节解析出来、用完立刻丢弃，整份 DOM 不常驻内存。**≤64 MB 的谱面行为完全不变。**
- **字节级解析**：逐条按字节产出数据，不再为每一节建一次 JSON DOM；单节峰值从约 52 MB 降到约 6 MB，也不再复制那一节的 JSON 字符串。
- **排序**：上千万条 Note 改用计数分桶排序。A 谱面（1183 万 Note）的排序耗时由 **2.8 s 降到 1.6 s**。
- **扫描**：定位小节边界的扫描器换成缓冲区内的紧循环。同一张谱面的扫描耗时由 **2.06 s 降到 0.62 s**（与游戏同一后端实测）。

### Note 性能（Turbo）

- **低流速 Note 性能修复**：引擎只有一条渲染路径 —— 真实 Note 精灵，所以「性能不够」永远等价于「同时存活的精灵太多了」。低流速下这个问题最严重：屏幕像素带是固定的，而它换算成的可视频段为 `1400 / (0.45 × 流速)` 毫秒，流速 1.0 时约 3.1 秒、流速 0.5 时约 6.2 秒。几千万 Note 的谱面在这个窗口里能塞进六位数条 Note，全部物化就是纯浪费 —— 这正是「高流速顶得住、低流速直接拉胯」的原因。
  修复改为按**屏幕像素间距**（而不是时间间距）折叠：同轨道、同侧、同 `multSpeed`、间距不足 4 像素的 tap 合并成一条代表 Note，折叠数量记入 `noteDensity`，因此判定与计分口径与原来完全一致。判据与流速自洽，流速越低合并越多，物化量因此恒定，不再随谱面密度爆炸。
  实测（`floccinaucinihilipilificatiophobia`，327,942 条，8K）：同时存活精灵数的峰值由 1788 / 3344 / 5200 / 5200 / 4160 降到 450 / 896 / 1392 / 1401 / 1372（对应流速 0.5 / 1 / 2 / 4 / 10）；`miragist`（3,382,148 条，4K）由 1121 / 1121 / 1743 / 1743 / 1394 降到 371 / 639 / 873 / 449 / 459（同样对应流速 0.5 / 1 / 2 / 4 / 10）。
- **移除 `turbo_cache` 侧车缓存**：它缓存的是 Note 列表的**下标区间** —— 谱面或折叠规则一变就整体错位，而算错的区间不会报错，只会静默算错；它的指纹也不稳定，同一首歌会被反复生成新缓存。去掉后每次进歌只多一次 O(n) 扫描，换来的是结果稳定，划算。
- **物化地平线对齐真实像素带**：生成窗口不再固定按 2000ms 铺开，而是按屏幕几何推导（上限仍为原版 `spawnTime`）。初值同时降到 250ms，避免倒计时前按 2 秒窗口一次性物化成千上万条 Note。
- **运行时像素级归属闸门**：与加载期折叠同一判据，但用**当前**流速计算；即使运行中 `songSpeed` 被事件或缓动改写，物化量依然有界。被挡下的音符就地走数据层结算，不会卡住结算游标。
- **批量结算路径统一**：`fastSkipPastNotes` 与新物化路径共用同一个结算函数与帧内累加器，保证「游标只前进、绝不提前消费却不推进」，同一像素带内的音符同时结算，不会把 combo 拆成好几段。
- **Turbo 下对手命中计入连击**：对手命中的 Note 现在也计入玩家连击与侧边 HUD 的总击中数（仅 Turbo）。
- **联机时静默关闭 Turbo**：Turbo 会强制自动打谱，与共享血条 / 逐玩家评分冲突；联机进入时它静默失效，退出联机后按用户设置照常生效。

### 连击弹窗与设置

- **连击 / 评分弹窗修复与提速**：修复开启「连击堆叠」后新生成的连击图标会被旧图标压住的问题 —— 现在后生成的图标始终绘制在最上层，不再沉底、不再重影。同时修掉弹窗对象池从不释放容器槽位、导致每帧绘制循环越走越长的问题，这正是高密度谱面下「帧数随歌曲进行持续下降」的根因。
- **连击数字完整显示**：连击数不再被截断，打到多少就显示多少。同时 rating / 数字 / COMBO 贴图改为缓存复用、弹窗取用改为 O(1)，十万级 NPS 下每次命中的弹窗开销明显下降。
- **设置项取值本地化**：语言、显示模式（窗口化 / 全屏 / 无边框）、时间条类型、Note 样式、引擎兼容模式、判定预设 `Custom`、触控按键位置等字符串选项的取值现在跟随界面语言显示（例如语言项由 `ChineseSimplified` 显示为「简体中文」）。自定义或未翻译的取值仍按原样显示。

### 崩溃排查与诊断

- **崩溃报告现在能直接看懂**：堆栈自带源码位置（形如 `[src/File.cpp:123]`），不再是一串 `<sprintf>+0x...` 的假地址；报告头还会写明它是哪一次构建、符号是否可信。
- **修掉三个具体的崩溃原因**：SDL3 迁移后 `SDL_GetBasePath()` 被错误释放（退出时 double free）；窗口关闭后渲染循环仍在调用 native 接口造成的空指针解引用；strum 组重建期间越界取成员（release 构建下 hxcpp 返回 `null` 而不报错，紧接着解引用直接崩溃）。
- **调试符号单独发布**：符号包挂在 Release 上，**不会混进玩家下载的游戏包**，游戏包内容不变。
- **F8 诊断**：卡顿时按一次 F8，会把最近 600 帧的分段耗时（整帧 / 批量结算 / Note 更新 / 排序 / 弹窗 / 分数文字）写到 `crash/hitprobe.txt`，把文件发回来就能定位是哪一段拖慢的。只读诊断，不影响判定与上报。
- 顺带澄清：多线程渲染早已移除（`RenderThread` 是空壳），渲染一直在单线程主循环里 —— 它**不是**崩溃的原因。

### 其他修复

- 修掉打开玩家排行榜时的闪退（服务端分页 20 与客户端 15 行不一致导致越界）。
- 修掉下载器缩略图下载的闪退，以及断网 / 联网时的下载器崩溃。
- 修掉 network 房间断线重连的闪退（`NetworkClient.client` 静态字段从未被赋值）。
- 修掉联机房间内角色被事件替换后远端不播动作、评分图标两玩家共用一套的问题。

## English Version

This is SeiunEngine v0.2.2 Pre-Online.1. It brings the engine into its online era, reworks chart loading and the low-scroll-speed note performance model, fixes the combo / rating popup's display and cost, moves the string setting values into the localization system, and makes crash reports readable again.

A chart with over ten million notes used to need roughly 4.8 GB just for the parsed JSON DOM — charts in the two-gigabyte range would not load at all. Only the section being consumed is parsed now and dropped immediately, no per-section DOM is built, and both sorting and scanning moved to faster algorithms.

### Online

- **Online multiplayer**: room list, lobby, shared health, per-player scoring, chat and DMs, room settings, reconnect.
- **Accounts and server**: register / login / change email / delete account (real email verification codes), leaderboards, clubs, mod repository, notifications and friends. The server is a Haxe rewrite with no Node / colyseus dependency.
- **In-game downloader**: GameBanana / PE search, download progress, install confirmation after the download finishes, downloaded files kept when installation is declined, redirects followed up to 3 hops.
- **Localization**: engine menus and the entire online UI ship in Simplified Chinese, Traditional Chinese and English.

### Chart loading

- **No more whole-file parse**: charts above 64 MB are loaded as a byte stream — only the section currently being consumed is parsed and dropped immediately, so the full DOM never stays resident. **Charts at or under 64 MB behave exactly as before.**
- **Byte-level parsing**: notes are produced straight from the bytes instead of building a JSON DOM per section; the per-section peak drops from roughly 52 MB to about 6 MB, and that section's JSON string is no longer copied either.
- **Sorting**: millions of notes now use a counting bucket sort. Chart A (11.8M notes) sorts in **1.6 s instead of 2.8 s**.
- **Scanning**: section boundaries are located with a tight loop over the read buffer. Scanning the same chart drops from **2.06 s to 0.62 s** (measured on the same backend as the game).

### Note performance (Turbo)

- **Low-scroll-speed note performance fix**: the engine has exactly one rendering path — real Note sprites — so "not fast enough" always means "too many sprites alive at once". Low scroll speed is where this hurts most: the screen's pixel band is fixed, and the time window it maps to is `1400 / (0.45 × speed)` ms — about 3.1 s at speed 1.0 and 6.2 s at speed 0.5. A chart with tens of millions of notes can fit six figures of notes inside that window, and materialising all of them is pure waste. That is exactly why high scroll speeds hold up while low ones collapse.
  The fix coalesces by **on-screen pixel spacing** instead of time spacing: taps in the same lane, same side, same `multSpeed`, less than 4 px apart, merge into one representative note, with the folded count stored in `noteDensity`. Judgement and scoring semantics are therefore unchanged. Because the criterion scales with scroll speed, lower speeds fold more and the materialised count stays constant instead of exploding with chart density.
  Measured (`floccinaucinihilipilificatiophobia`, 327,942 notes, 8K): peak simultaneously-alive sprites drop from 1788 / 3344 / 5200 / 5200 / 4160 to 450 / 896 / 1392 / 1401 / 1372 (speeds 0.5 / 1 / 2 / 4 / 10). `miragist` (3,382,148 notes, 4K) drops from 1121 / 1121 / 1743 / 1743 / 1394 to 371 / 639 / 873 / 449 / 459 (same speeds).
- **Removed the `turbo_cache` sidecar cache**: it cached **index ranges** into the note list — any change to the chart or to the folding rule shifts them wholesale, and a wrong range does not crash; it silently computes the wrong notes. Its fingerprint was unstable too, so the same song kept minting new cache files. Dropping it costs one extra O(n) scan per song load and buys stable results — a good trade.
- **Spawn horizon aligned to the real pixel band**: the spawn window is no longer a flat 2000 ms; it is derived from screen geometry, capped at the original `spawnTime`. Its initial value also drops to 250 ms so the pre-countdown frames cannot materialise thousands of notes on a 2-second window.
- **Runtime pixel-level admission gate**: the same criterion as the load-time fold, but evaluated against the **current** scroll speed, so materialisation stays bounded even if `songSpeed` is changed at runtime by an event or a tween. Rejected notes are settled in the data layer on the spot, without stalling the settlement cursor.
- **Unified bulk settlement path**: `fastSkipPastNotes` and the materialisation path now share one settlement function and one per-frame accumulator, guaranteeing the cursor only ever moves forward and never consumes a note without advancing. Notes inside the same pixel band settle together, so combo is never split into fragments.
- **Opponent hits count towards combo in Turbo**: opponent notes now add to the player's combo and to the side HUD's total hit count (Turbo only).
- **Turbo is silently disabled online**: Turbo forces autoplay and conflicts with the shared health bar and per-player scoring; it is switched off inside online rooms and behaves as configured outside them.

### Combo popup and settings

- **Combo / rating popup fixed and made cheaper**: with combo stacking enabled, a newly spawned combo icon used to be drawn underneath the older ones — the newest popup now always draws on top, with no sinking and no ghosting. The popup pool also never released its container slots, so the per-frame draw loop grew with every hit; that was the root cause of the frame rate decaying over the course of a dense chart.
- **Full combo number**: the combo count is no longer truncated — whatever you hit is what is shown. Rating / digit / COMBO graphics are now cached and reused, and popup acquisition is O(1), so the per-hit popup cost at six-figure NPS drops noticeably.
- **Localized setting values**: language, display mode (windowed / fullscreen / borderless), time bar type, note style, engine compatibility, the `Custom` judgement preset and the extra touch-button position now follow the UI language (for example the language row shows 简体中文 instead of `ChineseSimplified`). Custom or untranslated values still show as-is.

### Crash reporting and diagnostics

- **Crash reports are readable again**: backtraces carry source locations (like `[src/File.cpp:123]`) instead of fake `<sprintf>+0x...` addresses, and the header states which build the report came from and whether its symbols can be trusted.
- **Three specific crash causes fixed**: `SDL_GetBasePath()` being freed after the SDL3 migration (a double free at exit); a null-pointer dereference from the render loop calling native window APIs after the window was closed; and an out-of-bounds `members[idx]` read while the strum group was being rebuilt (release-mode hxcpp returns `null` instead of trapping, and the next dereference is an instant crash).
- **Debug symbols ship separately**: the symbol bundle is attached to the Release and **never mixed into the game archive players download** — the game package is unchanged.
- **F8 diagnostics**: when a chart stutters, press F8 once and the last 600 frames' timings (whole frame / bulk settlement / note update / sort / popup / score text) are written to `crash/hitprobe.txt`; sending that file back pinpoints the slow section. Read-only; judgement and reporting are untouched.
- Related clarification: multi-threaded rendering was removed long ago (`RenderThread` is a stub) and rendering has always run in the single-threaded main loop — it is **not** the cause of the crashes.

### Other fixes

- Fixed a crash when opening the player leaderboard (server page size 20 vs the client's 15 rows).
- Fixed downloader crashes on thumbnail fetch and on offline / online transitions.
- Fixed a crash while reconnecting in the network room (`NetworkClient.client` was never assigned).
- Fixed remote players not animating after a character swap, and two players sharing one rating popup.

## 中文版

0.2.2 Pre-Online.2 才刚开始：这一部分把「巨大谱面的第二次加载」变成可缓存的一步，让选歌不再为预览解析整张谱面，把分段谱面的识别放宽到任意起始编号，给 Turbo / Botplay 补上自己的 HUD，并修掉结算界面的评分图标、统计图例与残留 HUD 三处显示问题。版本号已改为 `0.2.2preonline2`，**后续更新会继续追加到这份公告里**。

### 谱面缓存：第二次加载不再重算

- **落盘位置**：可执行文件旁的 `chart_cache/`，每张谱面两个文件（`.skel` / `.notes`）。缓存的是 `generateSong` 里 Note 循环的**输出**（完整 DTO，而不是可变数组的下标），所以即使命中缓存也不可能指到错的那一条 Note。
- **失效判据**：每个分段文件的**大小 + 修改时间**与调用方的配置串（流速、mania、折叠阈值、Turbo 开关…）都不变才使用；任何一项变了就是 miss，并重写缓存。
- **命中时省掉的工作**：骨架扫描（ChartStream）、逐小节解析（ChartSectionReader / ChartPrefetch）、折叠（TurboDensity）、排序（ChartSort）全部跳过 —— 直接回放 Note 列表。
- **文件大小**：记录按列压缩（实测一张 12,608,616 条 Note 的列表里，12 个 Float 列有 7 列、5 个 String 列与 splash 块**每列都只有一个取值**），恒定列只存一次、常零列只占一个 bit、其余按 1 MB 块 deflate。同一张列表 **1.78 GB → 几 MB**（设置项里的实测是 290 MB → 压缩后 2 MB）；读写时内存里最多只持有 1 MB 块。
- **实测产物**：45 GB / 2,064,278,444 个 tap 的 amphotercity（折叠后 4,291,710 条代表 Note）缓存为 `.skel` 14,215,997 B + `.notes` 12,855,326 B。
- **设置**（性能页 → Note 优化）：`Huge Chart Cache`（默认开）、`Compress the Chart Cache`（默认开，代价约每次读写 +1 秒）、`Clear the Chart Cache` 按钮（会报告释放了多少 MB）；原地改过谱面后建议清一次。

### 选歌不再为「预览」解析整张谱面

- Freeplay 的预览块在 `PRELOAD_ALL` 下**每次选中歌曲**都会调用一次 `Song.loadFromJson()`：2 GB 的单文件谱面要几秒，分段谱面更久。现在先把该谱面识别成「流式尺寸」，直接跳过预览解析（预览只需要歌名与 `needsVoices`），并写一条 trace 便于确认确实跳过了。

### 分段谱面：识别放宽到任意起始编号

- 规则改为：目录里所有 `<song>-<n>.json` 按 n 升序，**从最小编号到最大编号**，起始位置任意（miragist 从 0、amphotercity 从 1，以后从 5 或 100 也一样）。
- 中间缺文件**只记录、不再作废**（trace 出缺哪些编号），仍按现有文件合并；编号文件少于 2 个仍按单文件处理。
- 仍然保留的判据：同目录存在 `<song>.json` 时不做分段（那是「普通歌 + 数字难度」的判据），`.parts.json` 清单仍是显式覆盖手段；玩家侧仍有 `Manifest/Off` 与选歌热键的 per-song 覆盖。
- 回归：合成布局（0 开头 / 5 开头 / 100 开头 / 0..3+7..9 断号 / 0..2+500 游离号 / 单个编号文件 / 裸名优先）+ 真实 miragist(29 段) / amphotercity(33 段) / amphotercity `empty` / slide20 共 11 例全部符合预期，现有 mod 的行为没有变化。

### 没有 `events` 字段的谱面也能流式加载

- 单文件谱面原先必须能「合成 events」才走流式读取；改用字节级特征（负的 Note 索引）判断后，老格式 / 外部工具转换的谱面（例如 2,105,875,665 B、153,955,328 条 Note 的 slide20）不再退回整份 DOM 解析 —— 那次回退正是这类谱面在 Freeplay 卡死的原因。

### Turbo / Botplay 的 HUD

- **标签**：Turbo 下显示 `TURBO BOTPLAY`（普通自动打谱仍是 `BOTPLAY`，练习模式仍是 `Practice Mode`）。
- **分数行**（仅自动打谱；手动模式逐字节不变）：
  `Notes: <对手命中> + <bf命中> = <合计> | NPS: <对手当前>/<峰值> + <bf当前>/<峰值> = <合计当前>/<峰值> | HP: <血量>%`
  - 对手侧命中用新增的 `opCombo` 统计，Turbo 折叠组按 `noteDensity` 计 ⇒ 是**原始 tap 数**；bf 侧用引擎自己的判定计数（`totalPlayed - songMisses`）。
  - NPS 是 1 秒滑动窗口（100 个 10 ms 桶）+ **快起慢落弹道**：一帧 5000 的突发会在约 1.47 秒内平滑回零，而不是像窗口原值那样一帧跳回 0；峰值单独记录窗口真值。
  - 显示值走私有单调计数器：脚本写 `opCombo` 只会改变总数，不会在 NPS 上伪造一次爆发。
  - 超长数字自动用紧凑写法（`1.03B`）保证单行，精确值仍在左侧统计栏。

### 结算界面

- **评分图标不再错成 FALSE**：`getRatingIconName()` 统计音符总数时漏了「超完美」桶 —— Turbo + 自动打谱下每个命中都判成超完美，其它桶全为 0 ⇒ 总数 0 ⇒ 直接落到 `FALSE` 兜底图。现在把超完美计入总数，并按准确率选图标。
- **图标尺寸**：评级图是 150×150，而兜底的 `false.png` 是 660×256，原来只按宽度 ×0.6 缩放（→396×154）把整张卡片压住；改为装进 240×90 的框（150×150 仍是 90×90，观感不变）。
- **统计图例不再换行、不再有黑块**：图例行原本 `fieldWidth = 155`，而 flixel 的 `fieldWidth > 0` 会打开 wordWrap，10 位数字被折成两行 —— 折出来的那一行还会在自己的文字域上画出一整块纯黑（实测：全屏唯一一块纯黑矩形正好是 155×46，就是那一行的文字域），并把尾巴压到下一行。现在 `fieldWidth = 0`（引擎自己的「永不换行」惯用法）+ 数字过长时分级收缩。
- **顺带**：结算界面原来只关了 camHUD，side HUD 与 BOTPLAY/REPLAY/ms/判定文字挂在 camOther 上，会直接画在结算面板上（20px 字 + 2px 黑描边在数字密集处连成黑块）；现在统一隐藏。

### Lua / HScript 兼容

- **`addWiggleEffect` / `removeWiggleEffect`**：按 H-Slice 的签名补上（速度 / 频率 / 振幅 / 类型），效果每帧随 `PlayState.wiggleMap` 推进。
- **`setProperty` 遇到未知字段不再打断回调**：目标为 state 自身且字段不存在时，改成保存为脚本变量并 trace（原先 hxcpp 会抛 `Invalid field:...`，整个回调直接中止，例如 Amphotercity 的 `opCombo`）。
- **`cameraFade` 补上第 5 个参数 `?fadeOut`**（1.0.4 / H-Slice 的签名）：4 参数写法行为完全不变，5 参数写法不再被静默丢掉（实测 mod 里 8 处调用只有 1 处用 5 参数）。
- **脚本错误循环保护**：只有每帧 / 每步回调计入连续错误计数，一次性回调报错只打印，不会因为别处的报错把整个脚本关掉。

### 设置

- 新增上面的谱面缓存三项（含清理按钮），简中 / 繁中 / 英文文案齐全；新增的 trace 文案同样三语。

### 已知取舍

- 缓存按「大小 + 修改时间」判断是否可用：原地编辑过谱面后，如果工具把大小与时间戳都保持原样，需要手动清一次缓存。
- 分段识别会容忍断号：断号时现有文件仍按编号顺序合并，并把缺失编号 trace 出来，不静默。
- 「第 0 段用裸名 `<song>.json`」这种布局仍不识别（它与「普通歌 + 数字难度」无法区分），请使用 `<song>.parts.json` 清单。

## English Version

0.2.2 Pre-Online.2 has just started. This slice makes the second load of a huge chart a cached step, stops song select from parsing a whole chart just to preview it, recognises a split chart whatever number its parts start at, gives Turbo / Botplay its own HUD, and fixes three display problems on the results screen (the rating icon, the hit legend and the leftover play HUD). The version is now `0.2.2preonline2`; **later commits keep appending to this announcement.**

### Chart cache: the second load no longer recomputes anything

- **On disk**: `chart_cache/` next to the executable, two files per chart (`.skel` / `.notes`). What is cached is the *output* of `generateSong`'s note loop (complete DTOs, never an index into a mutable array), so a cache hit cannot address the wrong note.
- **Validity**: every chart part's **size and modification time** plus the caller's configuration string (scroll speed, mania, fold threshold, Turbo flag, ...). Anything else is a miss, and the file is rewritten.
- **Skipped on a hit**: the skeleton scan (ChartStream), the per-section parse (ChartSectionReader / ChartPrefetch), the fold (TurboDensity) and the sort (ChartSort) -- the note list is simply replayed.
- **Size**: records are column-compressed (measured on a 12,608,616-note list: 7 of the 12 Float columns, all 5 String columns and the splash block held one value each). Constant columns are stored once, usually-zero columns cost one bit, and the rest is deflated in 1 MB blocks. The same list went from **1.78 GB to a few MB** (the option text measures 290 MB plain against 2 MB compressed); at most one 1 MB block is ever held in memory.
- **Measured output**: amphotercity (45 GB, 2,064,278,444 taps, 4,291,710 representative notes after folding) caches to `.skel` 14,215,997 B + `.notes` 12,855,326 B.
- **Options** (Performance -> Note Optimisation): `Huge Chart Cache` (on by default), `Compress the Chart Cache` (on by default, about one extra second per read and write) and a `Clear the Chart Cache` button that reports how many MB it freed. Clear it after editing a chart in place.

### Song select no longer parses a whole chart to preview it

- Freeplay's preview block ran `Song.loadFromJson()` on **every selection** under `PRELOAD_ALL`: seconds for a 2 GB single-file chart and longer for a split one. A streaming-sized chart is now recognised first and the preview parse is skipped (a preview needs the song name and `needsVoices` only), with a trace line so the skip is visible.

### Split charts: any numbering is recognised now

- The rule is now: every `<song>-<n>.json` in the directory, ascending by n, **from the lowest number to the highest**, starting wherever the author started (miragist at 0, amphotercity at 1, and 5 or 100 would work the same).
- A hole in the middle is **reported, no longer a refusal** (the missing numbers are traced) and the files that exist are still merged; fewer than two numbered files still means a single chart.
- The remaining gates: a `<song>.json` in the same directory disables detection (that is what tells a normal chart with numeric difficulties apart), a `<song>.parts.json` manifest is still the explicit override, and the player-side `Manifest/Off` plus the song-select hotkey still work.
- Regression: synthetic layouts (starting at 0 / 5 / 100, a hole 0..3 + 7..9, a stray 0..2 + 500, a single numbered file, a bare-name chart winning) and the real miragist (29 parts), amphotercity (33 parts), amphotercity `empty` and slide20: all 11 cases behave as intended, and no existing mod changes behaviour.

### Charts without an `events` field can stream too

- A single-file chart used to need synthesizable events to take the streaming reader. A byte-level test (a negative note index) now lets legacy and externally converted charts stream as well -- for example slide20 (2,105,875,665 B, 153,955,328 notes) no longer falls back to parsing the whole file into a DOM, which is exactly what used to freeze Freeplay on those charts.

### Turbo / Botplay HUD

- **Label**: Turbo shows `TURBO BOTPLAY` (plain botplay stays `BOTPLAY`, practice mode stays `Practice Mode`).
- **Score line** (botplay only; manual play's line is byte-identical):
  `Notes: <opponent hits> + <bf hits> = <total> | NPS: <opponent now>/<max> + <bf now>/<max> = <total now>/<max> | HP: <health>%`
  - Opponent hits come from the new `opCombo`, where a Turbo fold group counts its whole `noteDensity`, so it is the **original tap count**; the bf side uses the engine's own judgement counter (`totalPlayed - songMisses`).
  - NPS is a one-second sliding window (100 buckets of 10 ms) with **fast attack / slow release**: a single-frame burst of 5000 fades back to zero over about 1.47 s instead of snapping there in one frame, and the maxima still record the exact window peaks.
  - The displayed value reads a private monotone counter, so a script writing `opCombo` changes the total without faking a burst in the NPS.
  - Very long numbers are compacted (`1.03B`) to stay on one line; the exact value remains in the left stats column.

### Results screen

- **The rating icon no longer falls back to FALSE**: `getRatingIconName()` left the marvelous bucket out of its note total -- under Turbo botplay every hit is judged marvelous, so the other buckets are all zero, the total is zero, and the icon became the `FALSE` placeholder. Marvelous is counted now and the icon is picked from the accuracy again.
- **Icon size**: the rank icons are 150x150 while the `false.png` fallback is 660x256, and the old scale (width * 0.6) turned that into 396x154, covering the whole card. The icon is now fitted into a 240x90 box (150x150 stays 90x90, so the normal look is unchanged).
- **The hit legend no longer wraps and no longer paints a black box**: a legend row used `fieldWidth = 155`, and flixel turns wordWrap on as soon as `fieldWidth > 0`, so a ten-digit count wrapped onto two lines -- and the wrapped row painted its whole text field as solid black (measured: the only pure-black rectangle on screen was exactly 155x46, i.e. that row's field) while pushing its tail into the row below. It now uses `fieldWidth = 0`, the engine's own never-wrap idiom, and compacts the number when even one line cannot fit.
- **Also**: the results screen only hid camHUD, so the side HUD and the BOTPLAY/REPLAY/ms/judge labels (which live on camOther) were drawn straight over the results panels -- 20px text with a 2px black outline reads as a black block where the digits are dense. They are hidden now.

### Lua / HScript compatibility

- **`addWiggleEffect` / `removeWiggleEffect`**: added with H-Slice's signature (speed / frequency / amplitude / type), advanced every frame through `PlayState.wiggleMap`.
- **`setProperty` no longer aborts the callback on an unknown field**: when the target is the state itself and the field does not exist, the value is kept as a script variable and traced (hxcpp used to throw `Invalid field:...` and kill the whole callback, as Amphotercity's `opCombo` did).
- **`cameraFade` gained the fifth `?fadeOut` argument** (the 1.0.4 / H-Slice signature): the four-argument form is unchanged and the five-argument form is no longer silently dropped (only 1 of the 8 calls in the installed mods uses five).
- **Script error-loop protection**: only per-frame / per-step callbacks count towards the consecutive-error counter, so a one-shot callback's error is printed without disabling the script because of an unrelated failure.

### Options

- The three chart-cache entries above (including the clear button) with Simplified Chinese, Traditional Chinese and English strings; the new trace line is localised the same way.

### Known trade-offs

- Cache validity is size plus modification time: after editing a chart in place, a tool that preserves both leaves the old note list in use until the cache is cleared by hand.
- Split detection tolerates holes: with a hole the existing files are still merged in numeric order and the missing numbers are traced, never silently ignored.
- A layout whose part 0 is the bare `<song>.json` is still not recognised (it cannot be told apart from a normal chart with numeric difficulties); use a `<song>.parts.json` manifest for that.

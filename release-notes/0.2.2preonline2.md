# SeiunEngine v0.2.2 Pre-Online.2 · 更新公告 / Release Notes

## 中文版

v0.2.2 Pre-Online.2 是 Pre-Online.1 之后的第二个预发布版本。联机服务端改用 SQLite 做持久化（不再是整份覆盖写的明文 JSON），补上凭据与会话安全、结构化日志与健康检查接口，并给出可以脱离 neko 工具链的独立服务端可执行文件；客户端这边则把「在局域网里开服」做成了联机菜单里的一个按钮 —— 像 Minecraft 的开放局域网一样，游戏进程自己就是服务端，朋友把一行房间码粘进 JOIN 就能进来。

同时这一版继续收拾巨型谱面：第二次加载走缓存、选歌不再为预览解析整张谱面、分段谱面的识别放宽到任意起始编号，没有 `events` 字段的老谱面也能流式加载；Note 数据改为列式存储并换上 Int64 计数器，二十亿级的 Note 不再溢出。底层完成了 Haxe 4.3.7 工具链迁移，新增基于 hxvlc 的视频播放与基于 ffmpeg 的游戏内录制，并对图形管线做了整轮加固。结算界面、Lua / HScript 兼容、选项与本地化、离线构建等一批既有问题也一并修掉。

### 联机总览：三种开局方式

- **官方 / 公共服务器**：在服务器列表里填地址即可。会落到明文 `ws://` 的形态（裸 IP、裸主机名、`http://x`、`ws://x` 等）会自动补上默认端口 2567，且只补一次；`wss://` / `https://` 保持 443 语义，走反向代理的公网服务器不受影响。探测结果现在分 **可达 / 超时 / 协议不符** 三类，后者表示那个地址不是本引擎的服务端或版本不一致，不再笼统显示「连不上」。
- **局域网**：不知道房主的 IP 就直接搜 —— 服务器列表新增 **搜索本网络中的服务器**：监听 UDP 2569 广播 4 秒，把听到的服务器列成 **Found on This Network** 清单（不会自动加入）；勾选想要的条目再点 **Add Selected Servers** 才会写进你的服务器列表，已经在列表里的会标注出来不可勾选，**Clear These Results** 则直接丢弃本次结果。房主必须是用本版客户端的 `LAN HOST` 开服，或用本仓库 `server/` 源码构建的独立服务端 —— 两边共用同一套启动代码，都会在 UDP 2569 上广播自己；广播分别发往每块网卡的 `x.y.z.255`，装了 VPN / WSL / Hyper-V 虚拟网卡也不会走错接口。自己开服时，`LAN HOST` 面板的 **LAN Address** 行直接给出可复制的地址。Android 已放行明文 `ws://` / `http://`，否则较新的系统会直接拒绝局域网连接。Windows 上开服时会打印现成的防火墙放行命令（2567 / 2568 两个端口）与自检命令。
- **游戏内开服**：联机菜单新增 `LAN HOST`，把服务端跑在自己的游戏进程里（详见「局域网：在游戏里开服」）。

### 服务端：SQLite 持久化

- **存储层换成 SQLite**：WAL 模式、单连接 + 唯一的数据库互斥锁、按 `user_version` 版本化的只增式建表，共 13 张表（账号、会话、成绩、评论、举报、俱乐部、Mod、警告、管理日志、首页消息、每日玩家、公共状态等）。标量字段走类型化列（可索引、可排序），列表型字段（权限 / 好友 / 成员 / 下载项等）仍以 JSON 文本列保存。
- **旧数据一次性导入**：首次启动且库为空时，会自动导入旧的 accounts / leaderboard / clubs / mods / admin / public 这些 JSON，随后把原文件改名为 `*.imported-<时间戳>`（**绝不删除**），并在库里记录导入标记与计数；也可以用 `--import-legacy-json` 显式重跑。
- **凭据与会话**：token **只存 HMAC-SHA256 哈希**（外加 8 字符查找前缀），比较走常量时间，支持过期与撤销；登录时明文 token 只返回一次，从库里读出来的账号对象不再携带 token；邮件验证码同样只存哈希。
- **随机数**：优先 `/dev/urandom`；没有该设备的平台（例如 Windows）走 HMAC-SHA256 DRBG。README 与启动日志都如实写明：**这不是硬件 CSPRNG**，是自建单进程局域网服务的工程折中。
- **可观测性**：结构化 JSON Lines 日志（按天切分），新增只读 `GET /api/health`（状态 / 运行时长 / 房间数 / 版本 / 库版本 / 各表行数），新增 `--log-dir` / `--log-level` 参数。
- **独立服务端可执行文件**：可以编译出原生的 `SeiunServer.exe`（零运行时依赖）；neko 目标与既有用法完全不变。

### 服务端：HTTP + WebSocket 接口、账号与控制台

- **接口行为不变**：账号 / 排行榜 / 俱乐部 / Mod 仓库 / 管理控制台等存储换成 SQLite 实现后，对外签名、错误字符串、排序、分页与 id 格式逐字保持，HTTP 面的行为没有变化。
- **双端口**：HTTP 2567 + WebSocket 2568，握手带协议标识与版本校验。
- **管理控制台网页**现在被编译进服务端程序本身，没有 `server/web/` 目录也能打开；部署目录里存在该目录时仍以磁盘为准，所以改页面依然是刷新即生效、不用重编译。
- **配置写入修好**：公告原先按 UTF-8 **字节**截断，长中文 / emoji 会被切在字符中间，写坏 `config.toml` 并让控制台接口一直报 500。现在按 **字符** 计数（500 字符，另加 2048 字节上限），磁盘上已损坏的值在加载配置时自动修复，写入失败会返回错误而不是假的 200。
- **同一类问题在全接口做了排查**：简介、俱乐部名、network 聊天、房间聊天、`sez`、Mod 标题、搜索、封禁 / 警告理由等 12 处用户可见的字数上限现在都按字符计数；上限数值、错误文案与成功响应的结构都不变。

### 公告

- **后登录的玩家也能看到**：持久化的公告现在会随 `GET /api/front` 一并返回，不再只有那一次实时推送。
- **客户端**：联机菜单左上角以固定区域渲染公告（最多 100 字符，没有公告就不画），不再压住菜单行、居中的在线人数与底部署名；实时推送改为带标题的提示（`NOTIFICATION` + 内容），不再只有一个标题。
- **折行按字符计算**：中日韩文本不再按大约三分之一的宽度被折行，ASCII 输出保持不变。

### 游戏内联机：房间、弹窗与暂停

- **双方都有各自的评分弹窗**：联机时你和对方各有一套评分图标与连击数字，互不覆盖、互不干扰；远端弹窗锚定在**该玩家自己的角色**一侧（并夹在 5%~95% 屏宽内），找不到绑定的角色时落到对方所在的那一半屏，同侧玩家（coop / 2v2）之间会再横向拉开。本地弹窗（单机与自己的命中）的位置和单机一致。
- **连击数字仍是引擎原有口径**：连击小于 10 不显示数字，10~99 显示三位（例如 `010`）。
- **房间设置新增「暂停策略」**（房主循环切换，三档）：
  1. **仅房主可暂停**：房主一按暂停，其他玩家被强制一起暂停；客人按 ESC 只会收到本地提示。
  2. **任一玩家暂停则全体暂停**（**默认**）：谁按 ESC 都会让所有人一起停、一起恢复。
  3. **保留原有逻辑**：暂停只影响自己，暂停消息双向都不上线，与旧版本行为完全一致。
- **服务端是唯一仲裁**：暂停会回显给房间里的所有人（含发起者）并带上发起者标识 —— 收到自己的标识表示自己持有暂停，收到别人的表示自己只是被强制暂停、**无权单独恢复**；两人同一时刻按 ESC 时先到服务端的一方持有暂停，另一方从回显里得知并交出所有权。恢复只对暂停持有者生效（仅房主档里房主也可以），被拒绝的一方会收到一条提示。持有者离开 / 掉线 / 被踢、结束歌曲、新一轮重置时，服务端都会自动广播恢复，不会把其他人永久卡在暂停里；迟到进房的玩家也不会继承一个旧暂停。
- **客户端**：ESC 先按策略门控；房间级暂停由暂停菜单发出，其他人收到广播后弹出同一个暂停菜单（带「谁暂停了」的提示）；暂停归别人所有时，菜单里的继续会拒绝并提示，通过后由关闭子状态发出恢复，其他人的暂停随之一起解除。
- **开始闸门**：房主点播放（或按 ACCEPT）后全员进入谱面，屏幕正中提示 **按 ACCEPT 开始** —— 按 ACCEPT / 手柄 A / 直接点那行提示文字都算「我准备好了」，提示随即变成 **等待其他玩家...**，等房主那句 start 到达才进倒计时。安卓 / 开了触屏支持的桌面端会同时出现一个 **A** 虚拟键（右下角），房主开始后自动收起 —— 没有它的话触屏端根本没有按键能发出 ACCEPT。

### 局域网：在游戏里开服

- **`LAN HOST` 面板**：开 / 停、端口（默认 2567，被占用时向上顺延并真实显示占用情况）、最大人数（1-64）、*允许本机玩家加入*、*公开房间*（关闭时只能凭房间码进入）、实时状态行（局域网地址、房间码点击复制、当前人数）、防火墙提示、*打开本机网页控制台*。
- **真·内嵌服务端**：游戏二进制里就是同一套服务端代码。开服时在游戏进程内绑定 2567（HTTP）+ 2568（WebSocket），房主客户端自动建房并通过本机地址加入；显示的房间码带上主机的局域网 IP，朋友把这一行粘进 JOIN 即可。停止会关闭两个监听口并释放端口，同一局游戏里可以反复「开 → 停 → 开」。
- **开服期间游戏房与社交 / 网络房都走本机服务端**：只在运行期改地址，玩家保存的服务器列表与账号选择完全不受影响。
- **免账号**：客人用房间码加入即可，不需要 token；账号、分数与排行榜只写在游戏自己的存档目录里，不会上传。
- **Android** 上同样提供该面板并会尝试开服（尽力而为），无法探测到局域网地址时会给出手动填写提示。
- **面板排版**：状态 / 局域网地址 / 房间码 / 人数这四行固定说明列宽，背景框与高亮框按实测内容重算 —— 长文本不再被硬折成三行，局域网地址不再从 IP 中间断开，「点击复制」也不会掉到框外。
- **内嵌网页控制台：本机免登录、只读**。内嵌开服没有管理员账号，因此只有来自本机（`127.0.0.0/8`、`::1`、`::ffff:127.0.0.1`）的 GET 免登录，服务端返回一个合成的只读账号，页面据此跳过登录墙并显示「本机只读」横幅；写操作（POST / PUT / DELETE）与局域网里其它机器的请求仍走原来的四步校验（401），管理接口本身没有改动。独立服务端默认关闭该模式，需要时用 `--console-local-readonly` 打开。
- 内嵌开服会写自己的 `config.toml`（不带 `[smtp]` 段），邮件黑名单在内嵌模式下不生效 —— 未配置邮件时无影响。

### 谱面加载与性能

- **谱面缓存：第二次加载不再重算**。缓存落在可执行文件旁的 `chart_cache/`，每张谱面两个文件（`.skel` / `.notes`）；缓存的是 Note 循环的**输出**（完整数据对象，而不是可变数组的下标），所以命中缓存也不可能指到错的那一条 Note。失效判据是「每个分段文件的**大小 + 修改时间** + 调用方配置串（流速、mania、折叠阈值、Turbo 开关…）都不变」，任何一项变了就重写。命中时骨架扫描、逐小节解析、折叠与排序全部跳过，直接回放 Note 列表。记录按列压缩（同一张列表 **1.78 GB → 几 MB**），读写时内存里最多只持有 1 MB 块。
- **设置**（性能页 → Note 优化）：`Huge Chart Cache`（默认开）、`Compress the Chart Cache`（默认开，代价约每次读写 +1 秒）、`Clear the Chart Cache` 按钮（会报告释放了多少 MB）；原地改过谱面后建议清一次。
- **选歌不再为「预览」解析整张谱面**：流式尺寸的谱面会先被识别出来并直接跳过预览解析（预览只需要歌名与 `needsVoices`）。
- **分段谱面：识别放宽到任意起始编号**。目录里所有 `<song>-<n>.json` 按编号升序合并，起始编号任意（从 0、1、5 或 100 开始都一样）；中间缺文件只记录、不再作废（会输出缺了哪些编号），仍按现有文件合并；编号文件少于 2 个仍按单文件处理。同目录存在 `<song>.json` 时不做分段（那要留给「普通歌 + 数字难度」），`.parts.json` 清单仍是显式覆盖手段。同一首歌拆成多个文件后可以像一首完整的歌一样游玩。
- **没有 `events` 字段的谱面也能流式加载**：改用字节级特征判断后，老格式 / 外部工具转换出来的谱面不再退回整份 DOM 解析 —— 那次回退正是这类谱面在选歌界面卡死的原因。
- **Note 数据改列式存储**：每个数值字段单独成列，全谱恒定的字段直接提升为标量（不分配列），首次出现分歧才回填 —— 谱面极其重复（`stepCrochet`、命中 / miss 血量、偏移与所有字符串列通常整张谱只有一个值），提升把每条 Note 约 358 字节的占用压到几十字节；列按倍增扩容，边解析边写入，hxcpp 的块池不再被撑到整张谱的体量。
- **计数器换 Int64**：谱面与命中计数改用 Int64，超过二十亿的 Note（实测 `amphotercity` 2,064,278,444 taps）不再溢出。
- **Turbo / Botplay 的 HUD**：Turbo 下标签显示 `TURBO BOTPLAY`（普通自动打谱仍是 `BOTPLAY`，练习模式仍是 `Practice Mode`）；自动打谱时的分数行为 `Notes: <对手命中> + <自己命中> = <合计> | NPS: … | HP: <血量>%`，NPS 是 1 秒滑动窗口加**快起慢落**的弹道（一帧内的爆发会在约 1.47 秒内平滑回零，而不是一帧跳回 0），超长数字自动改用紧凑写法（如 `1.03B`）保证单行，精确值仍在左侧统计栏。
- **联机时禁用全部运行期优化**：`perfMode`、`bulkSkip`、`fastSort`、`scriptArgReuse`、`limitNotes` 上限以及强制自动打谱的 Turbo，在联机进歌时**只改本局内存值**关闭，退出歌曲按进歌快照恢复，玩家的设置文件零触碰。加载期优化（流式解析、分桶排序、巨谱缓存、分段识别）保留。
- **联机只承诺单文件谱面**：分段谱面在联机下会被**明确拒绝并提示**（本地弹窗 + 房间内状态），不再因为哈希阶段抛异常而静默卡在等待对方谱面。
- **联机谱面分析**：按每个音符自己的 mania 快照取键数，含 Change Mania 的谱面 FP 计分更准确。

### 图形与渲染

- **Haxe 4.3.7 工具链迁移**：编译器与 API 层（430）整体升级，hxcpp 使用本引擎维护的 haxe-4.3 分支，CI 与发布构建对齐新工具链；引擎代码已适配 4.3.7 的 API 变化。
- **图集重打包加固**：所有像素写入统一走带边界检查的 `blit()`（目标必须完全落在打包画布内、源必须完全落在源图内，越界即跳过并计数告警）；打包画布按请求尺寸校验（平台钳制分配时放弃重打包、保留原图）；CPU 副本已释放的源图不再参与 `copyPixels`（整体放弃重打包，绝不产出透明图集）；跨线程结果发布由主线程持有。这一轮加固关掉了「堆被写坏、几秒后在 GC 线程里崩溃」的一整类隐患。
- **异步图片加载移除**：`AsyncGfxLoader` 与「异步图片加载」设置整体删除，位图解码统一在主线程按帧小批量完成 —— GC 线程崩溃的排查最终指向跨线程发布位图的堆损坏路径，宁可放弃异步收益，也不再保留这条风险。
- **分离 update / draw 与空闲帧跳过重绘**：开启「分离更新与绘制」后，没有跑逻辑步的绘制帧会直接重新呈现已录制的绘制命令，不再整帧重建，空闲画面（例如暂停的谱面）GPU 负担明显下降；直接写 `camera.canvas.graphics` 的代码请调用 `FlxGame.invalidateDrawCache()`。
- **窗口模式统一**：新增 `backend.WindowMode`，windowed / fullscreen（真实 SDL 显示模式切换）/ borderless（去装饰 + 贴满 + 顶置）三种模式由同一条路径处理，启动流程（Main / TitleState）与设置页共用同一实现。
- **回放录制的输入检测 O(1)**：录制时改用单调事件计数器判断「有没有键变化」，不再每帧遍历全部 95 个键位探询（实测每帧 1547 ns → 0.9 ns）。

### 视频：播放与游戏内录制

- **过场视频播放**：接入 **hxvlc 2.3.1**（libVLC 3.0.23），并移除了树内的影子副本。开场 / 中途视频过场照常播放，`startVideo` 支持 1.0.4 的完整参数（`canSkip` / `forMidSong` / `shouldLoop` / `playOnLoad`）；引擎保留 hxcodec 风格的 `FlxVideo` / `FlxVideoSprite` / `VideoSprite` 包装层与视频预加载器，模组按老习惯调用即可。
- **游戏内录制（桌面端）**：歌曲中按 **F9**（或打开「开歌自动录制」）即可把游戏画面连同 Inst / Voices 混音送进 ffmpeg 管道，输出到游戏旁的 `render_video/` 目录。
  - 编码器任选：H.264（x264 / NVENC / AMF / QSV）、HEVC（x265 / NVENC）、VP9 / VP8（VP8 / VP9 输出 `.webm`，其余 `.mp4`）；码控支持 CRF/CQP（恒定质量）、VBR（目标码率）与 CBR（固定码率）。

- 房间级暂停靠消息通知，其他人会比暂停者晚**一个单程延迟**才停下，恢复时各自从自己的冻结位置继续，两边会保留这点偏移（局域网通常是个位数毫秒，与进歌时各自的音频启动偏差同一量级）。
- 游戏内录制依赖系统里可用的 **ffmpeg**（GPU 编码器还需要支持的显卡与对应编码器构建）。

## English Version

v0.2.2 Pre-Online.2 is the second pre-release following Pre-Online.1. The online server now persists to SQLite (instead of rewriting one whole plaintext JSON file), adds credential and session safety, structured logs and a health endpoint, and ships a standalone server executable that runs without the neko toolchain. On the client side, "host over LAN" is now a single button in the online menu — much like Minecraft's Open to LAN: the game process itself is the server, and friends paste one line of room code into JOIN to get in.

This version also keeps dealing with huge charts: the second load hits a cache, song select no longer parses an entire chart just to preview it, sectioned-chart detection is relaxed to accept any starting index, and old charts without an `events` field can stream as well; note data moved to a column store with Int64 counters, so two-billion-note charts no longer overflow. Under the hood the toolchain moved to Haxe 4.3.7, video playback (hxvlc) and in-game recording (ffmpeg) are in, and the graphics pipeline got a hardening pass. A batch of existing problems in the results screen, Lua / HScript compatibility, options and localization, and offline builds is fixed too.

### Online Overview: Three Ways to Start

- **Official / public servers**: fill in the address in the server list. Anything that falls back to plaintext `ws://` (bare IP, bare hostname, `http://x`, `ws://x`, etc.) gets the default port 2567 appended, exactly once; `wss://` / `https://` keep 443 semantics, so public servers behind a reverse proxy are unaffected. The reachability check now reports three outcomes — **reachable / timed out / protocol mismatch**, where the last one means that address is not this engine's server or the versions differ, instead of a blanket "cannot connect".
- **LAN**: no idea what the host's IP is? Just search — the server list gains **Search for Servers on This Network**: it listens for UDP 2569 broadcasts for 4 seconds and lists what it heard as a **Found on This Network** list (nothing is joined automatically); tick the entries you want and press **Add Selected Servers** to write them into your server list, entries already in the list are marked and cannot be ticked, and **Clear These Results** discards the batch. Hosts must be running this version's client via `LAN HOST`, or a standalone server built from this repository's `server/` sources — both share the same boot code and announce themselves on UDP 2569; the broadcast goes to `x.y.z.255` of every network interface, so VPN / WSL / Hyper-V virtual adapters never steal it. When hosting yourself, the `LAN HOST` panel's **LAN Address** row shows a copyable address. Android now allows plaintext `ws://` / `http://`, otherwise newer systems refuse LAN connections outright. On Windows, hosting prints a ready-to-use firewall allow command (ports 2567 / 2568) plus a self-check command.
- **Hosting inside the game**: the online menu gains `LAN HOST`, which runs the server inside the player's own game process (see "LAN: Hosting from Inside the Game").

### Server Side: SQLite Persistence

- **Storage switched to SQLite**: WAL mode, a single connection plus one database mutex, append-only schema versioned by `user_version`, 13 tables in total (accounts, sessions, scores, comments, reports, clubs, mods, warnings, admin log, front-page messages, daily players, public state, and more). Scalar fields use typed columns (indexable, sortable); list-shaped fields (permissions / friends / members / download entries, etc.) stay in JSON text columns.
- **One-time legacy import**: on first start with an empty database, the old accounts / leaderboard / clubs / mods / admin / public JSON files are imported automatically, then the originals are renamed to `*.imported-<timestamp>` (**never deleted**), and the import marker and counts are recorded in the database. `--import-legacy-json` re-runs it explicitly.
- **Credentials and sessions**: tokens are stored **only as HMAC-SHA256 hashes** (plus an 8-character lookup prefix), compared in constant time, with expiry and revocation supported; the plaintext token is returned once at login, and account objects read back from the database no longer carry a token. Email verification codes are hashed as well.
- **Random numbers**: `/dev/urandom` when available; platforms without that device (Windows, for example) use an HMAC-SHA256 DRBG. Both the README and the startup log state plainly: **this is not a hardware CSPRNG**, it is an engineering compromise for a self-hosted single-process LAN service.
- **Observability**: structured JSON Lines logs (rotated per day), a new read-only `GET /api/health` (status / uptime / room count / version / schema version / row count per table), and new `--log-dir` / `--log-level` flags.
- **Standalone server executable**: a native `SeiunServer.exe` can be built (zero runtime dependencies); the neko target and all existing usage are unchanged.

### Server Side: HTTP + WebSocket APIs, Accounts and Console

- **API behavior unchanged**: after accounts / leaderboard / clubs / mod repository / admin console moved to the SQLite implementation, external signatures, error strings, ordering, pagination and id formats are kept verbatim — the HTTP surface behaves exactly as before.
- **Two ports**: HTTP 2567 + WebSocket 2568, with a protocol identifier and version check in the handshake.
- **Admin console web page** is now compiled into the server program itself, so it opens even without a `server/web/` directory; when that directory exists in the deployment folder, disk still wins, so editing the pages still takes effect on refresh with no recompilation.
- **Config writing fixed**: announcements were previously truncated by UTF-8 **bytes**, so long Chinese text / emoji could be cut mid-character, corrupting `config.toml` and making console endpoints return 500 forever. Counting is now by **characters** (500 characters, plus a 2048-byte cap), already-corrupted values on disk are repaired when the config is loaded, and a failed write returns an error instead of a fake 200.
- **The same class of bug was swept across the whole API**: the 12 user-visible length limits — bio, club name, network chat, room chat, `sez`, mod titles, search, ban / warning reasons, and so on — now count characters as well; the limit values, error text and success-response shapes are unchanged.

### Announcements

- **Players who log in later see them too**: persisted announcements are now returned together with `GET /api/front`, instead of only arriving via that one live push.
- **Client side**: announcements render in a fixed area at the top-left of the online menu (up to 100 characters, nothing drawn when empty), no longer covering the menu rows, the centered online count or the footer credits; the live push became a titled notification (`NOTIFICATION` + content) instead of a bare title.
- **Wrapping counts characters**: CJK text is no longer wrapped at roughly one third of its width; ASCII output is unchanged.

### In-Game Online: Rooms, Popups and Pausing

- **Both players get their own rating popup**: online, each player has their own set of rating icons and combo numbers, with no overwriting and no interference; the remote popup is anchored to **that player's own character** side (clamped to 5%–95% of screen width), falls back to the opponent's half of the screen when no bound character is found, and same-side players (coop / 2v2) are spread further apart horizontally. The local popup (single player and the player's own hits) stays where it is in single player.
- **Combo numbers keep the engine's original rule**: no number below 10 combo, three digits from 10 to 99 (for example `010`).
- **Room settings gain a "pause policy"** (cycled by the host, three modes):
  1. **Host only**: when the host pauses, everyone else is forced to pause with them; a guest pressing ESC only gets a local hint.
  2. **Any player pauses everyone** (**default**): whoever presses ESC stops everyone and resumes everyone together.
  3. **Keep the old logic**: pausing affects only the player themselves and pause messages are not sent either way, exactly matching older versions.
- **The server is the sole arbiter**: a pause is echoed to everyone in the room (including the initiator) with the initiator's identifier — receiving your own identifier means you hold the pause, receiving someone else's means you were merely force-paused and **cannot resume on your own**; if two players press ESC at the same moment, whoever reaches the server first holds the pause and the other learns it from the echo and yields ownership. Resuming only works for the pause holder (the host may also resume in host-only mode), and a rejected player gets a hint. When the holder leaves / disconnects / is kicked, when the song ends, or when state resets for the next play, the server broadcasts a resume automatically, so nobody is stuck paused forever; players who join late do not inherit an old pause either.
- **Client side**: ESC is gated by the policy first; room-level pause is issued from the pause menu, and others open the same pause menu when the broadcast arrives (with a hint about who paused). While the pause belongs to someone else, "continue" in the menu refuses with a hint; once allowed, resume is issued by closing the substate and everyone else's pause clears with it.
- **Start gate**: when the host presses play (or ACCEPT), everyone enters the chart and sees **Press ACCEPT to start** centered on screen — ACCEPT / gamepad A / clicking the hint itself all count as "I'm ready", the hint then becomes **Waiting for other players...**, and the countdown starts only when the host's start arrives. Android / touch-enabled desktop also shows an **A** virtual button (bottom right) that retracts once the host starts — without it, touch players had no way to send ACCEPT at all.

### LAN: Hosting from Inside the Game

- **`LAN HOST` panel**: start / stop, port (2567 by default, incremented upward when taken, with the real occupancy shown), max players (1-64), *allow local player to join*, *public room* (when off, entry is by room code only), a live status row (LAN address, click-to-copy room code, current player count), firewall hints, and *open local web console*.
- **A genuinely embedded server**: the same server code lives inside the game binary. Hosting binds 2567 (HTTP) + 2568 (WebSocket) inside the game process, the host client creates a room automatically and joins through the local address; the displayed room code carries the host's LAN IP, so friends paste that one line into JOIN. Stopping closes both listeners and releases the ports, and "start → stop → start" can be repeated within the same session.
- **While hosting, both the game room and the social / network room talk to the local server**: only the address is changed at runtime, and the player's saved server list and account selection are completely untouched.
- **No account needed**: guests join with the room code, no token required; accounts, scores and leaderboards are written only to the game's own save directory and are never uploaded.
- On **Android** the panel is offered and hosting is attempted (best effort); when no LAN address can be detected, a manual-entry hint is shown.
- **Panel layout**: the four rows — status / LAN address / room code / player count — use a fixed description column width, and the backing box and highlight box are recomputed from measured content, so long text is no longer hard-wrapped into three lines, the LAN address is no longer broken in the middle of the IP, and "click to copy" no longer falls outside the box.
- **Embedded web console: local, login-free, read-only**. Embedded hosting has no admin account, so only GETs originating from this machine (`127.0.0.0/8`, `::1`, `::ffff:127.0.0.1`) skip login; the server returns a synthetic read-only account, and the page uses it to skip the login wall and show a "local read-only" banner. Writes (POST / PUT / DELETE) and requests from other machines on the LAN still go through the original four-step check (401); the admin endpoints themselves are unchanged. The standalone server disables this mode by default — enable it with `--console-local-readonly` when needed.
- Embedded hosting writes its own `config.toml` (with no `[smtp]` section), and the email blacklist does not apply in embedded mode — no impact when email is unconfigured.

### Chart Loading and Performance

- **Chart cache: the second load no longer recomputes**. The cache lives in `chart_cache/` next to the executable, two files per chart (`.skel` / `.notes`); what is cached is the **output** of the Note loop (full data objects, not indices into a mutable array), so a cache hit can never point at the wrong Note. Invalidation requires that "the **size + modification time** of every section file and the caller's configuration string (scroll speed, mania, fold threshold, Turbo switch, …) are all unchanged"; if any of them differs, it is rewritten. On a hit, skeleton scanning, per-section parsing, folding and sorting are all skipped and the Note list is replayed directly. Records are stored column-compressed (one list went from **1.78 GB to a few MB**), with at most a 1 MB chunk held in memory while reading or writing.
- **Settings** (Performance page → Note Optimization): `Huge Chart Cache` (on by default), `Compress the Chart Cache` (on by default, costs about +1 second per read/write), and a `Clear the Chart Cache` button (reports how many MB were freed). Clearing once is recommended after editing a chart in place.
- **Song select no longer parses a whole chart for the "preview"**: streamed-size charts are recognized up front and skip preview parsing (the preview only needs the song name and `needsVoices`).
- **Sectioned charts: detection relaxed to any starting index**. All `<song>-<n>.json` files in a directory are merged in ascending index order with any starting index (starting at 0, 1, 5 or 100 all work); a gap in the middle is only recorded, no longer fatal (the missing indices are reported), and the files that do exist are still merged; fewer than 2 indexed files is still treated as a single file. Sectioning is skipped when `<song>.json` exists in the same directory (that case is left for "normal song + numeric difficulty"), and a `.parts.json` manifest remains the explicit override. A song split across several files now plays as one complete song.
- **Charts without an `events` field can stream too**: after switching to byte-level feature detection, old-format charts and charts converted by external tools no longer fall back to whole-DOM parsing — that fallback was exactly why such charts froze on the song select screen.
- **Note data moved to a column store**: every numeric field gets its own column, and fields that are constant across the whole chart are hoisted to a plain scalar (no column allocated at all) until the first divergence — charts are extremely repetitive (`stepCrochet`, hit / miss health, offsets and every string column are usually one value for the whole file), so hoisting shrinks the per-note footprint from about 358 bytes to a few tens. Columns grow by doubling and can be written while parsing, so hxcpp's block pool is no longer stretched to the chart's full size.
- **Counters are Int64 now**: chart and hit counters moved to Int64, so charts beyond two billion notes (measured: `amphotercity` with 2,064,278,444 taps) no longer overflow.
- **Turbo / Botplay HUD**: under Turbo the label reads `TURBO BOTPLAY` (normal autoplay still reads `BOTPLAY`, and practice mode still reads `Practice Mode`); while autoplay the score line reads `Notes: <opponent hits> + <own hits> = <total> | NPS: … | HP: <health>%`, where NPS uses a 1-second sliding window with a **fast rise, slow fall** trajectory (a burst within one frame decays to zero over roughly 1.47 seconds instead of snapping back to 0 in a single frame), and overly long numbers switch to a compact form (such as `1.03B`) to stay on one line, with the exact value still in the left stats column.
- **All runtime optimizations disabled online**: `perfMode`, `bulkSkip`, `fastSort`, `scriptArgReuse`, the `limitNotes` cap, and Turbo's forced autoplay are turned **off in memory for the current song only** when entering a song online, and restored from the snapshot taken on entry when leaving; the player's settings file is never touched. Load-time optimizations (streaming parse, bucketed sort, huge-chart cache, section detection) remain.
- **Online guarantees single-file charts only**: sectioned charts are now **explicitly refused with a hint** online (local popup + in-room status) instead of silently hanging on "waiting for the opponent's chart" because an exception was thrown during hashing.
- **Online chart analysis**: key count is taken from each note's own mania snapshot, so FP scoring is more accurate for charts with Change Mania.

### Graphics and Rendering

- **Haxe 4.3.7 toolchain migration**: the compiler and API level (430) moved wholesale, hxcpp comes from this engine's maintained `haxe-4.3` branch, and CI / release builds are aligned to the new toolchain; the engine code has been adapted to 4.3.7's API changes.
- **Atlas repack hardening**: every pixel write goes through a bounds-checked `blit()` (the destination must fit entirely inside the packed canvas and the source entirely inside the source sheet; invalid input is skipped and counted with a warning); the packed canvas is verified against the requested size (if the platform clamped the allocation, the repack is abandoned and the original texture kept); a source whose CPU copy was released never enters `copyPixels` (the whole repack aborts — never a fully transparent atlas); cross-thread results are published by the main thread. This closes the whole class of "the heap got corrupted, and seconds later the GC thread crashed" hazards.
- **Async image loading removed**: `AsyncGfxLoader` and its "async image loading" setting are gone; bitmap decoding happens on the main thread in small per-frame batches. The GC-thread crash investigation ultimately pointed at the cross-thread bitmap publication path as a heap-corruption source — the async win is not worth that risk.
- **Separate update / draw with idle-frame draw reuse**: with "separate update and draw" enabled, a draw tick that ran no logic step re-presents the already-recorded draw commands instead of rebuilding the whole frame, which visibly cuts GPU load for idle screens (a paused chart, for example); code that writes to `camera.canvas.graphics` directly should call `FlxGame.invalidateDrawCache()`.
- **Window modes unified**: the new `backend.WindowMode` handles windowed / fullscreen (a real SDL display-mode switch) / borderless (decorations off + fill the screen + topmost) through one code path, shared by the boot flow (Main / TitleState) and the options page.
- **O(1) input detection for replay recording**: recording now watches a monotonic event counter instead of probing all 95 key bindings for "did any key change" every frame (measured 1547 ns → 0.9 ns per frame).

### Video: Playback and In-Game Recording

- **Cutscene playback**: the engine now uses **hxvlc 2.3.1** (libVLC 3.0.23), and the in-tree shadow copy is gone. Intro / mid-song video cutscenes play as before, `startVideo` accepts 1.0.4's full parameter set (`canSkip` / `forMidSong` / `shouldLoop` / `playOnLoad`); the hxcodec-style `FlxVideo` / `FlxVideoSprite` / `VideoSprite` wrapper layer and the video preloader are kept, so mods keep calling them the old way.
- **In-game recording (desktop)**: press **F9** during a song (or enable "Render on Song Start") to pipe the game frames plus the Inst / Voices mix into ffmpeg, writing to the `render_video/` folder next to the game.
  - Encoder of choice: H.264 (x264 / NVENC / AMF / QSV), HEVC (x265 / NVENC), VP9 / VP8 (VP8 / VP9 write `.webm`, the rest `.mp4`); rate control supports CRF/CQP (constant quality), VBR (target bitrate) and CBR (fixed bitrate).
  - **1 frame = 1/fps of song time**: frame numbers are derived from the Conductor clock, so pause / seek / speed changes line up automatically; while rendering the game is pinned to the configured rate with a fixed timestep, and a machine that cannot keep up does not change the video length (the ring buffer waits for the encoder instead of dropping frames).
  - **Preview render**: runs the whole pipeline (fixed timestep + per-frame capture) without writing a file, to check the timing first.
  - A **RenderIndicator** badge shows the state in the corner while rendering; every render writes a `.log` next to the output (settings, frame count, speed, and ffmpeg's own stderr).
  - A new "Render" settings page (trilingual): render on song start, preview, framerate (15-480), audio mix, codec, rate control, quality, bitrate, and buffer frames (the buffer is the memory cap).

### Note Sustain Geometry (mod skins)

- Fixed broken sustains, misaligned tail caps and "the higher the BPM the bigger the offset" for mod-provided `arrowSkin` atlases with **trimmed Sparrow frames**: sustain height normalization now uses the atlas's visible region height (a new `Note.sustainContentHeight()` unifies the four formulas behind one skin-adaptive coefficient), the falling-mode sustain anchor compensation sign is corrected, and the clip top edge uses the new `Note.contentTopInFrame()`. Default and built-in skins are bit-identical; measured on a real mod material, the sustain's near end lands at a constant offset regardless of BPM / speed, and tail caps overlap the neighbouring segments normally again.

### Results Screen

- **Rating icon no longer falls back to FALSE**: counting total notes omitted the "perfect-plus" bucket, and under Turbo + autoplay every hit was counted as perfect-plus with all other buckets at 0, giving a total of 0 and landing directly on the `FALSE` fallback graphic. Perfect-plus now counts toward the total, and the icon is chosen by accuracy.
- **Icon sizing**: rating graphics are 150×150 while the `false.png` fallback is 660×256, so scaling by width alone used to squash the whole card; everything now fits a 240×90 frame (150×150 still renders 90×90, visually unchanged).
- **Stats legend no longer wraps and no longer draws black blocks**: the legend row was given a fixed column width, and Flixel turns on automatic wrapping as soon as it receives a positive number, so long numbers were folded into two lines — and the folded line painted its own text field as one solid black block while pushing the tail onto the next line. It now uses a never-wrap form with graded shrinking when numbers get long.
- **Leftover HUD hidden together**: the results screen only turned off camHUD before, while the side HUD and the BOTPLAY / REPLAY / ms / judgement text live on another camera and were drawn straight onto the results panel (their outlines merging into black blocks where numbers are dense).

### Lua / HScript and 1.0.4 Compatibility

- **Full 1.0.4 API alignment**: all 62 signatures Psych 1.0.4 relaxed are relaxed here too (`doTween*` / `noteTween*` `ease`, `mouseClicked/Pressed/Released` `button`, `getMouseX/Y`, `makeLuaText`, `startVideo`'s four new arguments, `precacheImage` `allowGPU`, `setProperty`-family `allowInstances`, `getPropertyFromGroup` / `setPropertyFromGroup` `allowMaps`, and so on); callback arguments match (`eventEarlyTrigger` gets `(event, value1, value2, strumTime)`, `onTweenCompleted(tag, vars)`); the two missing 1.0.4 functions `getFileTranslation` / `getTranslationPhrase` are added, backed by a reader for 1.0.4's plain-text `data/<language>.lang` format (merged with the engine's JSON language tables, `{1}` / `{2}` substitution included); `Paths.getAtlas` / `Paths.getAsepriteAtlas` were ported so `'auto'` really auto-detects the atlas format; HScript gains `getModSetting` and optional-argument `keyJustPressed` / `keyPressed` / `keyReleased`. Types are widened (`addAnimation` accepts an array or the `'0,1,2'` string form, animation framerates are `Float`, `setGraphicSize` takes `Float`), `removeFromGroup` answers both dialects, and version-dependent defaults (`setHealth`, `setObjectCamera`, `loadFrames`, …) all go through `CompatEngine` — 0.6.3 / 0.7.3 modes stay byte-identical.
- **Mod JSON is parsed the way 1.0.4 parses it**: 1.0.4 reads mod data with tjson (which tolerates trailing commas and `//` / `/* */` comments); this engine used strict parsing in the same places, so a `pack.json` ending in one extra comma failed the whole mod. `pack.json`, `stages/*.json`, `data/settings.json` and `images/gfDanceTitle.json` now use a tolerant-first parser (tjson first, strict as fallback); song / character / dialogue parsing stays strict, matching 1.0.4. Measured fix: one mod was never registered as a global mod because of a trailing comma in its `pack.json`; after the fix the global mod list goes 2 → 3.
- **`close()` no longer closes the wrong script**: linc_luajit's callback table is static and shared, so the last-created instance wins and `close()` could act on a different script (the visible symptom: a mod's custom menu never appeared). The executing instance is now recorded during callback dispatch, `close()` acts on it, and the log records `CLOSE() <script>`.
- **`callMethodFromObject` no longer calls with unresolved arguments**: `instanceArg(...)` resolves modchart sprites / texts before falling back to the variables map, and an unresolved argument skips the call with a logged warning — fixing a `0xC0000005` native crash caused by a mod passing null into `mouse.overlaps`.
- **`getDataFromSave` honours its default value**: in 0.7.3 / 1.0.4 semantics an absent save field returns the caller's default (0.6.3 keeps the raw lookup) — fixing the class of "a 1.0.4 mod's options menu builds halfway and ESC stops working" reports; `logs/script_log.txt` records `[save]` diagnostics.
- **Sound and property reads completed**: `allowMaps` is honoured when reading again; tagged sounds are stored as `sound_<tag>` (so mods can read `.time` / `.length` / `.playing`); tag-less `stopSound` / `pauseSound` / `resumeSound` / `getSoundTime` / `setSoundTime` act on the current music; a failed `playSound` no longer leaves a null slot behind.
- **Scripts are less able to kill the process**: `makeLuaSprite` and friends skip safely when the tag is missing; `safeColor()` replaces the hand-rolled hex conversions (a garbage colour yields opaque white instead of a native crash; the strict validation applies in 1.0.4 mode only); the engine's software cursor is force-disabled before gameplay and restored by the pause menu on exit; the engine's extra HUD widgets (the key / KPS panel and the side stats) now hide together with `scoreTxt.visible` (the user's own hide-HUD setting and the online path are excluded).
- **1.0.4 judgement-name mapping**: a new option, "1.0.4 Judgement Names for Mods" (on by default, 1.0.4 compat mode only): scripts reading the rating name get the engine-private `marvelous` rewritten to `sick` (what the same hit would have been called in 1.0.4), so judgement-by-name mods stop mis-counting accuracy / combo; the engine's own judgement, scoring, results, online and replays keep the real rating, and scripts that want the perfect-plus tier can read `notes.members[i].ratingRaw`.
- **Script errors no longer disable the whole script**: repeated errors only trigger silencing (one summary line, then rate-limited) while the script's other callbacks keep running; an error in a one-shot callback is just printed. The old behaviour — a per-frame callback erroring 50 times closing the whole script (so even `onEndSong` never arrived) — is gone.
- **`addWiggleEffect` / `removeWiggleEffect`**: added with the H-Slice signature (speed / frequency / amplitude / type), with the effect advanced every frame.
- **`setProperty` no longer aborts the callback on unknown fields**: when the target is the state itself and the field does not exist, it is stored as a script variable and logged — previously it threw `Invalid field` and killed the whole callback.
- **`cameraFade` gains the fifth parameter `?fadeOut`** (the 1.0.4 / H-Slice signature): the four-argument form behaves exactly as before, and the five-argument form is no longer silently dropped.

### Notes / Known Limitations

- LAN hosting requires firewall allowance for **both 2567 and 2568**, and "Search for Servers on This Network" depends on UDP **2569** broadcasts — allow all three. Without it the symptom is a connection timeout or an empty search result. Only host on networks you trust — the embedded server binds all interfaces, and its REST and `/console` endpoints are visible on the LAN (the console is read-only).
- Online rooms **guarantee single-file charts only**; sectioned charts combined with the huge-chart cache are not guaranteed.
- All runtime optimizations are force-disabled online (in-memory for the current song only, restored from the snapshot taken on entry when leaving); changing these options in the online pause menu is likewise overwritten on exit.
- The server only arbitrates and relays — **there is no server-side simulation and no anti-cheat boundary**: scores are reported by the client.
- Room-level pause works by notification, so others stop **one one-way delay** later than the player who paused, and on resume each side continues from its own frozen position, preserving that offset between the two (usually single-digit milliseconds on a LAN, on the same order as the per-player audio start offset when entering a song).
- In-game recording needs an **ffmpeg** available on the system (GPU encoders additionally need a supported GPU and a matching encoder build).

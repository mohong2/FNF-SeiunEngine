## 中文版

这一版没有新玩法，主要是修复与优化：谱面打包、图片内存、打歌时的绘制开销、存档与备份、崩溃排查，以及一个可以选的 Vulkan 渲染后端。

> **这是最后一个联机预发布版本。** 之后不会再有 `Pre-Online.4`，联机相关内容改为随正式版发布。联机相关的崩溃、掉线、重连和分数复算，请在这一版反馈。

### 渲染

![OpenGL / Vulkan](https://img.shields.io/badge/OpenGL%20%2F%20Vulkan-1f6feb?style=flat-square&logo=vulkan&logoColor=white)

- **图形页新增「渲染器」一行**：可以在 OpenGL 和 Vulkan 之间切换。选择需要确认，确认后写入存档，下次启动生效。
- **启动失败会自动回退**：驱动、窗口或管线出错时，本局回到 OpenGL，存档里的选择也改回 OpenGL，并弹窗说明原因。启动阶段直接崩溃的情况会在下次启动时被识别，留在 OpenGL，不会形成崩溃循环。
- **命令行参数仍然可用**：`--vulkan` / `--no-vulkan` / `SEIUN_VULKAN` 的优先级高于存档选择；`--vulkan-stats` 打印帧时与批处理统计；`logs/renderer.txt` 记录每次启动的决定。构建时加 `-DSEIUN_NO_VULKAN` 可以不编入后端。
- **仍然是实验性功能**：菜单只在 Windows 提供。Android 编入了后端但暂不开放——模组与 OpenFL 着色器还需要在运行时从 GLSL 翻译到 SPIR-V，这条链还没做；Linux / macOS / iOS 不提供。glow、投影、位移贴图、triangle 路径和离屏渲染纹理还没有实现，用到这些效果的画面会缺东西。
- **批处理与画面**：同一批图形只在真的需要不同颜色或透明度时才逐个顶点展开；相机滤镜和舞台覆盖层都接上了；鼠标指针改用系统光标。顺带修掉竖屏设备上横屏画面被再转 90 度、非 16:9 屏幕右侧被裁的问题。

### 谱面

![.chartpack](https://img.shields.io/badge/.chartpack-1f6feb?style=flat-square)

- **新增 `.chartpack` 谱面格式**：大量重复的音符按「一条 + 重复次数」保存，不再逐条存储，打包后的体积和加载时间都明显下降。
- **打包工具带界面**：把文件、文件夹或 ZIP 拖进去就能打包，中英双语，带进度与压缩比；也有命令行版本。
- **巨型谱面加载走多线程**（Turbo 或音符数很大时启用），出错会自动退回原来的加载方式，只影响速度。
- **单个谱面文件超过 2 GB 也能正确读取**（以前会读错位置，表现为音符错乱）。
- **分数、连击等计数改为 64 位**，谱面音符再多也不会把分数变成负数；顺带修好了结算写成绩时的崩溃。
- 旧谱面、旧存档、旧回放仍然可以直接读取。

### 图片

![atlas / palette](https://img.shields.io/badge/atlas%20%2F%20palette-1f6feb?style=flat-square)

- **大图上传显卡后释放内存里的副本**，需要读像素时自动重新解码。旧的「强制回收、销毁仍在使用的图片」的做法已删除。
- **图集裁掉用不到的空白**，相同图块只留一份，再重新排紧；颜色少的图改用索引加调色板保存。
- 画面逐像素不变，代价是加载时略慢一点。
- 对模组的影响：直接从图集原图按坐标取像素的模组，拿不到被裁掉的空白区域。

### 打歌

![HUD text](https://img.shields.io/badge/HUD%20text-1f6feb?style=flat-square)

- **带描边文字的重绘路径简化**，画面不变，命中时的重绘开销明显下降。
- **只改颜色时不再重新排版**；文字没有变化时跳过重画；菜单里静态的文字合并绘制。
- HUD 文本保持原版行为：脚本在命中那一帧读到的就是新值。
- **视觉页新增两个开关**：命中毫秒读数（`showHitMs`）和左下角的歌曲 / 版本行（`showVersionText`），默认开启，也受 Hide HUD 控制。旧的 `Stock HUD Text Rewrite` 开关已删除。
- **静止箭头不再单独占一次绘制**，可以和下落音符合批。
- 高分辨率窗口与高 DPI 设备上，HUD 文字保持全分辨率。

### 存档与备份

![SEB2](https://img.shields.io/badge/SEB2-1f6feb?style=flat-square)

旧存档直接走 OpenFL 的 `SharedObject.flush()`，写入前先截断文件，中途失败就会留下坏档，下次启动静默变成空存档。这一版补上了写档这一侧的保护，并把设置里的备份 / 恢复整套重写。

- **写档前先留快照**：每次 flush 前把内容写进 `flxsave_backups/`，轮转保留若干份（份数与上限可配，可以关闭）。快照先写临时文件再改名，不会留下写了一半的版本。
- **坏档自动恢复**：`bind()` 读不出存档时，把文件另存为 `*.corrupt`，再用最新的有效快照顶上，并把 `recovered` 置 true。
- **写完回读校验**（`verifyWrites`，可以关闭）。序列化失败、空对象覆盖已有存档、超过大小上限的写入会在截断文件之前被拒绝；快照写不出来时默认也不覆盖（`abortWhenBackupFails`）。
- `MinFileSize` 现在真的传给 `flush()`，flush 失败会给出原因（`status` / `lastError`）。
- 只调 `bind()` / `flush()` 的代码不用改。

**设置里的备份 / 恢复重写：**

- **新的容器与载荷**（`BackupFormat` / `BackupData`）：`SEB2` 容器带版本与校验和，文件损坏会给出具体原因；存档字段用 `haxe.Serializer` 原样保存，Map、Int64 和模组字段不再丢失；成绩文件按字节保存，路径经过校验。
- **全有或全无**：恢复前先全部解码校验，当前数据先存一份安全备份，写入失败会回滚；恢复完成后重新加载设置、键位、成绩、成就和语言。
- **旧的 `SEB1` 备份仍可读取**，读取时升级并合并进当前存档。
- **导出改为流式写盘**，不再把整份备份在内存里复制多遍；导入按块解码，并用文件实际大小挡掉头部声明的异常长度。
- **备份界面重做**：备份 / 恢复两张卡片，支持键盘、鼠标和触屏；确认框先显示文件日期、引擎版本、字段与成绩数量；失败时说明原因。

### 崩溃排查

![crash.py](https://img.shields.io/badge/crash.py-1f6feb?style=flat-square&logo=python&logoColor=white)

- **四条崩溃路径统一成一份报告**：原生崩溃、脚本异常、底层库初始化失败、网页版。
- 报告里有系统、显卡与驱动、系统错误码、加载的模块和这次构建的身份信息。
- **每次构建自动生成符号文件**，工具能判断符号是否属于这个版本；发布包只发一个按平台分目录的符号压缩包，附 `manifest.json`。
- **九个旧工具合并成一个 `crash.py`**，中英双语，可以查看状态、解析报告、打包发给开发者。
- 报告只写事实，不再自动生成「猜测的原因」。
- **Windows / Android 构建恢复**：合并工具时删掉的两个符号脚本仍被流水线调用，导致构建失败。现在回到一次 `lime build`，符号由 postbuild 归集，发版前用 `crash.py verify-map` 校验 map 与 exe 是否对应。
- **顺带修好的流水线问题**：macOS arm64 的 runner 标签已退役；hxcpp 钉在重基前的旧分支；macOS arm64 包里混进了 x86_64 的 `lime.ndll`；iOS 因为 SDL3 的手柄震动缺 `CoreHaptics` 链接失败。现在编译前会跑 `verify-forks`，并校验 `.app` 里实际的库架构。
- **Linux / macOS 的报告也能还原函数名**：符号包里带上 ELF / Mach-O 符号表，`crash.py sym` 可以把偏移解析成函数名。代价是 macOS 发布件不再 strip。
- **构建工具链记录下来**：每次构建写入 `toolchain.json` / `toolchain.txt` / `toolchain-key.txt`，并进入 `build.json`；工具链标识参与 hxcpp 对象缓存 key。Windows 构建钉在固定镜像上，另有每周一次的 canary 检查镜像变动。
- 安卓改用 compileSdk 33 编译。
- 符号表在三条桌面流水线上都做了校验，但拿真实报告做的端到端验证目前只有 Windows 做过。

## English Version

No new gameplay this time; this release is fixes and optimisation: chart packing, image memory, the drawing cost during a song, saves and backups, crash investigation, and a Vulkan renderer you can select.

> **This is the last online pre-release.** There will be no `Pre-Online.4`; the online work ships with regular releases from here on. Crashes, disconnects, reconnects and score recomputation in online play all belong in this release.

---

### Rendering

![OpenGL / Vulkan](https://img.shields.io/badge/OpenGL%20%2F%20Vulkan-1f6feb?style=flat-square&logo=vulkan&logoColor=white)

- **A new Renderer row on the Graphics page** switches between OpenGL and Vulkan. The choice is confirmed, saved, and takes effect on the next launch.
- **A failed start falls back by itself**: if the driver, the window or a pipeline fails, the session returns to OpenGL, the saved choice is put back to OpenGL and a dialog says why. A launch that dies before it can report anything is recognised on the next boot, which stays on OpenGL - a bad driver does not become a crash loop.
- **The command line still works**: `--vulkan` / `--no-vulkan` / `SEIUN_VULKAN` outrank the saved choice; `--vulkan-stats` prints frame time and batch statistics; `logs/renderer.txt` records each launch's decision. `-DSEIUN_NO_VULKAN` leaves the backend out of a build.
- **Still experimental**: the menu offers it on Windows only. Android compiles the backend in but does not offer it yet - mods and OpenFL shaders would have to be translated from GLSL to SPIR-V at runtime, and that chain does not exist; Linux, macOS and iOS do not offer it. Glow, drop shadow, displacement maps, the triangle path and offscreen render textures are not implemented, so scenes that use them lose effects.
- **Batching and picture**: per-vertex values are only materialised when a batch really has to mix colours or alpha; camera filters and the stage overlay are wired in; the mouse uses the system cursor. Two display faults went with it: a landscape game on a portrait panel was rotated another 90 degrees, and the right edge was clipped on non-16:9 screens.

---

### Charts

![.chartpack](https://img.shields.io/badge/.chartpack-1f6feb?style=flat-square)

- **New `.chartpack` format**: repeated notes are stored as "one note plus a repeat count" instead of one entry each, so packed charts are much smaller and load much faster.
- **The packer has a window**: drag in a file, folder or ZIP; English and Chinese, with progress and ratios. A command-line version ships too.
- **Very large charts load on multiple threads** (Turbo or a very high note count) and fall back to the old loader on error - a speed loss at worst.
- **A single chart file over 2 GB reads correctly now** (it used to read from the wrong place, which showed up as scrambled notes).
- **Score and combo counters are 64-bit**, so a chart with an enormous note count no longer shows a negative score; this also fixes the crash when the score is written at the end of a song.
- Old charts, old saves and old replays still load.

---

### Images

![atlas / palette](https://img.shields.io/badge/atlas%20%2F%20palette-1f6feb?style=flat-square)

- **After a large image is uploaded to the GPU, its CPU copy is released** and re-decoded when pixels are read again. The old "force collections, destroy images in use" path is gone.
- **Atlases crop unused blank space**, identical tiles are kept once and the rest is repacked; images with few colours use an index plus a palette.
- The picture is pixel-identical; the cost is slightly slower loading.
- For mods: a mod that reads whole atlas bitmaps by coordinates loses the cropped blank areas.

---

### Gameplay

![HUD text](https://img.shields.io/badge/HUD%20text-1f6feb?style=flat-square)

- **The outlined-text redraw path is simpler**, the picture is unchanged, and redrawing on a hit costs much less.
- **A colour-only change no longer rebuilds the layout**; unchanged text skips the redraw; static menu text is drawn in one batch.
- HUD text keeps its original behaviour: a script reading it on the hit frame sees the new value.
- **Two new switches on the Visuals page**: the hit timing readout (`showHitMs`) and the bottom-left song / version line (`showVersionText`), on by default and still gated by Hide HUD. The old `Stock HUD Text Rewrite` option is gone.
- **Idle arrows no longer cost a separate draw** and batch with the falling notes.
- On high-resolution windows and high-DPI devices, HUD text stays at full resolution.

### Saves and backups

![SEB2](https://img.shields.io/badge/SEB2-1f6feb?style=flat-square)

A save used to go through OpenFL's `SharedObject.flush()`, which truncates the file before writing: a failure in the middle left a broken file, and the next launch silently came back empty. The write path has protection now, and the Backup / Restore feature was rewritten.

- **Snapshot before the risky write**: every flush first writes the payload into `flxsave_backups/`, keeping a configurable number of rotating snapshots (cap configurable, can be disabled). Snapshots go to a temporary file and are renamed, so a half-written one is never visible.
- **Damaged files come back**: when `bind()` cannot deserialize the save, it archives the file as `*.corrupt`, puts the newest valid snapshot in place and sets `recovered` to true.
- **Writes are read back** (`verifyWrites`, can be turned off). A payload that cannot be serialized, an empty object over an existing file, or a write above the size cap is refused before anything is truncated; a snapshot that cannot be created also refuses to overwrite by default (`abortWhenBackupFails`).
- `MinFileSize` is really forwarded to `flush()` now, and a failed flush reports why (`status` / `lastError`).
- Code that only calls `bind()` / `flush()` needs no changes.

**The Backup / Restore feature was rewritten:**

- **A new container and payload** (`BackupFormat` / `BackupData`): the `SEB2` container carries a version and a checksum, and a damaged file produces a specific message; save fields are stored as `haxe.Serializer` output, so Maps, Int64 values and mod-added fields are no longer dropped; score files are stored as raw bytes with validated paths.
- **All or nothing**: everything is decoded and verified before the restore starts, the current data is captured to a safety backup first, a failed write rolls back, and settings, key binds, scores, achievements and language are reloaded afterwards.
- **Old `SEB1` backups are still readable**, upgraded on read and merged into the current save.
- **The export streams to disk** instead of holding several copies of the whole backup in memory; the import decodes in chunks and rejects a header that claims more than the file can hold.
- **The backup screen was rebuilt**: two cards (Backup / Restore) with keyboard, mouse and touch support; the confirmation dialog shows the file date, engine version, field and score counts before anything happens; failures name the reason.

### Crashes

![crash.py](https://img.shields.io/badge/crash.py-1f6feb?style=flat-square&logo=python&logoColor=white)

- **Four crash paths produce one report format**: native crashes, script exceptions, low-level library init failures and the web build.
- The report carries the system, GPU and driver, the system error code, the loaded modules and the identity of the build.
- **Every build publishes symbols**, and the tool can tell whether they belong to that exact build; a release ships one symbols archive with a directory per target and a `manifest.json`.
- **Nine old tools became one `crash.py`**, English and Chinese, to check status, read a report and bundle one for the developers.
- Reports carry facts only; the auto-generated "guessed cause" paragraph is gone.
- **The Windows / Android builds work again**: collapsing the tools deleted two symbol scripts the pipeline still called, so both targets failed. A build is one `lime build` again, the postbuild hook files the symbols, and Windows proves with `crash.py verify-map` that the map matches that exact exe.
- **Pipeline faults fixed on the way**: the macOS arm64 job named a retired runner label; hxcpp was pinned to the pre-rebase branch; the macOS arm64 package carried an x86_64 `lime.ndll`; iOS failed to link because SDL3's rumble needs `CoreHaptics`. A `verify-forks` step now runs before anything compiles, and the libraries inside the `.app` are checked by architecture.
- **Linux and macOS reports resolve to function names too**: the symbol bundle carries the ELF / Mach-O symbol table, and `crash.py sym` turns an offset into a name. The price is that macOS release builds no longer strip.
- **The build toolchain is recorded**: every build writes `toolchain.json` / `toolchain.txt` / `toolchain-key.txt` and feeds `build.json`; the toolchain token takes part in the hxcpp object-cache key. Windows legs are pinned to a fixed image, with a weekly canary that notices an image move.
- Android builds with compileSdk 33.
- The symbol tables are checked on all three desktop pipelines, but end to end with a real report only Windows has been proven.

### Phones and launching

![iOS · Android](https://img.shields.io/badge/iOS%20%C2%B7%20Android-1f6feb?style=flat-square&logo=android&logoColor=white)

- **iPhone / iPad**: the picture fills the screen, fonts load properly, and video and rendering run on SDL3. This is the first playable iOS build.
- **iOS has not been verified on a device**: the fixes are only verified at the code and CI level, and the `.ipa` CI produces is ad-hoc signed with no provisioning profile, so it has to be re-signed. Treat the platform as experimental.
- **iPad / tablets**: the canvas offset comes from the real stage-unit-to-device-pixel mapping (new `backend/RenderScale.hx`) and re-lays out immediately when Retina changes.
- **Android**: crash reports list the loaded modules; the online chat box can close the keyboard; BACK while chatting no longer leaves the results screen; a text prompt with content can be cancelled with a double B.
- **Launching from a shortcut or a command line** no longer loses assets, mods and crash reports.
- **Judgement order fixed**: players with Marvelous enabled no longer get online scores weighted against the wrong tier.

![breaking changes](https://img.shields.io/badge/breaking%20changes-1f6feb?style=flat-square)

### Known issues

![known issues](https://img.shields.io/badge/known%20issues-1f6feb?style=flat-square)

- The atlas and palette differences above: reading through frames is unaffected and 1:1 is identical.
- Turbo and very large charts can lose Alt Animation on the accelerated loading path.
- tvOS only has the compile switch - no build, no verification.
- iOS is not verified on a device and the `.ipa` has to be re-signed.
- Installing under a read-only location such as `Program Files` cannot write saves or crash reports.
- Vulkan is offered on Windows only, some filters and offscreen rendering are not implemented, and it stays experimental.
- Stutter on enormous charts is expected.

### Underlying libraries

<details>
<summary>For developers and anyone debugging</summary>

- **The C++ runtime (hxcpp) moved to a new base**: the worst frame time improves noticeably. The optional crash reporter now links on every platform, the Android libc++ atomic trait no longer depends on a missing type, zlib is back on the upstream calling convention, and uncaught exceptions reach the crash reporter.
- **Script engine 1.4.0**: regex literals, object spreads, structural matching, `enum abstract`, and errors that name the script call stack and likely typos.
- **Video library**: the macOS packaging failure is fixed, real libvlc dylibs ship with the package, and setups that used to stay black can play video.
- **Lua**: a state's callback table is dropped before the state closes; reading a function out of Lua no longer changes the stack.
- **The Lua binding (linc_luajit)**: reading a function pushes a copy first, so the stack is balanced; `forget_state` also collects the leftover callback entries.
- **The Lua prebuilts**: rebuilt by CI with an architecture check.
- **Renderer backend (the lime fork)**: the Vulkan renderer is compiled into `Lime.ndll` (Windows / Linux / Android, `-Dlime-vulkan-off` leaves it out) and covers note batches, colour transforms, palette textures, camera filters, per-sprite shaders, the overlay and video frames, plus a texture memory budget, image suballocation, a pipeline cache and frame statistics. This release adds upload channels split per frame slot, pre-rotation handed to the compositor, `SUBOPTIMAL` no longer rebuilding the swapchain, and ANativeWindow takeover. Glow, drop shadow, displacement maps, the triangle path and offscreen render textures are not implemented.
- **lime build and calling-convention fixes**: Linux's `FatalReport` was missing `<stdarg.h>`; the 32-bit Android ABI gets `-march=armv7-a`; the GL object table is locked; destructors no longer free themselves; blocking calls nest; Android null-path guards; the EGL surface is destroyed before the window goes to the renderer.
- **The OpenFL fork**: the bitmap buffer keeps headroom so cairo/pixman cannot write past it; GL state is not re-sent and dynamic vertex buffers refresh in place; a `FileReference` failure no longer terminates the process; a colour-only text change no longer invalidates the layout.
- **The flixel fork**: outlined text is rasterized once; unchanged text skips the rebuild and static text batches into one page; palette hooks into the atlas and the quad batch; `FlxSave` rewritten.
- **flixel-ui**: a sort-by-ID branch that swallowed every value is fixed.
- **Toolchain**: versions are pinned and recorded for every build; Android builds with compileSdk 33.

</details>

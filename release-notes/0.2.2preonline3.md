# SeiunEngine v0.2.2 Pre-Online.3 · 更新公告 / Release Notes

## 中文版

这次没有新玩法。全部内容都是让引擎更稳、更快、更能装下夸张的谱面。

**一句话版本：**

- **巨谱装得下了**：新的谱面打包格式，几十 GB 的谱面能压到几十 KB，加载从几十秒变成几秒。
- **图片更省内存**：画面一个像素都没改，显存最多能省四分之三，启动时的图片占用少了约三分之一。
- **打歌更稳**：命中那一刻 HUD 文字的重绘开销砍掉一大半，高分辨率窗口下文字也不会变糊。
- **崩了能查**：不管哪一层崩，都会留下报告和对应的符号文件，配套工具一键解析。
- **iPhone / iPad 第一次能正常玩**：画面铺满、字体正常、视频能播。
- **界面换了个切换动画**，菜单特效移除。
- **存档更抗折腾**：写档之前先留一份轮转快照，存档文件坏了会自动从快照恢复，不会再出现「一进去发现全空了」。
- **Windows 上多了个实验性的 Vulkan 后端**：构建默认把它编进去，但画面默认还是 OpenGL，加 `--vulkan` 才真的切，切不过去自动退回。
- **编辑器换了一套控件**：面板能拖着走、双击折叠，谱面编辑器可以在「现代」和「经典（0.6.3）」两套排版之间切换。

### 谱面：更大的谱面也装得下、开得快

- **新增谱面格式 `.chartpack`**：谱面里大量重复的音符只记「一条 + 重复多少次」，不再逐条存。实测一套 71.5 GB 的谱面打包后只有 20 KB；引擎侧的 42 GB 谱面打包后 2.4 MB，第一次加载 6～8 秒，有缓存时约 4.7 秒。
- **打包工具带界面**：把文件、文件夹或 ZIP 拖进去就能打包，中英双语、带实时进度与压缩比；也有命令行版本。
- **巨型谱面加载走多线程**（只在 Turbo 或音符数超过 1200 万时启用）；万一出问题会自动退回原来的加载方式，只影响速度、不影响正确性。
- **单个谱面文件超过 2 GB 也能正确读取**（以前会读错位置，表现为音符错乱）。
- **分数、连击这些计数改成 64 位**：几十亿音符的谱面不会再把分数变成负数。顺带修好了「打完歌写成绩那一下崩溃」。
- 旧谱面、旧存档、旧回放都不用改，照常能读。

### 图片：更少内存，画面一模一样

- **大图上传显卡后，内存里的那份副本会被释放**，需要读像素时自动重新解码。以前那套「强制回收、销毁还在用的图片」的做法删掉了——那正是各种莫名崩溃的来源。
- **自动裁掉图集里用不到的空白**，完全相同的图块只留一份，再把剩下的排紧。画面逐像素不变，省下的内存和显存都是白赚的。
- **颜色少的图换成更省空间的存法**（索引 + 调色板）：一张 166 MB 的图能压到 41 MB，画面依旧逐像素一致。
- 综合结果：启动时图片占用的内存从 86 MB 降到 57 MB，显存从 85 MB 降到 56 MB。代价是加载时多花零点几秒，大图集最明显。
- 对模组的影响：如果某个模组直接从图集原图上按坐标取像素（而不是按帧取），被裁掉的空白区域就拿不到了。

### 打歌：不掉帧，文字更清楚

- **命中时的文字重绘便宜了很多**：带描边的文字以前要画 17 遍，现在画 2 遍，画面逐像素相同。重画一次分数行的耗时少了大约三成。
- **只改颜色时不再重新排版**；文字没变化时直接跳过重画；菜单里长时间不动的文字合并成一次绘制（整个菜单要画的次数少了一半）。
- HUD 文本保持原版行为：脚本在命中那一帧读到的就是新值，不会晚一帧。原来那个 `Stock HUD Text Rewrite` 开关随之删除。
- **静止的箭头不再各自多一次绘制**，可以和下落音符合批，少 7 次绘制。
- 高倍率窗口 / 高 DPI 手机上，HUD 文字保持全分辨率，不再变糊。

### 渲染：实验性 Vulkan 后端

Windows 构建现在默认把 Vulkan 后端编进去（`seiun_vulkan`），但**画面默认还是 OpenGL**：只有加 `--vulkan`（或设环境变量 `SEIUN_VULKAN=1`）才会真的切过去，驱动、窗口或 `Lime.ndll` 说不行就自动退回 OpenGL 并弹一条说明。想要纯 OpenGL 的包，构建时加 `-D SEIUN_NO_VULKAN`。

- **音符批处理走 Vulkan**：同一批图形只有在真的出现不同颜色或透明度时才逐个顶点展开，否则整批共用一个常量，省掉每帧成千上万次顶点写入。
- **相机滤镜和舞台覆盖层**也一起接上了，所以切过去不是「少画一半东西」的半成品。
- **鼠标指针改用系统光标**：flixel 的指针是舞台里的一个 Bitmap，Vulkan 这条路不画它，不换就是「游戏里没有鼠标」。
- **设置里新增「渲染器」一行**（图形页第 3 行），带 OpenGL / Vulkan 两张卡片的选择器。这一行目前只是预览，只允许选 OpenGL，点 Vulkan 会把卡片亮一下然后拒绝，提示条说明原因。
- **没编 Vulkan 的构建**带着 `--vulkan` 启动会明确弹窗说「这个构建没有 Vulkan 后端」，而不是安静地忽略。
- **排查开关**：带 `--vulkan-stats` 启动，每 60 帧打印一次平均帧时与批处理统计。
- 范围：库那边 Windows / Linux / Android 都带着后端，但**游戏目前只在 Windows 打开**（`seiun_vulkan` 仍限 windows）；macOS / iOS 没有 Vulkan 驱动。这条链路也只在这台 Windows 上端到端验证过，第一次在别人的机器上跑请当作实验性功能。

### 崩了也能查清楚

- **四条崩溃路径，一份统一格式的报告**：原生崩溃、脚本异常、底层库初始化失败、网页版，都会在游戏旁边写一份报告。
- 报告里有系统、显卡与驱动、真实的系统错误码、加载了哪些模块，以及这次构建的身份信息。
- **每次构建都会自动生成符号文件**，工具能判断「这份符号是不是这个版本」，再把地址还原成函数名。
- **九个旧工具合并成一个 `crash.py`**，带中英双语界面，可列状态、解析报告、打包发给开发者。
- 报告不再写「猜测的原因」。以前那段自动生成的「什么 / 为什么 / 怎么修」经常猜错，现在只写事实，原因在 issue 里回。
- **发布包的符号文件只剩一个压缩包**：以前每个平台各出一个 `*-symbols-<版本>.zip`，几个名字只差中间一段，正好是「拿错 map 却不自知」的温床。现在只有 `SeiunEngine-symbols-<版本>.zip`，里面一个平台一个目录，外加 `manifest.json` 说明每个目录属于哪次构建。
- **Windows / Android 的 GitHub 构建恢复**：崩溃工具合并成 `crash.py` 时删掉了两个符号脚本，流水线却还在调用它们，这两个平台因此直接构建失败。现在构建回到「一次 `lime build`」，符号由 `<postbuild>` 自动归集；Windows 发版前还会用 `crash.py verify-map` 证明那份 map 确实属于那个 exe，不是「看着像」。
- 限制：函数名的还原目前只在 Windows 上完整验证过。

### 存档：写坏了也能救回来

以前的存档走的是 OpenFL 的 `SharedObject.flush()`：先把文件截断再写。中途崩了、断电、磁盘满了、杀软占着文件，留下来的就是一个坏档 —— 下次进游戏反序列化失败，静默给你一个空存档，进度没了而且没有任何提示。这一版把这条链补上了：

- **写之前先留快照**：每次 flush 前把内容写进 `<存档目录>/flxsave_backups/`，轮转保留最近 3 份（`backupCount` 可调，上限 10，设 0 关闭）。快照先写临时文件再改名，不会留下写了一半的版本。
- **坏档自动恢复**：`bind()` 发现存档读不出来时，把它另存为 `*.corrupt`，再用最新的有效快照顶上，并把 `recovered` 置 true（想提示玩家就自己读这个字段）。
- **写完回读校验**：默认每次写完都把文件读回来比对，不一致就修（`verifyWrites`，嫌慢可以关）。
- **不该写的写入会被挡下**：序列化失败、拿空对象覆盖已有存档、超过 `maxSize` —— 这些都在截断文件**之前**拒绝，失败一次不会顺手毁掉上一份存档；快照写不出来时默认也不覆盖（`abortWhenBackupFails`）。
- `MinFileSize` 以前是被直接丢掉的，现在真的传给 `flush()`；flush 失败也会给出原因（`status` / `lastError`），不再只是一句「problem flushing」。
- 对模组和旧存档完全兼容：只调 `bind()` / `flush()` 的代码一行都不用改。

### 手机与启动

- **iPhone / iPad**：画面铺满不再偏移、字体正常（不再退回系统字体）、视频与画面后端换到更新的 SDL3、Retina 与非 Retina 之间切换立刻重排。这是引擎第一次在 iOS 上真正可用。
- **安卓**：崩溃报告能列出加载的模块；联机聊天能收起软键盘；聊天时按返回键不会顺手退出结算页；输入框里有字也能双击 B 取消。
- **从桌面快捷方式或命令行启动**也不会再找不到资源、模组和崩溃报告。
- **评级顺序修正**：开了 Marvelous 的玩家，联机复算分数不再按错档位加权。

### 编辑器

- **控件重做**：编辑器那批控件（面板盒、按钮、复选框、滑条、数字步进、单选组、输入框、标签页）统一成一套事件模型。面板盒可以**拖动**、双击标题**折叠**，切页时控件逐个淡入。顺手修掉「折叠起来的面板还在吃点击」「切页动画跑一半被销毁，留下看不见的控件」这类老毛病。
- **谱面编辑器两套排版可切换**：右上角多了个布局按钮，在「现代」（浮动的三块面板）和「经典」（和 Psych 0.6.3 一样的右侧五标签页面板）之间切换。两套排版共用同一批控件对象，所以功能一定一致，不会「切过去少东西」。
- 删除旧的下拉菜单实现（`PsychUIDropDownMenuOld`），编辑器只用新控件。

### 界面

- **切界面多了过渡动画**，三档可选：快门（默认，黑幕从上往下扫过）、淡入淡出、直接切换。旧的调用方式都还能用，模组不用改。
- **菜单特效移除**：极光、粒子、节拍脉冲、选中辉光、入场动画、选歌预览辉光整套删掉，设置里对应的开关也删了。依赖这些接口的模组脚本会失效。
- **制作人员名单**新增 GitHub 贡献者一栏（头像 + 贡献数，最多 30 人）。

### 顺带说几句底层库

- **C++ 运行时（hxcpp）换到新底座**：最卡的那一帧从 58～67 毫秒降到 35～39 毫秒，卡顿最明显的地方就在这里。
- **脚本引擎 1.4.0**：新增正则字面量、`{...obj}` 展开、结构化匹配、`enum abstract`；报错会指出脚本调用链和「你是不是拼错了」。
- **视频库**：macOS 的打包问题修好（以前检出后链接必失败）；在某些以前会黑屏的渲染环境里也能正常播视频。
- **Lua**：关闭一个 state 之前先摘掉它的回调表，脚本重载、编辑器脚本退出不再留下没人用的闭包；从 Lua 取函数也不再偷偷改栈，取值时的栈平衡统一了。
- **Lua 绑定层（linc_luajit）**：从 Lua 取值时对函数先压一份副本再取引用，栈平衡变成「进多少出多少」；`forget_state` 现在连遗留全局回调表里属于该 state 的条目一起回收。上面那条引擎侧修复就是靠这两处落地的：以前每个调用点都得自己推导「这次弹没弹栈」，推错一次就是永久的栈漂移。
- **Lua 预编译库**：15 个平台的库改为由 CI 统一重建并校验架构。
- **渲染后端（lime 分叉）**：Vulkan 渲染器整条链编进 `Lime.ndll`，Windows / Linux / Android 默认带（`-Dlime-vulkan-off` 可去掉），macOS / iOS 没有 Vulkan 驱动所以不带。已经支持音符批处理、颜色变换、调色板纹理、相机滤镜（着色器 / 模糊 / 颜色矩阵 / 卷积）、逐精灵自定义着色器、OpenFL 覆盖层，以及模组塞进精灵的视频帧；还有纹理内存的 LRU 预算、图像内存子分配与直接 BGRA 上传、管线缓存落盘、帧统计。glow / 投影 / 位移贴图、triangle 路径、离屏渲染纹理还没做。
- **lime 的两个构建级修复**：Linux 的 FatalReport 少 include `<stdarg.h>`，gcc 直接把整个 ndll 构建卡死；Android 32 位 ABI 的 clang 目标默认是 armv5te，Khronos 头直接拒绝编译（「Vulkan is not supported for the armeabi NDK ABI」），现在按 gcc 的做法传 `-march=armv7-a`。分叉的 CI 现在每次 push 都重建五个平台的 `Lime.ndll`，并校验导出表，少一个导出就让构建红掉。
- **C++ 运行时（hxcpp）的三处构建/链接修复**：崩溃上报器是「可选符号」，不提供上报器的程序也得能链接 —— MSVC x86 的 `/alternatename` 认的是修饰名（`_seiun_fatal_report`），Darwin 上 `weak_import` 也不够（Mach-O 的可执行文件不允许留未定义符号），于是 Apple 上改为在头文件里给一份弱定义、应用侧的强定义覆盖它；Android 上 `std::atomic<T>::value_type` 在 libc++（NDK）里根本不存在，换成不依赖它的 trait；zlib 不再用 `ZLIB_WINAPI`（Win32 上会变成 `_deflate` 对 `_deflate@8`，x64 完全看不出来），回到上游的 cdecl。
- **flixel-ui**：修了一个「按 ID 排序会吃掉所有值」的分支。

### 已知问题

- 图集裁边会让「直接读整张图」的模组拿不到图外像素；按帧读取的模组不受影响。
- 颜色少的图改走索引后，缩放或旋转并开抗锯齿时的过滤方式和以前略有不同（1:1 显示完全一致）。
- Turbo 或超巨谱走新的加速加载路径时，Alt Animation 会失效。
- tvOS 只加了编译开关，没有实际构建与验证。
- 游戏装进 `Program Files` 这类只读目录会写不进存档和崩溃报告。
- Vulkan：lime 里 Windows / Linux / Android 都带了后端，但游戏这边目前只在 Windows 打开（`-Dseiun_vulkan` 仍限 windows），渲染器选项里也暂时只能选 OpenGL；想试就加 `--vulkan` 启动，失败会自动退回。glow、投影、位移贴图、triangle 路径和离屏渲染纹理还没实现，画面里出现它们的地方会缺效果。
- 还是那句：大物量谱面卡顿是正常现象，这次的优化不构成「任何谱面都流畅」的承诺。

## English Version

No new gameplay this time. Everything here makes the engine steadier, faster, and able to hold absurdly large charts.

**The one-line version:**

- **Huge charts now fit**: a new chart format packs tens of gigabytes down to tens of kilobytes, and loading drops from tens of seconds to a few.
- **Images use less memory**: not a single pixel changed, but video memory can drop by up to three quarters, and image memory at startup is about a third lower.
- **Hits stay smooth**: redrawing the HUD text on a hit costs far less, and text no longer goes soft on high-resolution windows.
- **Crashes can be investigated**: whichever layer dies, there is a report and the matching symbol file, plus one tool to read them.
- **iPhone / iPad actually work now**: full screen, correct fonts, working video.
- **Screens switch with a transition**, and the menu effects are gone.
- **Saves survive a bad write**: a rotating snapshot is taken before every save, and a damaged save file is restored from it instead of silently coming back empty.
- **Windows gained an experimental Vulkan backend**: builds compile it in by default, but the game still draws through OpenGL - pass `--vulkan` to switch, and it falls back on its own when it cannot.
- **The editors moved to a new set of controls**: panels drag and collapse on a double click, and the chart editor flips between a "modern" and a "classic (0.6.3)" layout.

### Charts: bigger charts fit, and open fast

- **New chart format `.chartpack`**: notes that repeat thousands of times are stored as "one note plus how many times", instead of one entry each. In testing, a 71.5 GB chart pack came out at 20 KB; the engine's own 42 GB chart packed to 2.4 MB and loads in 6-8 seconds cold, about 4.7 seconds from cache.
- **The packer has a window**: drag in a file, a folder or a ZIP and press go — English and Chinese, with live progress and ratios. A command-line version ships too.
- **Very large charts load on multiple threads** (only under Turbo or above 12 million notes), and fall back to the old loader if anything goes wrong — a speed loss at worst, never a wrong result.
- **A single chart file over 2 GB now reads correctly** (it used to read from the wrong place, which showed up as scrambled notes).
- **Score and combo counters are 64-bit**: a chart with billions of notes no longer shows a negative score. This also fixes the crash that happened the moment a song ended and the score was written.
- Old charts, old saves and old replays need no changes.

### Images: less memory, identical picture

- **After a large image is uploaded to the GPU, the copy in RAM is released** and re-decoded automatically when something needs to read pixels. The old approach — forcing collections and destroying images that were still in use — is gone, and it was the source of the unexplained crashes.
- **Unused blank space is cropped off atlases**, identical tiles are kept only once, and the rest is packed tightly. The picture is pixel-identical; the saved memory and video memory are free.
- **Images with few colours are stored as an index plus a palette**: a 166 MB image becomes 41 MB, still pixel-identical.
- Net result at startup: image memory 86 MB down to 57 MB, video memory 85 MB down to 56 MB. The cost is a fraction of a second more loading, most visible on big atlases.
- For mods: if a mod reads pixels straight off the atlas bitmap by coordinates instead of through frames, the cropped blank areas are no longer there.

### Gameplay: no dropped frames, sharper text

- **Redrawing HUD text on a hit got much cheaper**: outlined text used to be drawn 17 times, now twice, with a pixel-identical result. One score-line redraw takes about a third less time.
- **A colour-only change no longer rebuilds the layout**; unchanged text is skipped entirely; static menu text is drawn in one batch (half as many draws for a whole menu).
- HUD text keeps its original behaviour: a script reading it on the hit frame sees the new value, not the previous one. The old `Stock HUD Text Rewrite` option is gone with it.
- **Idle arrows no longer cost a separate draw**, so they batch with the falling notes — seven fewer draws.
- On high-resolution windows and high-DPI phones, HUD text stays at full resolution instead of going soft.

### Rendering: the experimental Vulkan backend

Windows builds compile the Vulkan backend in (`seiun_vulkan`), but **the picture still comes from OpenGL by default**: only `--vulkan` (or `SEIUN_VULKAN=1`) actually switches, and if the driver, the window or `Lime.ndll` refuses, the session falls back to OpenGL and says so. Add `-D SEIUN_NO_VULKAN` for an OpenGL-only build.

- **Note quads batch through Vulkan**: per-vertex colour and alpha are only materialised when the batch really has to mix values, otherwise the batch shares one constant - that is thousands of vertex writes per frame that no longer happen.
- **Camera filters and the stage overlay** went through as well, so switching over is not half a picture.
- **The mouse uses the system cursor**: flixel's pointer is a Bitmap in the stage, drawn by OpenFL's renderer, so the Vulkan path would simply not draw it - "there is no mouse in the game".
- **New "Renderer" row in the settings** (third row of Graphics): a card picker with OpenGL and Vulkan. It is a preview and only OpenGL can be picked today; the Vulkan card lights up for a moment and is refused, with the notice line explaining why.
- **A build compiled without Vulkan** that is launched with `--vulkan` says so in a dialog instead of quietly ignoring the flag.
- **Diagnostics**: `--vulkan-stats` prints the average frame time and batch statistics every 60 frames.
- Scope: the library carries the backend on Windows, Linux and Android, but **the game only turns it on for Windows** (`seiun_vulkan` is still windows-only), and macOS / iOS have no Vulkan driver. The chain has only been verified end to end on this one Windows machine - treat it as experimental on any other machine.

### Crashes: findable again

- **Four crash paths, one report format**: native crashes, script exceptions, low-level library init failures and the web build all leave a report next to the game.
- The report carries the system, GPU and driver, the real system error code, which modules were loaded, and the identity of the build.
- **Every build publishes symbol files automatically**, and the tool can tell whether those symbols belong to that exact build before turning addresses back into function names.
- **Nine old tools became one `crash.py`**, with an English/Chinese window: check status, read a report, bundle it to send to the developers.
- Reports no longer guess. The old auto-generated "what / why / how to fix it" paragraph was often wrong; the file now carries facts, and the reason gets answered in the issue.
- **A release ships exactly one symbol archive**: it used to publish `*-symbols-<version>.zip` once per target - five names that differ only in the middle, which is precisely how the wrong map gets used without anyone noticing. It is one `SeiunEngine-symbols-<version>.zip` now, one directory per target plus a `manifest.json` naming the build each directory describes.
- **The Windows and Android GitHub builds work again**: collapsing the crash tooling into `crash.py` deleted two symbol scripts while the pipeline still called them, so both targets failed to build. A build is one `lime build` again, the `<postbuild>` hook files the symbols, and before publishing Windows proves with `crash.py verify-map` that the map belongs to that exact exe.
- Limit: function names are verified end to end on Windows only.

### Saves: a bad write no longer eats the file

A save used to go straight through OpenFL's `SharedObject.flush()`, which truncates the file before writing. A crash, a power cut, a full disk or an antivirus holding the file open in the middle of that left a broken file behind - and the next launch failed to deserialize it, quietly handed back an empty object, and the progress was gone with no message at all. That chain has a safety net now:

- **Snapshot before the risky write**: every flush first writes the payload into `<storage>/flxsave_backups/`, keeping the last 3 rotating snapshots (`backupCount`, capped at 10, 0 disables). Snapshots are written to a temporary file and renamed, so a half-written one is never visible.
- **Damaged files come back**: when `bind()` cannot deserialize the save, it archives the file as `*.corrupt`, puts the newest valid snapshot in place and sets `recovered` to true (show it to the player if you like).
- **Writes are read back**: by default every flush re-reads the file and repairs it when the contents do not match (`verifyWrites`, turn it off if you care about the extra read).
- **Destructive writes are refused**: a payload that cannot be serialized, an empty object over an existing file, a write above `maxSize` - all of it is rejected *before* anything is truncated, so one failed flush can never destroy the previous save; a snapshot that cannot be created also refuses to overwrite by default (`abortWhenBackupFails`).
- `MinFileSize` used to be dropped on the floor and is really forwarded to `flush()` now, and a failed flush reports why (`status` / `lastError`) instead of a generic 'problem flushing'.
- Fully compatible with mods and old saves: code that only calls `bind()` / `flush()` needs no changes.

### Phones and launching

- **iPhone / iPad**: the picture fills the screen instead of drifting, fonts load properly (no more falling back to a system font), video and rendering run on SDL3, and Retina / non-Retina switches re-lay out immediately. This is the first release where iOS is actually usable.
- **Android**: crash reports list the loaded modules; the online chat box can close the keyboard; BACK while chatting no longer leaves the results screen; a text prompt with content can be cancelled with a double B.
- **Launching from a desktop shortcut or a command line** no longer loses the assets, mods and crash reports.
- **Judgement order fixed**: players with Marvelous enabled no longer get online scores weighted against the wrong tier.

### Editors

- **Controls rebuilt**: the editor widgets (panel box, buttons, check boxes, sliders, numeric steppers, radio groups, input fields, tabs) share one event model now. Panels **drag** and **collapse** on a double click of their title, and switching a page fades its controls in one after another. It also fixes the old "a collapsed panel still eats clicks" and "a page destroyed mid-fade leaves an invisible control behind".
- **Two chart editor layouts**: a layout button in the top right switches between "modern" (three floating panels) and "classic" (the 0.6.3 right-hand panel with five tabs). Both layouts move the same control objects, so a feature cannot go missing in one of them.
- The old drop-down menu implementation (`PsychUIDropDownMenuOld`) is gone; the editors use the new controls only.

### Interface

- **Screens now switch with a transition**, in three styles: shutter (default, a black curtain sweeping down), fade, or instant. Existing call sites keep working, so mods need no changes.
- **Menu effects removed**: aurora, particles, beat pulses, selection glow, entry animations and the freeplay preview glow are all gone, along with the matching option. Mod scripts that relied on those calls will stop working.
- **The credits screen** now lists GitHub contributors (avatar and contribution count, up to 30).

### A few words about the underlying libraries

- **The C++ runtime (hxcpp) moved to a new base**: the worst frame time drops from 58-67 ms to 35-39 ms — that is where the hitching lived.
- **Script engine 1.4.0**: regex literals, `{...obj}` spreads, structural matching, `enum abstract`, and errors that name the script call stack and point out likely typos.
- **Video library**: the macOS packaging failure is fixed (every checkout used to fail to link), and video plays in rendering setups that used to stay black.
- **Lua**: a state's callback table is dropped before the state is closed, so reloading a script or leaving an editor no longer leaves closures behind; reading a function out of Lua no longer pops the stack behind your back either.
- **The Lua binding (linc_luajit)**: reading a function out of Lua pushes a copy before taking the reference, so `fromLua` is stack-neutral - in and out are the same size again - and `forget_state` now also takes back the legacy global callback entries that belong to the closing state. That is what the engine-side fix above needed: every call site used to re-derive whether the read had popped, and one wrong guess became permanent stack drift.
- **The Lua prebuilts**: the binaries for all 15 platforms are rebuilt by CI with an architecture check.
- **Renderer backend (the lime fork)**: the whole Vulkan renderer is compiled into `Lime.ndll` - built by default on Windows / Linux / Android (`-Dlime-vulkan-off` leaves it out), absent on macOS / iOS, which have no Vulkan driver. It already covers note quad batches, colour transforms, palette textures, camera filters (shader, blur, colour matrix, convolution), custom per-sprite shaders, the OpenFL overlay and video frames a mod feeds into a sprite, plus an LRU budget on texture memory, image memory suballocation with direct BGRA upload, a persisted pipeline cache and frame statistics. Glow, drop shadow and displacement-map filters, the triangle path and offscreen render textures are not implemented yet.
- **Two build-level lime fixes**: Linux's `FatalReport` was missing `<stdarg.h>`, which stopped gcc on the whole ndll; and clang's 32-bit Android target defaults to armv5te, where the Khronos headers refuse to compile at all ("Vulkan is not supported for the armeabi NDK ABI"), so the ABI that ships as `armeabi-v7a` now gets `-march=armv7-a` the way the gcc toolchain always did. The fork's CI rebuilds `Lime.ndll` for all five platforms on every push and checks the export table, so a missing export fails the build instead of the game.
- **Three build/link fixes in the C++ runtime (hxcpp)**: the crash reporter is an optional symbol, so a host that provides no reporter must still link - on MSVC x86 `/alternatename` needs the decorated `_seiun_fatal_report`, and on Darwin `weak_import` is not enough either (a Mach-O executable may not leave the symbol undefined at all), so Apple now gets a weak *definition* in the header that an application's strong definition coalesces over. On Android `std::atomic<T>::value_type` does not exist in libc++ (the NDK's), which broke that build until the trait stopped using it. And zlib is no longer built with `ZLIB_WINAPI` (`_deflate` versus `_deflate@8` on Win32 - x64 hides it completely), which also restores the upstream cdecl convention.
- **flixel-ui**: a sort-by-ID branch that swallowed every value is fixed.

### Known issues

- Atlas cropping means a mod that reads whole atlas bitmaps by coordinates loses the cropped blank areas; mods that read through frames are unaffected.
- Images stored as an index use a slightly different filtering mode when scaled or rotated with smoothing on (identical at 1:1).
- Turbo and very large charts can lose Alt Animation on the new accelerated loading path.
- tvOS only has the compile switch — no build, no verification.
- Installing under a read-only location such as `Program Files` cannot write saves or crash reports.
- Vulkan: lime carries the backend on Windows, Linux and Android, but the game only turns it on for Windows (`-Dseiun_vulkan` is still windows-only) and the renderer row still only accepts OpenGL; pass `--vulkan` to try it, and it falls back on its own. Glow, drop shadow, displacement maps, the triangle path and offscreen render textures are not implemented, so whatever uses them loses its effect.
- And once more: stutter on enormous charts is expected, and none of this promises that every chart will run smoothly.

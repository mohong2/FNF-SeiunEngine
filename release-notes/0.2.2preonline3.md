# SeiunEngine v0.2.2 Pre-Online.3 · 更新公告 / Release Notes

## 中文版

这次没有新玩法。全部内容都是让引擎更稳、更快、更能装下夸张的谱面。

**一句话版本：**

- **巨谱装得下了**：新的谱面打包格式，几十 GB 的谱面能压到几十 KB，加载从几十秒变成几秒。
- **图片更省内存**：画面一个像素都没改，显存最多能省四分之三，启动时的图片占用少了约三分之一。
- **打歌更稳**：命中那一刻 HUD 文字的重绘开销砍掉一大半，高分辨率窗口下文字也不会变糊。
- **崩了能查**：不管哪一层崩，都会留下报告和对应的符号文件，配套工具一键解析。
- **iPhone / iPad 第一次能正常玩**：画面铺满、字体正常、视频能播。
- **界面换了个切换动画**，菜单特效移除。

### 谱面：更大的谱面也装得下、开得快

- **新增谱面格式 `.chartpack`**：谱面里大量重复的音符只记「一条 + 重复多少次」，不再逐条存。实测一套 71.5 GB 的谱面打包后只有 20 KB；引擎侧的 42 GB 谱面打包后 2.4 MB，第一次加载 6～8 秒，有缓存时约 4.7 秒。
- **打包工具带界面**：把文件、文件夹或 ZIP 拖进去就能打包，中英双语、带实时进度与压缩比；也有命令行版本。
- **巨型谱面加载走多线程**（只在 Turbo 或音符数超过 1200 万时启用）；万一出问题会自动退回原来的加载方式，只影响速度、不影响正确性。
- **单个谱面文件超过 2 GB 也能正确读取**（以前会读错位置，表现为音符错乱）。
- **分数、连击这些计数改成 64 位**：几十亿音符的谱面不会再把分数变成负数。顺带修好了「打完歌写成绩那一下崩溃」。
- 旧谱面、旧存档、旧回放都不用改，照常能读。

### 图片：更少内存，画面一模一样

- **大图上传显卡后，内存里的那份副本会被释放**，需要读像素时自动重新解码。以前那套「强制回收、销毁还在用的图片」的做法删掉了——那正是各种莫名崩溃的来源。
- **自动裁掉图集里用不到的空白**，完全相同的图块只留一份，再把剩下的排紧。画面逐像素不变，省下的内存和显存都是白赚的。
- **颜色少的图换成更省空间的存法**（索引 + 调色板）：一张 166 MB 的图能压到 41 MB，画面依旧逐像素一致。
- 综合结果：启动时图片占用的内存从 86 MB 降到 57 MB，显存从 85 MB 降到 56 MB。代价是加载时多花零点几秒，大图集最明显。
- 对模组的影响：如果某个模组直接从图集原图上按坐标取像素（而不是按帧取），被裁掉的空白区域就拿不到了。

### 打歌：不掉帧，文字更清楚

- **命中时的文字重绘便宜了很多**：带描边的文字以前要画 17 遍，现在画 2 遍，画面逐像素相同。重画一次分数行的耗时少了大约三成。
- **只改颜色时不再重新排版**；文字没变化时直接跳过重画；菜单里长时间不动的文字合并成一次绘制（整个菜单要画的次数少了一半）。
- HUD 文本保持原版行为：脚本在命中那一帧读到的就是新值，不会晚一帧。原来那个 `Stock HUD Text Rewrite` 开关随之删除。
- **静止的箭头不再各自多一次绘制**，可以和下落音符合批，少 7 次绘制。
- 高倍率窗口 / 高 DPI 手机上，HUD 文字保持全分辨率，不再变糊。

### 崩了也能查清楚

- **四条崩溃路径，一份统一格式的报告**：原生崩溃、脚本异常、底层库初始化失败、网页版，都会在游戏旁边写一份报告。
- 报告里有系统、显卡与驱动、真实的系统错误码、加载了哪些模块，以及这次构建的身份信息。
- **每次构建都会自动生成符号文件**，工具能判断「这份符号是不是这个版本」，再把地址还原成函数名。
- **九个旧工具合并成一个 `crash.py`**，带中英双语界面，可列状态、解析报告、打包发给开发者。
- 报告不再写「猜测的原因」。以前那段自动生成的「什么 / 为什么 / 怎么修」经常猜错，现在只写事实，原因在 issue 里回。
- 限制：函数名的还原目前只在 Windows 上完整验证过。

### 手机与启动

- **iPhone / iPad**：画面铺满不再偏移、字体正常（不再退回系统字体）、视频与画面后端换到更新的 SDL3、Retina 与非 Retina 之间切换立刻重排。这是引擎第一次在 iOS 上真正可用。
- **安卓**：崩溃报告能列出加载的模块；联机聊天能收起软键盘；聊天时按返回键不会顺手退出结算页；输入框里有字也能双击 B 取消。
- **从桌面快捷方式或命令行启动**也不会再找不到资源、模组和崩溃报告。
- **评级顺序修正**：开了 Marvelous 的玩家，联机复算分数不再按错档位加权。

### 界面

- **切界面多了过渡动画**，三档可选：快门（默认，黑幕从上往下扫过）、淡入淡出、直接切换。旧的调用方式都还能用，模组不用改。
- **菜单特效移除**：极光、粒子、节拍脉冲、选中辉光、入场动画、选歌预览辉光整套删掉，设置里对应的开关也删了。依赖这些接口的模组脚本会失效。
- **制作人员名单**新增 GitHub 贡献者一栏（头像 + 贡献数，最多 30 人）。

### 顺带说几句底层库

- **C++ 运行时（hxcpp）换到新底座**：最卡的那一帧从 58～67 毫秒降到 35～39 毫秒，卡顿最明显的地方就在这里。
- **脚本引擎 1.4.0**：新增正则字面量、`{...obj}` 展开、结构化匹配、`enum abstract`；报错会指出脚本调用链和「你是不是拼错了」。
- **视频库**：macOS 的打包问题修好（以前检出后链接必失败）；在某些以前会黑屏的渲染环境里也能正常播视频。
- **Lua 库**：15 个平台的预编译库改为由 CI 统一重建并校验架构。
- **flixel-ui**：修了一个「按 ID 排序会吃掉所有值」的分支。

### 已知问题

- 图集裁边会让「直接读整张图」的模组拿不到图外像素；按帧读取的模组不受影响。
- 颜色少的图改走索引后，缩放或旋转并开抗锯齿时的过滤方式和以前略有不同（1:1 显示完全一致）。
- Turbo 或超巨谱走新的加速加载路径时，Alt Animation 会失效。
- tvOS 只加了编译开关，没有实际构建与验证。
- 游戏装进 `Program Files` 这类只读目录会写不进存档和崩溃报告。
- 还是那句：大物量谱面卡顿是正常现象，这次的优化不构成「任何谱面都流畅」的承诺。

## English Version

No new gameplay this time. Everything here makes the engine steadier, faster, and able to hold absurdly large charts.

**The one-line version:**

- **Huge charts now fit**: a new chart format packs tens of gigabytes down to tens of kilobytes, and loading drops from tens of seconds to a few.
- **Images use less memory**: not a single pixel changed, but video memory can drop by up to three quarters, and image memory at startup is about a third lower.
- **Hits stay smooth**: redrawing the HUD text on a hit costs far less, and text no longer goes soft on high-resolution windows.
- **Crashes can be investigated**: whichever layer dies, there is a report and the matching symbol file, plus one tool to read them.
- **iPhone / iPad actually work now**: full screen, correct fonts, working video.
- **Screens switch with a transition**, and the menu effects are gone.

### Charts: bigger charts fit, and open fast

- **New chart format `.chartpack`**: notes that repeat thousands of times are stored as "one note plus how many times", instead of one entry each. In testing, a 71.5 GB chart pack came out at 20 KB; the engine's own 42 GB chart packed to 2.4 MB and loads in 6-8 seconds cold, about 4.7 seconds from cache.
- **The packer has a window**: drag in a file, a folder or a ZIP and press go — English and Chinese, with live progress and ratios. A command-line version ships too.
- **Very large charts load on multiple threads** (only under Turbo or above 12 million notes), and fall back to the old loader if anything goes wrong — a speed loss at worst, never a wrong result.
- **A single chart file over 2 GB now reads correctly** (it used to read from the wrong place, which showed up as scrambled notes).
- **Score and combo counters are 64-bit**: a chart with billions of notes no longer shows a negative score. This also fixes the crash that happened the moment a song ended and the score was written.
- Old charts, old saves and old replays need no changes.

### Images: less memory, identical picture

- **After a large image is uploaded to the GPU, the copy in RAM is released** and re-decoded automatically when something needs to read pixels. The old approach — forcing collections and destroying images that were still in use — is gone, and it was the source of the unexplained crashes.
- **Unused blank space is cropped off atlases**, identical tiles are kept only once, and the rest is packed tightly. The picture is pixel-identical; the saved memory and video memory are free.
- **Images with few colours are stored as an index plus a palette**: a 166 MB image becomes 41 MB, still pixel-identical.
- Net result at startup: image memory 86 MB down to 57 MB, video memory 85 MB down to 56 MB. The cost is a fraction of a second more loading, most visible on big atlases.
- For mods: if a mod reads pixels straight off the atlas bitmap by coordinates instead of through frames, the cropped blank areas are no longer there.

### Gameplay: no dropped frames, sharper text

- **Redrawing HUD text on a hit got much cheaper**: outlined text used to be drawn 17 times, now twice, with a pixel-identical result. One score-line redraw takes about a third less time.
- **A colour-only change no longer rebuilds the layout**; unchanged text is skipped entirely; static menu text is drawn in one batch (half as many draws for a whole menu).
- HUD text keeps its original behaviour: a script reading it on the hit frame sees the new value, not the previous one. The old `Stock HUD Text Rewrite` option is gone with it.
- **Idle arrows no longer cost a separate draw**, so they batch with the falling notes — seven fewer draws.
- On high-resolution windows and high-DPI phones, HUD text stays at full resolution instead of going soft.

### Crashes: findable again

- **Four crash paths, one report format**: native crashes, script exceptions, low-level library init failures and the web build all leave a report next to the game.
- The report carries the system, GPU and driver, the real system error code, which modules were loaded, and the identity of the build.
- **Every build publishes symbol files automatically**, and the tool can tell whether those symbols belong to that exact build before turning addresses back into function names.
- **Nine old tools became one `crash.py`**, with an English/Chinese window: check status, read a report, bundle it to send to the developers.
- Reports no longer guess. The old auto-generated "what / why / how to fix it" paragraph was often wrong; the file now carries facts, and the reason gets answered in the issue.
- Limit: function names are verified end to end on Windows only.

### Phones and launching

- **iPhone / iPad**: the picture fills the screen instead of drifting, fonts load properly (no more falling back to a system font), video and rendering run on SDL3, and Retina / non-Retina switches re-lay out immediately. This is the first release where iOS is actually usable.
- **Android**: crash reports list the loaded modules; the online chat box can close the keyboard; BACK while chatting no longer leaves the results screen; a text prompt with content can be cancelled with a double B.
- **Launching from a desktop shortcut or a command line** no longer loses the assets, mods and crash reports.
- **Judgement order fixed**: players with Marvelous enabled no longer get online scores weighted against the wrong tier.

### Interface

- **Screens now switch with a transition**, in three styles: shutter (default, a black curtain sweeping down), fade, or instant. Existing call sites keep working, so mods need no changes.
- **Menu effects removed**: aurora, particles, beat pulses, selection glow, entry animations and the freeplay preview glow are all gone, along with the matching option. Mod scripts that relied on those calls will stop working.
- **The credits screen** now lists GitHub contributors (avatar and contribution count, up to 30).

### A few words about the underlying libraries

- **The C++ runtime (hxcpp) moved to a new base**: the worst frame time drops from 58-67 ms to 35-39 ms — that is where the hitching lived.
- **Script engine 1.4.0**: regex literals, `{...obj}` spreads, structural matching, `enum abstract`, and errors that name the script call stack and point out likely typos.
- **Video library**: the macOS packaging failure is fixed (every checkout used to fail to link), and video plays in rendering setups that used to stay black.
- **Lua library**: the prebuilt binaries for all 15 platforms are rebuilt by CI with an architecture check.
- **flixel-ui**: a sort-by-ID branch that swallowed every value is fixed.

### Known issues

- Atlas cropping means a mod that reads whole atlas bitmaps by coordinates loses the cropped blank areas; mods that read through frames are unaffected.
- Images stored as an index use a slightly different filtering mode when scaled or rotated with smoothing on (identical at 1:1).
- Turbo and very large charts can lose Alt Animation on the new accelerated loading path.
- tvOS only has the compile switch — no build, no verification.
- Installing under a read-only location such as `Program Files` cannot write saves or crash reports.
- And once more: stutter on enormous charts is expected, and none of this promises that every chart will run smoothly.
